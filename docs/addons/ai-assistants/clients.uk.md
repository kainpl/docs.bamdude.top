## Codex

ZIP містить локальний каталог, а не публічний marketplace. Розпакуйте його до постійної теки, наприклад `C:\BamDude-AI`, і зберігайте її для оновлень. Нижче її шлях позначено як `<розпакована-тека>`.

1. Завантажте переносний ZIP плагіна й розпакуйте його, потім виконайте команди зі своїм шляхом. Вони встановлюють skill, але не налаштовують ключ чи сервер:

    ```powershell
    codex plugin marketplace add "<розпакована-тека>"
    codex plugin add bamdude-ai@bamdude-ai-local
    ```
2. У **Ручному підключенні** BamDude скопіюйте команду PowerShell для збереженої адреси. Вона містить назву змінної середовища, не ваш ключ.
3. Передайте `BAMDUDE_MCP_KEY` процесу Codex через звичне приватне налаштування середовища. Не вводьте його в чат і не комітьте у проєкт. Це секрет середовища, а не обіцянка зберігання у сховищі ОС.
4. Або додайте конфігурацію зі своєю адресою:

    ```toml
    [mcp_servers.bamdude]
    url = "https://farm.example/mcp"
    bearer_token_env_var = "BAMDUDE_MCP_KEY"
    ```

5. Перезапустіть MCP-підключення/клієнт і попросіть capabilities та інструкцію. Не запускайте OAuth-вхід для цього сервера лише з ключем. Для самопідписаного сертифіката задайте явну довіру у відповідному конекторі чи керованих сертифікатах; не вимикайте перевірку.

Локальні MCP-налаштування Codex у ChatGPT Desktop — інший маршрут, ніж ChatGPT у браузері/хмарі. Наявність одного не доводить доступність іншого. Див. [офіційне налаштування MCP](https://learn.chatgpt.com/docs/extend/mcp).

## Claude Code

1. Розпакуйте ZIP плагіна Claude до постійної теки, зареєструйте вкладений локальний каталог і встановіть плагін:

    ```powershell
    claude plugin marketplace add "<розпакована-тека>"
    claude plugin install bamdude-ai@bamdude-ai-local
    ```

    Для тимчасової перевірки `claude --plugin-dir <розпакована-тека>` підключає його лише до цієї сесії.
2. У налаштуваннях користувача плагіна введіть **BamDude MCP address**, **BamDude MCP key** і за потреби **Trusted CA file**. Поле ключа позначене як sensitive; зберіганням керує клієнт.
3. Плагін використовує локальний Node-конектор. На цьому комп’ютері має бути Node 22.19+.
4. Запустіть нове підключення й попросіть capabilities та інструкцію. Канонічний skill уже в плагіні.

Пакет не має публічного marketplace; не використовуйте вигадану команду встановлення з GitHub. Локальний каталог уже вкладено в ZIP. Див. [довідник плагінів Claude](https://code.claude.com/docs/en/plugins-reference).

HTTP-приклад у **Ручному підключенні** майстра з’єднується напряму, оминаючи локальний конектор: його CA-файл, захисти від перенаправлень та OAuth і ліміти конектора тут не діють; для самопідписаного сервера налаштуйте довіру в самому Claude Code й ніколи не вимикайте перевірку TLS.

## Claude Desktop

1. Завантажте `.mcpb` з панелі підключення.
2. У локальному встановленні **Extensions** Desktop виберіть пакет і перегляньте запит дозволів конектора.
3. Введіть адресу ферми та ключ у конфігурації розширення. Для самопідписаного сертифіката виберіть файл CA. Власний Node хоста має відповідати мінімуму з пакета; приймання Desktop ще потрібне.
4. Окремо завантажте **ZIP skill** і встановіть його через Skills клієнта. Саме встановлення MCPB не встановлює skill.
5. Перезапустіть підключення, попросіть capabilities та інструкцію. Перевірте MCP-позначку обраного ключа в BamDude.

Хмарний **remote connector** Desktop — інший маршрут: запити можуть надходити з інфраструктури провайдера, не з вашого комп’ютера. Див. [локальні MCP-сервери Desktop](https://support.claude.com/en/articles/10949351-getting-started-with-local-mcp-servers-on-claude-desktop).

## ChatGPT у браузері й публічні тунелі

У матриці v1 немає перевіреного шляху встановлення для ChatGPT у хмарі. Не відкривайте всю ферму, щоб позеленіла перевірка. Якщо майбутньому підтримуваному налаштуванню потрібен публічний proxy/тунель, він має відкривати **лише `/mcp`**; `/api/v1` та вебінтерфейс повинні лишатися недоступними через нього. Додайте до MCP лише точний зовнішній хост і врахуйте, що обраний провайдер отримує дозволені дані. Інфраструктура OAuth/relay не входить у v1.
