# Окремий сервер Obico ML

Для [AI-виявлення збоїв друку](../features/obico.md) BamDude потрібен лише контейнер Obico **`ml_api`**. Ця інструкція встановлює його в окремому Docker Compose-проєкті. Вебзастосунок Obico, фонові workers, Redis, база даних і хмарний обліковий запис не потрібні.

Скрипт збирає ML-образ з офіційної [гілки `release` сервера Obico](https://github.com/TheSpaghettiDetective/obico-server/tree/release/ml_api). Його можна запустити на хості BamDude або на окремій машині у вашій довіреній локальній мережі.

## Що потрібно

- Linux із Bash і локальним Docker Engine. Інструкція розрахована на звичайний CPU-образ; спеціальні збірки для GPU й ARM тут не розглядаються.
- [Docker Engine із плагіном Compose](https://docs.docker.com/engine/install/), який підтримує `docker compose up --wait`. Ваш користувач має успішно виконувати `docker info`.
- Git, curl, OpenSSL, `flock` (зазвичай пакет `util-linux`) і `realpath` (зазвичай `coreutils`). Для Debian/Ubuntu після встановлення Docker:

    ```bash
    sudo apt-get update
    sudo apt-get install -y git curl openssl util-linux coreutils
    ```

- Інтернет для GitHub, реєстру контейнерів і завантаження моделей. Залиште кілька ГБ диска для джерел, образів і кешу збірки; сама модель займає сотні МБ. Потреба в пам'яті й CPU залежить від моделі та частоти перевірок.
- Мережевий доступ **в обидва боки**: BamDude → ML API та ML-контейнер → зовнішня адреса BamDude для отримання кадрів камери.

## Завантажте скрипт

[Завантажити obico-ml.sh](../assets/downloads/obico-ml.sh){ .md-button download="obico-ml.sh" }

Або завантажте його на Linux-хості командою:

```bash
curl -fL --proto '=https' --tlsv1.2 \
  https://docs.bamdude.top/assets/downloads/obico-ml.sh -o obico-ml.sh
less obico-ml.sh
bash obico-ml.sh --help
```

Завантажте й перегляньте файл перед запуском. Скрипт не встановлює Docker і не змінює firewall хоста. Він створює нову теку, окремий Compose-проєкт і випадковий API-токен. Адрес і секретів сервера розробників BamDude в ньому немає.

## Встановлення

Оберіть нову теку й вільний порт хоста. Замість **`10.0.0.20`** вкажіть LAN IPv4-адресу, яка належить **хосту ML**:

```bash
bash obico-ml.sh install "$HOME/obico-ml" 10.0.0.20 3333
```

Якщо BamDude працює безпосередньо на тому самому хості, можна залишити типові значення:

```bash
bash obico-ml.sh install
```

Типові значення: адреса `127.0.0.1`, порт `3333`, тека `$HOME/obico-ml`. Loopback **недоступний з окремого контейнера BamDude**; для такого розміщення також використовуйте LAN-адресу хоста. Наступні команди запускайте від того самого користувача й передавайте ту саму теку, якщо обрали інше місце.

Перша збірка завантажує базовий образ, залежності й ваги моделі, тому може тривати кілька хвилин. Після успіху скрипт покаже URL ML і ревізію джерел. Сервіс автоматично запускається разом із Docker.

!!! warning "Лише довірена локальна мережа"
    Залишайте порт у довіреній мережі; не відкривайте його в Інтернет через маршрутизатор. API працює через HTTP, тому bearer-токен передається без шифрування. Прив'язка до LAN-адреси не замінює firewall. Опубліковані порти Docker можуть обходити звичайні правила UFW; для обмеження доступу використовуйте [правила firewall з урахуванням Docker](https://docs.docker.com/engine/network/packet-filtering-firewalls/).

У теці встановлення будуть:

| Файл | Призначення |
|---|---|
| `obico-ml.sh` | Локальна копія скрипта встановлення й оновлення |
| `compose.yaml` | Один сервіс: `ml_api` |
| `.env` | Адреса, порт, назва проєкту й секретний токен; типово читати може лише користувач, який виконав встановлення |
| `source/` | Копія офіційних джерел Obico |

Не використовуйте теку повного Obico. Скрипт не переносить і не зупиняє наявний стек; для одночасної роботи оберіть іншу теку й порт. Він не виконує `down`, не видаляє volumes і не очищує ресурси Docker.

## Підключення до BamDude

1. Покажіть згенерований токен локально:

    ```bash
    bash "$HOME/obico-ml/obico-ml.sh" token
    ```

2. У BamDude відкрийте **Налаштування → AI-виявлення збоїв друку**. У полі **URL Obico ML API** вкажіть `http://10.0.0.20:3333`, а в **Токен ML API** вставте токен. Потрібен базовий URL, без `/p/`, `/hc/` чи `/api/v1/octo/`.
3. У **Налаштування → Мережа → Зовнішній URL** вкажіть адресу **BamDude**, доступну з ML-контейнера. Наприклад, `http://10.0.0.10:8000`, якщо BamDude обслуговується за цією адресою й портом. `localhost` усередині ML-контейнера означає сам контейнер.
4. Увімкніть детекцію, виберіть принтери й натисніть **Перевірити**. Почніть із дії **Лише сповіщення**, доки оцінюєте ракурс камери й чутливість.
5. Під час активного друку переконайтеся, що лічильник проаналізованих кадрів зростає. Це перевіряє весь шлях камера → BamDude → ML, а не лише стан сервісу.

Не поширюйте `.env` або вивід команди `token`. `/hc/` відкритий навіть тоді, коли розпізнавання захищене токеном, тому успішна перевірка здоров'я сама по собі не доводить правильність токена. Скрипт перевіряє готовність, відмову без токена й прийняття налаштованого токена; справжній кадр камери він не надсилає.

## Оновлення лише ML

```bash
bash "$HOME/obico-ml/obico-ml.sh" check
bash "$HOME/obico-ml/obico-ml.sh" update
```

`check` перевіряє локальну конфігурацію й стан джерел; нічого не завантажує, не збирає, не перезапускає й не перевіряє живе розпізнавання.

`update` отримує офіційну гілку `release`, пересуває чистий checkout лише через fast-forward, збирає **тільки `ml_api`**, поки старий контейнер працює, а потім замінює цей контейнер і чекає готовності. Токен, адреса й порт зберігаються. Під час заміни буде коротка перерва. Блокування теки не дозволяє запускати дві операції одночасно.

Якщо збірка впала, запущений контейнер лишається працювати. Якщо впала заміна або подальші перевірки, команда завершується з помилкою; **автоматичного відкату немає**. Перегляньте логи, виправте причину й повторіть `update`. Джерела вже можуть бути новішими, навіть якщо контейнер ще працює зі старим образом.

Скрипт не оновлює сам себе. Щоб перейти на нову версію помічника, завантажте й перегляньте її окремо; збережіть наявний `.env` і перевірте інструкції перенесення на цій сторінці перед заміною локального скрипта.

## Стан і типові проблеми

```bash
bash "$HOME/obico-ml/obico-ml.sh" status
bash "$HOME/obico-ml/obico-ml.sh" logs
curl --noproxy '*' -fsS http://10.0.0.20:3333/hc/
```

Остання команда має повернути `ok`. Тіло відповіді `error`, навіть із HTTP 200, означає, що модель не готова.

| Симптом | Що перевірити |
|---|---|
| Порт зайнятий / не вдалося прив'язати адресу | IP має належати цьому хосту, а порт — бути вільним. Змініть `ML_BIND` чи `ML_PORT` у `.env`, потім виконайте `update`. |
| Помилка збірки чи завантаження | Доступ до реєстру, GitHub і хоста моделей, вільний диск та вивід збірки Docker. |
| ML здоровий, але BamDude отримує 401 | Вставте значення з команди `token` у поле токена ML API в BamDude. |
| ML здоровий, але детекцій немає | Перевірте активний друк, вибрані принтери, доступність камери й зовнішній URL **із ML-контейнера**. Якщо перед BamDude є шлюз авторизації, він має пропускати запит по кешований кадр. |
| Локальні зміни джерел / неможливий fast-forward | Перевірте `source/`; скрипт навмисно не відкидає ваші правки й не скидає історію Git. |
| Встановлення впало до завершення клонування | Перегляньте частково створену теку. Повторіть у новій порожній теці; не видаляйте наявне встановлення наосліп. Після завершеного клонування `update` може повторити невдалу збірку чи запуск. |
| API відповідає, але збережених кадрів немає | Історію кадрів зберігає BamDude, а не ML-контейнер. Перевірте налаштування запису та які події записує ваша версія BamDude; живий лічильник не означає збереження кожного кадру. |

## Джерела й межі

Цей помічник супроводжується в репозиторії документації BamDude. Реалізація Obico лишається в upstream: [Dockerfile ML](https://github.com/TheSpaghettiDetective/obico-server/blob/release/ml_api/Dockerfile), [опис сервісу](https://github.com/TheSpaghettiDetective/obico-server/blob/release/docker-compose.yml), [API](https://github.com/TheSpaghettiDetective/obico-server/blob/release/ml_api/server.py) та [автентифікація](https://github.com/TheSpaghettiDetective/obico-server/blob/release/ml_api/auth.py). Встановлення й оновлення слідують за `release`, а не за фіксованою ревізією моделі. Перед оновленням робочої ферми переглядайте зміни upstream.
