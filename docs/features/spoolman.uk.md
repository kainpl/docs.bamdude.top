# Інвентар філаменту та Spoolman

BamDude постачається з **повноцінним інвентарем філаменту** — сторінкою **Філамент** у бічному меню. Це джерело істини для ваги котушок, RFID, локації та вартості — жодного зовнішнього сервісу не потрібно. Якщо ви вже використовуєте [Spoolman](https://github.com/Donkie/Spoolman), опціональний шар синхронізації тримає обидві системи в актуальному стані; якщо ні — BamDude робить усе сам.

!!! tip "Spoolman не обов'язковий"
    Вбудований інтентар повністю працює standalone. Синхронізація зі Spoolman — це суто інтеграційний вибір для тих, хто вже централізує котушки в кількох інструментах (наприклад, OctoPrint, Mainsail, Klipper, кілька slicer-хостів). Обирайте те, що підходить вашому workflow.

=== ":material-package-variant: Вбудований інвентар"

    BamDude-native — без зовнішніх сервісів, без мережевих round-trip-ів, кожна колонка лежить у `data/bamdude.db`.

=== ":material-sync: Синхронізація зі Spoolman"

    Add-on інтеграція з self-hosted сервером Spoolman. Двостороння, з тонким налаштуванням по концернах (вага vs локація vs звіт про часткове використання).

## :material-package-variant: Вбудований інвентар

Відкрийте **Філамент** у бічному меню. Кожен рядок — фізична котушка: додана вручну, імпортована за RFID або автоматично створена при скануванні AMS.

### :material-plus-box: Додавання котушок

Форма "Add Spool" покриває все, що BamDude трекає по котушці:

| Поле | Примітки |
|------|----------|
| `brand` | Вільний текст (наприклад, `Polymaker`, `Bambu Lab`, `SUNLU`). |
| `material` | `PLA`, `PETG`, `ABS`, `TPU`, `PA`, `PC`, `PVA`, `ASA`, … |
| `subtype` | `Basic`, `Matte`, `Silk`, `CF`, `Tough`, … |
| `color_name` + hex | Вільнотекстова назва кольору + `#RRGGBBAA` зразок. Hex-input нормалізується на кожен keystroke — вставте `#FFAA00` і BamDude доповнить його до `FFAA00FF`. |
| `purchase_date` | Коли ви її реально купили. Відрізняється від `created_at` (коли рядок було імпортовано). Колонка "Added" віддає перевагу цьому полю, якщо воно задане. |
| `filament_diameter` | `1.75` або `2.85`. За замовчуванням `1.75`. |
| `label_weight_g` | Заявлена нетто-вага на етикетці (за замовчуванням 1000 г). |
| `core_weight` | Вага порожньої котушки, використовується для розрахунку залишку через ваги. Підтягується з каталогу при збігу brand+spool. |
| `lot` | 1-based позиція всередині закупки. Шлях масового додавання може автонумерувати `1..N` server-side через checkbox **auto-increment lots**. |
| `cost_per_kg` | Просто число, без знака валюти. Множиться на вагу друку для поля cost в архіві. |
| `note` | Вільнотекстова нотатка (`Kuhonna polychnia`, `Відкрита 12 квіт`, …). |
| `tag_uid` / `tray_uuid` | RFID-ідентифікатори. Порожні для котушок, доданих вручну — прив'яжіть тег пізніше через matcher. |

Масове додавання приймає кількість і створює N рядків за раз — комбінуйте з **auto-increment lots**, щоб пронумерувати пакет з 5 котушок як `lot 1..5` без ручного набору кожної.

### :material-format-text: Шаблон display-name котушки

Сторінка «Філамент» синтезує людський лейбл по котушці через user-configurable шаблон. Редагуйте під **Налаштування → Філамент → Основне → Відображувана назва котушки**.

За замовчуванням: `{brand} {material} {subtype} {color_name}` (рендериться як, наприклад, `Polymaker PLA Matte Jade White`; у котушки без підтипу це слово просто пропускається). Шаблон змінює лише те, як котушка називається: пошук знаходить котушку за брендом, матеріалом, підтипом, кольором, приміткою чи партією, хоч що показує шаблон.

| Токен | Джерело | Приклад |
|-------|---------|---------|
| `{brand}` | колонка | `Polymaker` |
| `{material}` | колонка | `PLA` |
| `{subtype}` | колонка | `Matte` |
| `{color_name}` | колонка | `Jade White` |
| `{slicer_filament_name}` | колонка | `Polymaker PolyTerra PLA @Bambu Lab X1C` |
| `{note}` | колонка | `Kuhonna polychnia` |
| `{label_weight_g}` | колонка | `1000` |
| `{label_weight_kg}` | обчислене | `1` (round) або `0.75` (дробове) |
| `{remaining_g}` | обчислене `label − used` | `750` |
| `{remaining_kg}` | обчислене | `0.75` |
| `{remaining_pct}` | обчислене | `75%` |
| `{color_hex}` | обчислене з `rgba` | `#FF3300` |
| `{cost_per_kg}` | колонка | `25` |
| `{purchase_date}` | колонка | `2026-04-15` |
| `{filament_diameter}` | колонка | `1.75` |
| `{lot}` | колонка | `3` |

!!! tip "Невідомі токени залишаються verbatim"
    Зробите друкарську помилку типу `{brnd}` — live-preview залишить її як є. Це одразу показує помилку, замість того, щоб тихо схлопнутися в порожній проміжок.

### :material-view-column: Видимість колонок

Натисніть **Налаштувати стовпці** на сторінці «Філамент», щоб перемкнути, які колонки видимі і в якому порядку. Налаштування — per-user.

**Видимі за замовчуванням:** `brand`, `material`, `color_name`, `remaining`, `location`, `note`, `purchase_date`.
**Приховані за замовчуванням:** `created_at` ("added time" — витіснений `purchase_date`).

Колонка, якої ваша збережена розкладка ще не знає, лягає на свою дефолтну позицію, а не в кінець, тож збережену розкладку не треба переставляти.

### :material-magnify-scan: Auto-assign по RFID

У хедері сторінки «Філамент» є дія **Auto-assign**: BamDude сканує всі AMS-слоти підключених принтерів, матчить `tag_uid` / `tray_uuid` кожного слота з рядками інвентаря і масово створює записи `SpoolAssignment`. Корисно після перезавантаження кількох котушок — один клік, без ручного підбору.

### :material-link-plus: Прив'язка невідомого RFID до ручної котушки

Коли на принтері з'являється невідомий RFID-тег, popover слота AMS пропонує прив'язати його до існуючого рядка інвентаря, у якого ще немає тега. Use case: сторонні бренди без RFID, заправлені core-и або котушка, яку ви купили до того, як почали користуватися BamDude. Виберіть рядок, підтвердіть — тег прикріплено, наступне сканування авторезолвиться.

## :material-sync: Синхронізація зі Spoolman

Опціонально. Підключіть BamDude до інстансу [Spoolman](https://github.com/Donkie/Spoolman) — і дві системи дзеркалитимуть одна одну.

### :material-spool: Що таке Spoolman?

[Spoolman](https://github.com/Donkie/Spoolman) — це open-source self-hosted менеджер інвентарю філаменту для 3D-друку. Він живе як окремий сервіс (Docker, bare metal або Spoolman-сумісний хмарний інстанс) і експонує REST API для трекінгу котушок, історії використання, vendor/material таксономії, low-stock-alert-ів і — найважливіше для multi-tool сетапів — є єдиним джерелом правди, проти якого можуть синкатися інші інструменти (OctoPrint, Mainsail, Klipper, кілька slicer-хостів).

Якщо у тебе тільки BamDude, вбудований інвентар вище вже робить усе, що робить Spoolman. Інтеграція — для тих, хто **вже** має Spoolman через якийсь інший хост у своєму сетапі.

### :material-link: Підключення

1. **Налаштування** → **Філамент** → **Основне** → **Відстеження філаменту** → **Spoolman**
2. Задайте **URL Spoolman** (наприклад, `http://192.168.1.50:7912` або docker-compose service alias типу `http://spoolman:7912`)
3. **Зберегти**

Поля для API-ключа немає: BamDude звертається до відкритого HTTP API Spoolman, тож Spoolman за проксі з авторизацією має бути досяжним для BamDude без облікових даних.

Статус біля URL щоразу питає налаштований Spoolman, чи він відповідає, — а не те, чи BamDude колись раніше з ним говорив. Поки він не відповідає, кнопка **Connect** пробує ще раз. Кнопки Disconnect немає: Spoolman — звичайний HTTP API без сесії, яку можна закрити, а вимикає інтеграцію перемикач увімкнення.

Додаткові поля, які BamDude тримає на котушці (RFID-мітка, пресет слайсера, назва кольору), реєструються в Spoolman першим записом, що їх несе, тож досить увімкнути інтеграцію в налаштуваннях — для першої синхронізації AMS нічого не треба створювати в Spoolman вручну. Поле, яке вже існує, не чіпається — навіть якщо ти перейменував чи змінив його тип в інтерфейсі самого Spoolman.

!!! tip "Доступність по мережі"
    BamDude має змогу досягти Spoolman URL зсередини власного процесу. На docker-compose тримайте обидва сервіси в одній мережі і використовуйте service alias; на bare metal достатньо LAN-хостнейму або статичного IP.

### :material-tune: Контроль синхронізації

| Налаштування | Ефект |
|--------------|-------|
| `spoolman_enabled` | Master switch. |
| `spoolman_sync_mode` | `auto` (пушити кожну зміну AMS одразу) або `manual` (чекати explicit натискання Sync). |
| `spoolman_disable_weight_sync` | Скіпати оновлення `remaining_weight` на існуючих spool-ах Spoolman. Використовуйте, якщо Spoolman — ваш authoritative weight tracker (його гранулярний звіт з'їдає AMS-оцінки). |
| `spoolman_report_partial_usage` | Коли друк падає або скасовується, звітувати **орієнтовну кількість грамів, використаних до точки переривання**, на основі прогресу по шарах, замість того щоб скидати всю оцінку. Допомагає Spoolman тримати точну вагу після фейлів. |

!!! warning "Зміна режиму обліку знімає призначення слотів"
    Вибір **Вбудований інвентар** чи **Spoolman** у **Налаштування → Філамент → Основне → Відстеження філаменту** знімає всі призначення слотів AMS того режиму, з якого ви йдете, — кожен режим має свої, і в новому котушки призначаються слотам заново. Тому сторінка питає перед зміною: скільки призначень буде знято і які принтери зараз друкують — філамент цих друків не потрапить у жоден інвентар. Самим кліком нічого не змінюється.

    Друк, що завершився й не зміг списати філамент зі слота, з якого друкував (призначення зняли під час друку або його не було), надсилає сповіщення **Філамент не списано** зі слотами й грамами. Воно йде за перемикачем **Відсутнє призначення котушки** ваших провайдерів сповіщень.

### :material-sync-circle: Що синхронізується

- **Слот AMS ↔ Spoolman spool** — кожен заряджений слот мапиться на Spoolman spool ID. Матеріал, бренд, колір і (якщо `disable_weight_sync` не увімкнено) залишок ваги тримаються в курсі один одного. Прозора чи напівпрозора котушка зберігає прозорість у `color_hex` Spoolman (вісім символів); непрозора лишається шестисимвольною, як і всі наявні філаменти, тож нічого вже збереженого не переписується й не дублюється.
- **Споживання друку** — кожен завершений друк звітує грами в Spoolman як usage event. Скасовані / провалені друки поважають `spoolman_report_partial_usage`.
- **Локація** — **місце зберігання**, яке ви обираєте для котушки, записується в поле `location` Spoolman, а назви локацій зі Spoolman зʼявляються у списку місць зберігання BamDude. Слот принтера — не місце зберігання: яка котушка де завантажена, відстежують призначення слотів, а не поле `location`.
- **RFID** — Bambu Lab tray UUID-и пробрасуються в поле `extra.tag` Spoolman, а на Spoolman 0.27 і новіших ще й прив'язуються як власні мітки Spoolman (див. [Мітки](#spoolman-tags)).

!!! note "Вага чекає, доки друк буде списано"
    Поки друк триває і доки його витрату не списано, автоматична синхронізація ваги котушок із мітками та **Синхронізувати ваги AMS у Spoolman** оминають цей принтер — інакше спершу записалося б показання залишку з принтера, а грами самого друку зняли б ще раз поверх нього. Синхронізуйте знову, коли друк завершено і списано.

### :material-link-off: Відв'язка

Окремої кнопки **Unlink** на слоті немає — у жодному режимі синхронізації. Котушку від слота чи від її мітки відокремлюють у двох місцях:

- **Зняти призначення** на hover-картці слота AMS знімає призначення слота. Котушка лишається в Spoolman.
- **Очистити RFID мітку** у формі котушки на сторінці **Філамент** прибирає прив'язку мітки — `extra.tag`, а на Spoolman 0.27 і новіших ще й власні мітки котушки (див. [Мітки](#spoolman-tags)).

### :material-tag-multiple: Мітки {#spoolman-tags}

BamDude тримає мітку котушки в полі `extra.tag` Spoolman. Spoolman 0.27 і новіші ще й самі прив'язують мітки до котушок; з таким сервером BamDude працює з обома способами:

- Котушку, якій мітку призначили в самому Spoolman, BamDude впізнає як ту саму котушку, коли вона з'являється в AMS, — другої котушки поряд не створює.
- Прив'язка мітки записує і `extra.tag`, **і** власну мітку Spoolman, тож Spoolman та інші зчитувачі міток знаходять ту саму котушку. `extra.tag` записується завжди, тож старіший зчитувач нічого не втрачає.
- Відв'язка котушки або **Очистити RFID мітку** у формі котушки прибирає обидві.
- Прив'язати мітку, яку вже тримає інша котушка, не вдасться: відмова називає цю котушку — архівну теж. Спершу відв'яжіть мітку там.

Котушки, прив'язані, коли сервер ще не мав власних міток, мають лише `extra.tag`. **Налаштування → Філамент → Відстеження філаменту** показує блок **Власні мітки Spoolman** для підключеного Spoolman, який їх підтримує: **Перевірити мітки** показує, що буде скопійовано, що вже є у Spoolman, і кожен конфлікт (дві котушки з однією міткою; мітка, що належить іншій або архівній котушці; мітка, прив'язана до філаменту); **Скопіювати мітки** потім копіює ті, що без конфлікту. Конфлікти ніхто не розв'язує за вас — вирішіть у Spoolman, якій котушці належить кожна мітка, і перевірте ще раз. Ідентифікатори слотів AMS, що стоять замість мітки, і мітки архівних котушок не копіюються.

Старіші версії Spoolman працюють лише через `extra.tag`.

### :material-poll: Результати синхронізації

Після кожного синку (auto чи manual) BamDude показує панель результатів:

- **Synced count** — скільки котушок успішно синхронізовано.
- **Skipped spools** — список котушок, які не змогли синкатися, з причиною per-row (наприклад, "Non-Bambu Lab spool", "No matching material in Spoolman", "Manual unlink in effect"). Кожен скіпнутий ряд показує локацію, кольоровий swatch і текст причини.
- **Errors** — будь-які HTTP / network / data помилки під час запуску.

!!! note "Детекція Bambu Lab RFID"
    Auto-sync фаєриться лише для **офіційних Bambu Lab котушок з RFID** — third-party, refilled, SpoolEase скіпаються спеціально, щоб не плодити фейкові ряди в Spoolman. Bambu Lab котушки ідентифікуються за hardware-ідентифікаторами (`tray_uuid` і `tag_uid`), не за іменем filament-preset. Не-Bambu котушки можна **призначити слоту вручну** (див. нижче).

### :material-chart-line: Трекінг використання

Кожен завершений друк звітує per-filament споживання у Spoolman як usage event:

1. BamDude дістає per-filament дані використання з архівованого 3MF-файлу (slicer estimates).
2. Для часткових друків (фейли, скасування) per-layer G-code-аналіз дає точне споживання до точно того шару, де друк впав. Якщо котушка змінилася під час друку — резерв AMS перейняв подачу або в той самий слот вставили нову котушку, і в одноколірному, і в багатоколірному друці, — це споживання ділиться за відрізком, який кожна котушка справді надрукувала до зупинки, так само, як ділить вбудований інвентар (див. [Інвентар](inventory.md)).
3. На завершенні кожна котушка звітується індивідуально — multi-material-друк оновлює кожну прив'язану котушку окремо. Лоток кожного філаменту — той, з яким друк було відправлено; для друку, який відправив не BamDude і чий мапінг він не бачив (A1 його не публікує), одно-філаментний друк списується з лотка, який назвав сам принтер. Лише коли лотка не назвало ніщо, списання йде за позицією лотка — це здогадка: вона пишеться в лог як попередження, і тоді архів лишає колір і матеріал з нарізаного файлу, а не бере їх із котушки, обраної за позицією. На принтері з двома зовнішніми тримачами (X2D, H2D) друк із зовнішньої котушки списується з того тримача, з якого справді друкували.
4. **Fallback за AMS remain-% для слотів, які 3MF не покрив.** Коли для слота немає 3MF-оцінки — no-3MF "Untitled" друк (`.gcode.3mf` не завантажився, тож архів це fallback-рядок) **або** часткове покриття 3MF, де завантажений слот не був у slice-info — BamDude падає на per-slot просадку залишкового відсотка AMS. На завершенні він пише `(remain% на старті − remain% в кінці) × розмір котушки в Spoolman` грамів як usage event — власний розмір котушки або вагу її філаменту, коли котушка свого не має (див. [Розмір, тара і ціна котушки](#spoolman-spool-size)). Він бере цю вагу зі Spoolman (а не ненадійну tray-вагу з AMS) і **пропускає будь-який слот, свопнутий посеред друку** (змінився tray UUID), бо не може розділити споживання між двома котушками.

Це збігається з BamDude-моделлю per-spool — ті самі цифри, що годують сторінку Stats, годують і Spoolman. Провалений чи скасований друк списується за тим самим розрахунком в обох інвентарях. Сам Spoolman зберігає лише підсумки котушки, без журналу по друках; запис по кожному друку веде BamDude (див. [Історія використання і прогноз](#spoolman-usage-history)).

**Про витрату, яку Spoolman не прийняв, повідомляється.** Якщо Spoolman не відповідає, коли друк закінчується, витрата цього друку не записується і пізніше не повторюється. BamDude надсилає сповіщення **Філамент не списано** зі слотами й грамами, а лог сервера називає друк, котушки і грами, тож вагу можна виправити вручну.

**Архів дізнається, що списано.** Кожне списання, що пройшло, оцінюється за власною котушкою — ціна котушки, поділена на розмір котушки, якщо задана, інакше ціна її філаменту, поділена на вагу філаменту, — тож багатоматеріальний друк рахує кожен слот за його ціною, а грами, які жодна котушка не оцінила, покриваються типовою ціною філаменту ферми. Вага філаменту в архіві йде за тим самим правилом, що й у вбудованому інвентарі: друк, що впав, або друк без 3MF записує реально списані грами; завершений друк лишає оцінку слайсера. Котушка без ціни не чіпає записаної вартості. **Перерахувати вартість** на сторінці статистики лишає так оцінену вартість, а не переоцінює її за типовою ціною, і каже, скільки лишила.

### :material-tray-full: AMS-слот мапінг (hover-картка)

Наведи на будь-який AMS-слот на сторінці Printers і побачиш:

| Поле | Джерело |
|------|---------|
| **Vendor** | Bambu Lab або Generic — читається з RFID-тега. |
| **Profile** | Тип і subtype філаменту (`PLA Basic`, `PETG Translucent`, …). |
| **Color** | Назва кольору + swatch — резолвиться через color-каталог BamDude (єдине джерело правди). У Spoolman немає поля назви кольору, тож котушка, чию назву BamDude не зберігав, показує назву з каталогу для свого swatch, а не свій підтип (`Silk+` — не колір); пошук знаходить котушку за назвою кольору, яку видно. |
| **K Factor** | Pressure-advance значення активне для цього слота. |
| **Fill Level** | Залишок у відсотках, з візуальним bar'ом. |
| **Spool ID** | Прив'язаний Spoolman spool ID (тільки коли Spoolman увімкнено і слот прив'язаний). |

#### Fill Level для AMS Lite / зовнішніх котушок

AMS Lite (наприклад, A1 серія) **не має сенсора ваги** і завжди звітує 0% fill level. Коли котушка прив'язана до Spoolman і там є weight-дані, BamDude використовує remaining-вагу зі Spoolman:

- **AMS з ваговим сенсором** — використовує AMS-відсоток напряму (без змін).
- **AMS Lite (звітує 0%)** — fallback на Spoolman: `(remaining_weight / filament_weight) × 100`.
- **External spool** — показує fill з Spoolman, якщо прив'язано (інакше `—`).

Коли джерело — Spoolman, hover-картка показує "(Spoolman)" поряд з відсотком, щоб видно було, звідки число.

### :material-link: Дії зі слотом на hover-картці

Кожна hover-картка слота AMS несе дії для котушки в цьому слоті; які саме з'являються — залежить від стану слота:

| Стан | Кнопка | Що робить |
|------|--------|-----------|
| **Котушку призначено або прив'язано за міткою** | **Відкрити в інвентарі** | Відкриває цю котушку на сторінці **Філамент** у BamDude. Власний інтерфейс Spoolman відкриває кнопка **Відкрити Spoolman** у заголовку тієї сторінки. |
| **Котушку призначено** | **Замінити котушку** | Відкриває picker котушок і одним кроком ставить у слот іншу котушку Spoolman. |
| **Котушку призначено** | **Зняти призначення** | Знімає призначення слота. Котушка лишається в Spoolman. |
| **Котушку не призначено** | **Призначити котушку** | Відкриває picker котушок — так само прив'язують до слота перезаправлену чи сторонню котушку без RFID. Неактивна, з поясненням причини, поки Spoolman недосяжний. |

Кнопок **Link to Spoolman**, **Manual Link** чи **Open in Spoolman** на картці немає: слот зв'язують із котушкою призначенням.

Щоб прибрати **прив'язку мітки**: відкрий форму котушки на сторінці **Філамент** і натисни **Очистити RFID мітку** — це очищає `extra.tag`, а на Spoolman 0.27 і новіших ще й власні мітки котушки.

### :material-database: Додавання котушок — AMS vs Inventory view

| Поверхня | Дія | Коли використовувати |
|----------|-----|----------------------|
| **З AMS** | Котушку Bambu Lab з RFID, якої Spoolman ще не знає, створює там синхронізація AMS | First-time onboarding, додати свіжо завантажену Bambu-котушку до Spoolman. |
| **У Spoolman напряму** | Add Spool на web UI Spoolman | Bulk-import історичних котушок, додавання котушок, які ще не завантажував, vendor/cost data entry. |
| **Сторінка «Філамент»** (BamDude) | **Додати котушку** на сторінці **Філамент** | У режимі Spoolman форма працює з котушками Spoolman, тож котушка створюється в Spoolman, не виходячи з BamDude. |

Саме призначення слота дозволяє AMS-hover-картці резолвити слот до Spoolman-ряду.

### :material-robot: Автофічі

Три речі відбуваються без кліку, поки Spoolman увімкнено. Власних перемикачів вони не мають — ті, що йдуть від AMS, підпорядковані **Режиму синхронізації** (**Автоматичний** / **Тільки вручну**), а звітування витрат для зупинених друків — перемикачу **Звітувати часткове використання для невдалих друків**:

- **Auto-sync on print complete** — кожен завершений друк звітує per-filament usage індивідуально у Spoolman, тож spool-quantities оновлюються автоматично.
- **Auto-detect on AMS change** — коли AMS-філамент змінюється, BamDude детектує нову конфігурацію, матчить проти Spoolman і оновлює slot mapping без втручання.
- **Auto-clear location on removal** — коли котушку прибирають з AMS, BamDude детектує порожній слот, знаходить Spoolman-котушки з відповідним рядком локації і чистить поле `location`. Котушка тепер доступна іншим принтерам.

!!! info "Маркери слотів у `location`"
    Поле `location` котушки в Spoolman може містити маркер слота — `H2D-Workshop - AMS A1`, `AMS-HT A1`, `External Spool` — назву слота, у який котушку колись завантажили. BamDude таких маркерів не пише. Наявні лишаються на ваших котушках у Spoolman, але як місця зберігання не пропонуються (якщо жодна котушка тут не записана під таким місцем). З котушки Bambu Lab маркер знімається, щойно вона покидає AMS.

### :material-server-network: Multi-printer синк

Один інстанс Spoolman обслуговує кілька BamDude-принтерів (та інші тулзи) одночасно:

- Кожен AMS принтера синкається незалежно.
- Різні котушки на принтер, окремий usage-tracking.
- Уніфікований інвентар у Spoolman — одне джерело правди по всій фермі.

Це головна причина, чому більшість farm-операторів обирають крутити Spoolman поряд з BamDude навіть коли built-in інвентар працює standalone — Spoolman це cross-tool хаб.

## :material-table-cog: Інвентарний UI (BamDude-сторона, бекенд — Spoolman)

Коли BamDude підключений до Spoolman, **сторінка «Філамент»** (`/inventory`) і **сторінка принтерів** (`/`) розгортаються у повноцінний Spoolman-flow: AMS-присвоєння слотів живе у власних таблицях BamDude (присвоєння переживає рестарт і їде разом з бекапами), K-профайли по котушці їдуть між інсталами BamDude, що ділять один Spoolman-бекенд, а вільне сторадж-полe лежить біля кожної котушки.
### :material-table: Сторінка «Філамент» у режимі Spoolman

Коли Spoolman увімкнено, сторінка **Філамент** — це власна сторінка BamDude, яку наповнюють дані Spoolman: таблиця й картки, форма котушки, етикетки та масові дії працюють із котушками Spoolman. [Наліпка](labels.md) котушки Spoolman несе ті самі поля, що й локальної. Коли адресу Spoolman задано, кнопка **Відкрити Spoolman** у заголовку сторінки відкриває власний інтерфейс Spoolman у новій вкладці.

Дещо відрізняється від вбудованого інвентаря:

- **Номер матеріалу** показує артикул філаменту зі Spoolman і лише для читання — змінюйте його у Spoolman.
- **Востаннє сушено** записується і для котушок Spoolman: циклом сушіння в AMS, де стоїть котушка, або вручну у формі котушки.
- **Скинути лічильник** обнуляє показник спожитого, який показує BamDude, і не чіпає власних чисел Spoolman — використаної й залишкової ваги. Масове скидання каже, які котушки скинути не вдалося.
- **Імпорт CSV** / **Експорт CSV** вимкнено — користуйтеся власним CSV-імпортом і експортом Spoolman.
- **Переоцінити витрати** на сторінці **Статистика** працює лише із записами вбудованого інвентаря і в режимі Spoolman недоступне.

Щоб прибрати збережений пресет, натисніть **Очистити сім’ю або пресет філаменту** у формі котушки. В інвентарі й далі видно назву філаменту з каталогу. Як зберігається пресет під час копіювання, описано в розділі [Сім’ї філаментів](filament-families.md).

BamDude читає відомий підтип і колір із назви філаменту в Spoolman. Наприклад, у `Matte Scarlet Red` підтипом буде `Matte`, а кольором — `Scarlet Red`. Збережена назва кольору має пріоритет. Якщо матеріал і підтип лишаються тими самими, редагування котушки зберігає оригінальну каталожну назву навіть тоді, коли для неї потрібен окремий запис філаменту.

### :material-history: Історія використання і прогноз {#spoolman-usage-history}

Spoolman зберігає лише підсумки котушки, без журналу по друках, тож BamDude веде власний запис кожного друку, який списує з котушки Spoolman. Цей запис живить режим **Історія** сторінки «Філамент», історію використання у формі котушки, вкладку **Прогноз** і сповіщення **Час замовляти** / **Ризик закінчення** — ті самі подання, що й у вбудованому інвентарі (див. [Інвентар → History](inventory.md#history)).

- **Запис починається з першого друку, який списує BamDude.** Друки, списані до того, як BamDude почав вести цей запис, зі Spoolman відновити неможливо: він не зберігає даних по друках.
- **Видалення записів не чіпає Spoolman.** Видалення одного запису чи очищення історії котушки прибирає лише записи BamDude; вага котушки у Spoolman не змінюється.
- **Історія належить адресі Spoolman.** Коли URL Spoolman змінюється, записи, зроблені для попередньої адреси, відкладаються окремо, а подання для нової починаються порожніми; якщо повернути попередню адресу, її історія повертається. Якщо за новою адресою та сама база Spoolman (хост перейменували чи перенесли), **Історія** каже, скільки записів відкладено, і пропонує **Та сама база — залишити історію**, щоб перенести їх.
- **Прогнозу потрібен Spoolman.** Запас зберігається у Spoolman, тож поки Spoolman не відповідає, прогнозу показати нема з чого.

[Git-бекап](backup.md) несе цю історію в категорії **Інвентар котушок** і відновлює її на той Spoolman, яким користується інсталяція, що відновлюється.

### :material-weight-gram: Розмір, тара і ціна котушки {#spoolman-spool-size}

Spoolman зберігає, скільки філаменту вміщує повна котушка, на самій котушці й бере вагу філаменту лише тоді, коли котушка свого розміру не має, — тож один філамент може мати котушки різного розміру. BamDude читає це так само всюди: список, синхронізації ваги, облік витрат і ціна за грам беруть власний розмір котушки.

- **Вага на етикетці** — створення котушки записує її розмір на цю котушку; редагування змінює лише цю котушку, а не філамент чи інші його котушки.
- **Вага порожньої котушки** — власна тара котушки, далі тара її філаменту, далі вага порожньої котушки виробника, у порядку самого Spoolman.
- **Вартість за кг** — Spoolman зберігає ціну котушки як те, скільки коштувала *ця котушка*, а не як ставку. Форма котушки показує її перерахованою через розмір котушки й перераховує назад під час збереження: котушка 250 г, що коштувала 10, читається як 40 за кг, а якщо ввести 40 за кг для котушки 250 г, збережеться ціна 10. Ціна, задана на філаменті, розкладається на вагу філаменту.
- **Що списується за друк** — ціна котушки, а коли її немає — ціна філаменту. Колонка **Вартість/кг** показує саме цю ставку, а діалог друку оцінює кожен слот і показує залишок у грамах за котушкою Spoolman, прив'язаною до цього слота.

!!! note "Ціна, яку мали на увазі як ставку"
    Оскільки ціна на котушці Spoolman — це ціна самої котушки, котушка не на 1 кг, чию ціну ввели як ставку за кг, читається з іншою вартістю за кг: котушка 250 г із ціною 40 показує 160 за кг. Нічого збереженого не переписується — виправте вартість у формі котушки.

**Котушки, розмір яких відрізняється від розміру філаменту.** Розмір котушки у Spoolman задається під час її створення і не йде за пізнішою зміною ваги філаменту, тож котушка може показувати не той розмір, якого ви чекаєте від її філаменту. Для підключеного Spoolman **Налаштування → Філамент → Відстеження філаменту** перелічує кожну таку активну котушку з її власним розміром, розміром її філаменту і залишком у грамах. **Взяти для цієї котушки розмір філаменту** змінює цю одну котушку після підтвердження; спожите лишається, тож залишок у грамах змінюється разом із розміром.

Один spool на слот. | Власне `location` у Spoolman — це вільний текст; використовувати його як джерело істини для "котушка зараз у слоті 3 AMS A принтера X" втрачає структуру (наприклад, не можна відфільтрувати "усі котушки, зараз завантажені"). Структурна таблиця піддається query і автоматично очищається коли слот спорожнів. |
| `spoolman_k_profile` (БД BamDude) | Pressure-advance + setting_id по `(spoolman_spool_id, printer_id, extruder, nozzle_diameter)`. Один + два екструдери. | K-профайл прив'язаний до фізичного філамент ↔ фізичний принтер + сопло, не лише до Spoolman-рядка. Зберігання на BamDude-стороні значить, що повторне тапання тієї самої Bambu RFID на іншому принтері не втратить калібрування, зроблене в іншому місці. |
| `spool.storage_location` (колонка БД BamDude) | Вільний текст типу `Drybox 3`, `Полиця A4`, `Цех / шафа 2`. | Дзеркалить Spoolman-полe `location`, але живе теж BamDude-сторінкою — щоб поле відображалось у колонках сторінки інвентарю + у формі котушки навіть на Spoolman-mode інсталах. |

Spoolman-полe `location` лишається недоторканим зі сторони Spoolman — оператори далі можуть заповнювати його з власного UI Spoolman як вільний текстовий лейбл. Структурна таблиця присвоєнь BamDude — джерело істини для "що зараз у принтері X".

### :material-printer: Сторінка принтерів — Spoolman-mode інтеграція слотів

Кожен тип слота на сторінці принтерів читає Spoolman-стан коли Spoolman-mode увімкнений:

- **Звичайні AMS-слоти** (AMS 0..7, лоток 0..3) — fill bar, ім'я пресета, swatch кольору і "Assigned spool" пілюлька в hover-карті — все читається з `spoolman_slot_assignments` приєднаних до `spoolman_inventory/spools`. Коли в слоті немає RFID-прив'язаної котушки, обчислення fill керується рядком присвоєння.
- **HT (high-temperature) слоти** — той самий flow, що й звичайні AMS, плюс H2D Ext-R single-tray зовнішній слот.
- **External Spool 254 / 255** — читає з тієї ж таблиці присвоєнь; hover-карта слота показує ім'я призначеної котушки + залишок ваги + сторадж.

На слот hover-карта несе:

| Кнопка | Коли з'являється |
|--------|------------------|
| **Призначити котушку** | Слоту не призначено котушку. Відкриває picker котушок Spoolman — без участі RFID, тож годиться й для перезарядженої бобіни чи сторонньої котушки. |
| **Замінити котушку** | Котушку призначено. Одним кроком ставить у слот іншу котушку. |
| **Зняти призначення** | Котушку призначено. Очищає присвоєння на боці BamDude; котушка лишається в Spoolman. |
| **Відкрити в інвентарі** | Котушку призначено або прив'язано за RFID. Відкриває цю котушку на сторінці **Філамент**. |

Окремих кнопок прив'язки за міткою (**Link to Spoolman**, **Manual Link**, **Open in Spoolman**) картка не має, тож один слот ніколи не показує двох способів прив'язати котушку.

Що призначення робить зі слотом:

- **Слот налаштовує власний пресет філаменту котушки.** Коли до котушки не прив'язано калібрування, принтеру каже, що завантажено, пресет, збережений на котушці, — заданий у формі котушки або взятий із лотка, коли BamDude створював котушку. Пресет іншого матеріалу, ніж у котушки, ігнорується, і слот отримує натомість замінний профіль для матеріалу котушки.
- **Профіль pressure advance обирається типово.** Коли профіль не прив'язували до котушки вручну, слот отримує активне калібрування для цього принтера, філаменту, діаметра сопла, типу потоку й екструдера — як у вбудованому інвентарі.
- **Архівну котушку призначити** в слот не можна.
- **Архівування чи видалення котушки звільняє її слот.** Слот звільняється на картці принтера, і наступний друк із нього на цю котушку не списується. Поки котушка стоїть у слоті принтера, який друкує, архівування й видалення відхиляються до завершення друку.
- **Поки Spoolman увімкнено, але він недоступний**, картка принтера не пропонує і не приймає призначення — вона каже *Spoolman недоступний. Призначити котушку можна буде, щойно він відповість.* Котушки вбудованого інвентаря замість нього не пропонуються.

### :material-flash: Авто-перепризначення K-профайлу при зміні AMS

Коли вміст AMS-слота змінюється (повторне RFID-тапання, скид слота, slicer-side `extrusion_cali_sel` зі сторони), BamDude підіймає збережений K-профайл присвоєної котушки для точного triplet'у `(printer_id, extruder, nozzle_diameter)`. Якщо живий `cali_idx` принтера відрізняється від збереженого — BamDude перевидає правильний `extrusion_cali_sel` через MQTT, відновлюючи K-значення, яке оператор обрав минулого разу. Без цього прошивка скидала б K на slot index 0 при кожному ре-тапі.

Drift-detection обмежений — BamDude перевидає тільки коли є справжня різниця, тож steady-state push не спамить принтер.

### :material-storage: Колонка Storage location

Сторінка **Філамент** має колонку **Місце зберігання** на будь-якому бекенді (локальна БД + Spoolman). Редагування inline по рядку; значення зберігається в `spool.storage_location` і виводиться скрізь, де рендериться котушка (карти, hover-карти, форма, пошук). На Spoolman-mode інсталах поле — BamDude-локальне; власне `location` Spoolman лишається оператору на самостійне ведення, якщо звичніше.

### :material-tag-multiple: Ширша підтримка RFID UID

`spool.tag_uid` вміщує до 32 символів. Bambu RFID UID — 16 hex; third-party таги (наприклад, NTAG216 стікери) несуть до 32 hex — ширини колонки досить, щоб прив'язувати такі таги до перезаряджених бобін без обрізки.

### :material-api: API-поверхня

Повний Spoolman-inventory шипається під `/api/v1/spoolman/inventory/*` (19 endpoint'ів, усі gate на `RequirePermission(INVENTORY_*)`). Корисне для скриптів:

- `GET /spoolman/inventory/spools` + `GET /spoolman/inventory/spools/{id}` — list / single з BamDude-приєднаннями (slot assignment, storage_location, лічильники K-профайлів).
- `POST /spoolman/inventory/spools` + `POST /spoolman/inventory/spools/bulk` + `PATCH /spoolman/inventory/spools/{id}` — створення / bulk / update.
- `POST /spoolman/inventory/spools/{id}/archive` + `/restore` — soft-delete через Spoolman archive-флаг. Архівування звільняє слот котушки й відповідає `409`, поки з цього слота подає друк, що зараз іде.
- `POST /spoolman/inventory/slot-assignments` + `DELETE /spoolman/inventory/slot-assignments/{id}` — присвоїти / зняти.
- `GET /spoolman/inventory/slot-assignments` — list-all з даними котушок.
- `POST /spoolman/inventory/spools/{id}/sync-weight` — підтягнути поточну AMS-вагу в рядок котушки.
- `POST /spoolman/inventory/ams-weights/sync` — bulk-sync ваги по всіх присвоєних слотах одним запитом.
- `GET /spoolman/inventory/spools/{id}/k-profiles` + `POST /spoolman/inventory/spools/{id}/k-profiles` — per-spool K-профайл read/save.
- `PATCH /spoolman/inventory/filaments/{id}` — переіменування + propagate `spool_weight` на кожну котушку цього філамента (`keep_existing_spools` обмежує каскад).
- `GET /spoolman/inventory/filaments` + `POST /spoolman/inventory/spools/{id}/link-tag` — пікер-запити.

Повний контракт API: [API Reference → Spoolman Inventory](../reference/api.md).

## :material-database-import: Йдемо зі Spoolman: одноразовий імпорт

Синхронізація вище лишає Spoolman джерелом істини. Якщо ви натомість хочете
**перестати** тримати Spoolman, але зберегти його дані, `scripts/import_spoolman.py`
одноразово переносить котушки у власний інвентар BamDude через API:

```bash
python scripts/import_spoolman.py \
    --spoolman-url http://localhost:7912 \
    --bamdude-url  http://localhost:8000 \
    --api-key      <ключ BamDude API з inventory:update> \
    --dry-run
```

Приберіть `--dry-run`, щоб записати. Переносяться матеріал, колір, бренд, вага
за етикеткою, використана вага, ціна за кг (рахується з ціни котушки у Spoolman)
і tag UID; у примітці лишається id зі Spoolman, тож повторний запуск легко
помітити й відкотити.

!!! warning "Це імпорт, а не синхронізація"
    Він виконується один раз і назад не дивиться. Спершу **вимкніть** синхронізацію
    зі Spoolman, інакше обидві сторони вважатимуть ті самі котушки своїми.

## :material-help-circle: Траблшутинг

**Connection failed**

- Перевір Spoolman URL — відкрий у браузері, щоб переконатися, що сам Spoolman живий.
- Глянь network reachability зсередини контейнера/процесу BamDude до Spoolman (наприклад, `curl http://spoolman:7912/api/v1/info` зсередини контейнера BamDude).
- Якщо Spoolman стоїть за авторизацією, BamDude не може в ньому автентифікуватися — налаштування API-ключа немає. Зроби його досяжним для BamDude без облікових даних.
- Файервол / Docker network isolation — обидва сервіси мають бути в одній мережі або мати explicit routing.

**Sync not working**

- Підтверди, що `spoolman_enabled` on і статус біля URL показує **Connected**.
- Подивись логи самого Spoolman — нові / старіші версії інколи затягують або змінюють REST-контракт.
- Перевір, що котушка розпізнана як Bambu Lab (auto-sync лише для Bambu RFID — див. вище). Для не-Bambu використовуй **Призначити котушку** на hover-картці слота.
- Для multi-printer сетапів — підтверди, що ім'я принтера в BamDude збігається з рядком локації, який Spoolman очікує.

**Wrong spool linked**

- Відкрий форму котушки на сторінці **Філамент** і натисни **Очистити RFID мітку** для unlink.
- З hover-картки AMS у BamDude, **Замінити котушку** → обери правильну Spoolman-котушку.
- Перевір, що RFID-tag UUID збігається з тим, що зберігає Spoolman — mismatched UUID найчастіша причина "linked, але вказує на неправильний ряд".
