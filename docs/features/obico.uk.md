# AI-детекція фейлів Obico

BamDude має опційну інтеграцію з **self-hosted** [Obico](https://github.com/TheSpaghettiDetective/obico-server) `ml_api` — ML-сервісом, що дивиться на кадри з камери під час друку і ловить spaghetti / фейли до того, як це вилізе боком. Інтеграція **вимкнена за замовчуванням**; ферма працює з одним детектором збоїв водночас — Obico або хмарним [OctoEverywhere](octoeverywhere.md), — і його обирають в одному полі. Поки обрано Obico, він поллить кадри камери, віддає в Obico ML-endpoint, згладжує результат у часі, і при стійкому фейлі або нотіфаїть, або паузить друк, або паузить + вимикає принтер через розумну розетку.

!!! info "Тільки self-hosted — без cloud, без obico.io"
    BamDude ходить до **твого власного** Obico `ml_api` через HTTP у локальній мережі. Жодного коннекту до obico.io, жодної реєстрації принтера в Obico web app, жодного WebSocket, жодних кадрів кудись за межі LAN. Кадри живуть у 30-секундному in-process кеші; єдиний зовнішній отримувач snapshot URL — ML-контейнер, який ти контролюєш.

## :material-shield-check: Коли це корисно

Obico найбільше виграє на unattended нічних прогонах і автоматизації ферми. Ловить:

- Відрив / spaghetti на перших ~20 шарах
- Mid-print blob-of-death від невдалої retraction чи layer-shift
- Заклеювання столу на multi-spool друках

Це **не** заміна моніторингу першого шару чи нотифікацій HMS — ті ловлять інші типи фейлів швидше.

## :material-server: Self-host Obico ML API

Тобі потрібен лише `ml_api` контейнер зі стека Obico. Web app, Django site і реєстрація принтера **не потрібні** — BamDude не говорить Obico printer-protocol-ом, тільки сирим classification HTTP-endpoint-ом.

Встановлення, оновлення й типові проблеми описані в окремій інструкції [Сервер Obico ML](../addons/obico-ml.md). Там є скрипт для завантаження: він запускає лише `ml_api`, створює API-токен і зберігає його під час оновлень.

## :material-cog: Налаштування

1. Підніми Obico ML-сервер за окремою інструкцією вище.
2. Відкрий **Налаштування → Виявлення збоїв**.
3. Заповни панель Obico:

    | Налаштування | Примітки |
    |---|---|
    | **ML API URL** | Базовий URL ML-контейнера, наприклад `http://10.0.0.20:3333`, без шляху ендпоінта. |
    | **Токен ML API** | Токен, створений скриптом встановлення (команда `token`). |
    | **Адреса BamDude для ML API (необов’язково)** | Адреса, з якої ML-контейнер забирає кадри камери: адреса BamDude в локальній мережі або ім’я його сервісу Docker, наприклад `http://10.0.0.10:8000` чи `http://bamdude:8000`. Порожнє поле — береться зовнішній URL. Деталі в примітці нижче. |
    | **Чутливість** | `low` / `medium` / `high`. Зсуває рівні Low / High, які має перейти згладжена оцінка. |
    | **Дія при виявленні збою** | **Лише сповіщення**, **Поставити друк на паузу** або **Пауза + вимкнути живлення** (`notify`, `pause`, `pause_and_off`). Деталі нижче. |
    | **Інтервал перевірки (с)** | Секунди між захопленням кадрів (5–120). Менше = швидша реакція, більше bandwidth + витрат на ML. |
    | **Принтери під моніторингом** | Перемикач на кожен принтер. Лиши все увімкненим або обмеж конкретними принтерами (наприклад тільки нічний unattended). Видалений принтер зникає і з цього списку. |

4. Панель зберігає свої поля сама. URL ML API, токен і адреса BamDude зберігаються окремою кнопкою **Зберегти підключення**, і змінювати їх може лише адміністратор.
5. У полі **Детектор збоїв** угорі сторінки обери **Obico (власний сервер)**. Вибір зберігається одразу, і змінити його може лише адміністратор. Детекція починається з наступної перевірки кожного друку, що йде.

!!! warning "ML API потрібна адреса, з якої забирати кадри"
    ML-контейнер сам забирає кожен кадр із BamDude за адресою `<адреса>/api/v1/obico/cached-frame/{nonce}`. Ця адреса — поле **Адреса BamDude для ML API**, якщо воно заповнене, інакше **Налаштування → Мережа → Зовнішній URL**. Одне з двох має бути задане, і адреса має відкриватися зсередини мережі ML-контейнера, а не з твого браузера.

    Заповни **Адреса BamDude для ML API**, коли зовнішній URL — це публічне ім’я за логіном reverse proxy або ML-контейнер просто не може до нього дістатися: вкажи адресу BamDude в локальній мережі або ім’я його сервісу Docker, якщо обидва контейнери в одній Docker-мережі. Потрібна повна адреса з `http://` або `https://`, без логіна, пароля й параметрів запиту. Це поле стосується лише кадрів — посилання в листах і сповіщеннях і далі будуються на зовнішньому URL.

    Якщо не задано жодної з адрес, друки під наглядом не перевіряються: бейдж пише **AI не перевіряє**, а картка статусу — `No address for the ML API to fetch snapshots from`.

### Sensitivity Low / Medium / High

| Рівень | Ефект |
|---|---|
| **Low** | Вищий confidence threshold; менше false positives, але повільніше алертить і може пропустити тонкі ранні фейли. |
| **Medium** | Оригінальні пороги Obico — рекомендована стартова точка. |
| **High** | Нижчий поріг; алертить раніше, більше false positives на retraction-blob-ах / тінях / camera glare. |

## :material-radar: Як працює детекція

Цикл поллить кожен увімкнений друкуючий принтер з заданим інтервалом:

1. **Capture** — BamDude бере кадр з локальної камери принтера (без участі Bambu Cloud).
2. **Stash** — JPEG іде в in-process кеш під 32-байтним random nonce з TTL 30 секунд.
3. **Hand off** — BamDude відправляє Obico ML API URL, що вказує назад на `/api/v1/obico/cached-frame/{nonce}`. Obico-сервер фетчить цей URL і запускає класифікатор. (Тому адреса й важлива: **Адреса BamDude для ML API**, а коли це поле порожнє — зовнішній URL, має відкриватися з Obico-хоста.)
4. **Оцінка** — рішення приймається так само, як у самому Obico, тією ж арифметикою, що й на його сервері. Один кадр ніколи нічого не запускає.

    - Сире значення кадру — сума confidence усього, що модель у ньому позначила.
    - Сирі значення згладжуються експоненційно зваженим середнім (`alpha = 2/13`), яке на кожному друці починається з нуля.
    - У кожного принтера є **тло**: довгострокове середнє його кадрів (близько 20 годин друку при типовому інтервалі 10 с). Воно запам’ятовується окремо для кожного принтера й переходить від друку до друку. Усе, що ця камера бачить завжди — фактура столу, наліпка, жолоб для скидання, — стає тлом.
    - **Оцінка** — це згладжене значення мінус тло. Тому те, що камера бачить завжди, у збій не накопичується; рахується лише те, що в кадрі нове.
    - Нижче порога **Low** друк безпечний, вище **High** — це збій. Між ними збоєм вважається лише оцінка, яка ще й помітно вища за недавнє середнє цього ж друку, тобто детекція з’явилась і тримається. Повільне наростання між Low і High збоєм не є.
    - Перші **30 кадрів** друку завжди безпечні (~5 хвилин при типовому інтервалі 10 с).

    Тло тримається в пам’яті: після рестарту BamDude воно починається спочатку й набирається заново на наступних друках.
5. **Два рівні** — детекція реагує на двох рівнях, на кожному один раз за друк:

    - **Рівень сповіщення** — оцінка є збоєм за порогами Low / High (вердикт `warning`). BamDude надсилає **одне сповіщення** за друк, хай яку дію налаштовано. Якщо через три години після останнього сповіщення цього друку підозра на збій лишається, надсилається нагадування — і далі кожні три години, поки вона триває.
    - **Рівень паузи** — сигнал зростав далі й сягнув 1,75 × High (вердикт `failure`); це число картка статусу показує як **Рівень паузи**. Саме тут спрацьовують **Поставити друк на паузу** і **Пауза + вимкнути живлення**, теж один раз за друк.

    Тож із дією-паузою спершу приходить сповіщення, а пауза настає лише тоді, коли сигнал росте далі. З дією **Лише сповіщення** після сповіщення більше нічого не відбувається.

    | Action | Що відбувається |
    |---|---|
    | `notify` | На рівні сповіщення спрацьовує окрема подія **AI Failure Detection** — самостійний **opt-in** тригер (вимкнений за замовчуванням) з власним шаблоном, виділений з `printer_error`, щоб можна було отримувати AI-алерти, не отримуючи пейдж на кожен HMS hardware-код. Алерт несе принтер, назву завдання, детектор, confidence-скор, вжиту дію, що сталося з паузою та живленням, і кадр камери, який позначив детектор. Підписуйся на неї окремо: кожен провайдер має власний тумблер **AI Failure Detection**, а Telegram додає відповідний per-chat notify-пункт. |
    | `pause` | Те саме сповіщення на рівні сповіщення; на рівні паузи шле pause MQTT-команду на принтер і сповіщає ще раз — уже про паузу. |
    | `pause_and_off` | Як `pause`, а на рівні паузи ще й вимикає прив'язану розумну розетку. Це для unattended overnight, коли краще вирубити живлення, ніж марнувати пластик. |

    Друк — це запуск, про який повідомляє принтер. Його аналіз живе від першого кадру до кінця друку, і через паузу; новий старт — зокрема повторний друк того самого файлу — це вже наступний друк. Після перепідключення BamDude чекає першого справжнього звіту стану принтера й починає аналіз заново; тло принтера лишається.

    Друк, який детекція поставила на паузу, **вдруге на паузу не ставиться** — ні після «Відновити», ні після перепідключення, ні після перемикання детектора чи вимкнення й увімкнення детекції: пауза чи вимкнення живлення стається один раз за друк для Obico і [OctoEverywhere](octoeverywhere.md) разом. Сповіщення після такого перемикання може прийти ще раз. Якщо вимкнути детекцію, обрати інший детектор або прибрати принтер зі списку моніторингу, його аналіз забувається.

    Ухвалена дія виконується сама до кінця: пауза надсилається лише поки друк іде, вимкнення живлення — лише поки друк іде або на паузі, і нічого не робиться, якщо друк тим часом закінчився, принтер перепідключився чи його видалили.

## :material-key-variant: Чому cached-frame URL у whitelist?

`/api/v1/obico/cached-frame/{nonce}` — один з небагатьох ендпоінтів, що **обходить** always-on auth gate — Obico ML-сервер не може відправити bearer-токен для одноразового GET. 32-байтний nonce + 30-секундний TTL — це поверхня безпеки; без nonce — 404. Шлях звільнений тільки в `auth_middleware` whitelist.

Через це адреса, з якої ML API забирає кадри, має відкриватися з ML-хоста. Якщо ти за reverse proxy — або переконайся, що `/api/v1/obico/cached-frame/` не блокується додатковим auth-шаром у nginx, або вкажи в полі **Адреса BamDude для ML API** адресу BamDude в локальній мережі, щоб ML-контейнер ходив повз проксі.

## :material-tune: Tuning чутливості

Стартуй на `medium`. Якщо Obico кричить "failure" на кожен retraction-blob — впади на `low`. Якщо пропускає очевидні детачі — підніми на `high`. Smoothing означає, що окремий кадр-outlier action не тригерне — потрібна стійка confidence над порогом. Чутливість зсуває рівні Low / High (а з ними й рівень паузи); тла вона не змінює — його кожен принтер набирає сам.

Точні пороги — у `backend/app/services/obico_smoothing.py`; за замовчуванням консервативні (щоб не false-trip-нути на reference-датасеті Obico).

## :material-eye: Що бачить Obico

Detection panel під **Налаштування → Виявлення збоїв** розбита на Status card і стрічку Recent detections:

**Status card**

- Прапор **Детекція активна** (зелений / червоний) — зелений лише коли детектором обрано Obico, задано ML URL, процес камери працює і цикл запущено. Той самий стан фарбує крапку на вкладці **Виявлення збоїв**.
- **Пороги Low / High** після sensitivity-scaling (щоб sanity-чекнути, що Low / Medium / High реально підкрутили цифри) і **Рівень паузи** — 1,75 × High, оцінка, на якій спрацьовує дія-пауза.
- На кожен поточно-друкуючий моніторений принтер:
    - Жива класифікація — `safe` / `warning` (рівень сповіщення) / `failure` (рівень паузи)
    - Оцінка (згладжене значення мінус тло принтера — саме це число порівнюється з порогами; нижче нуля не показується)
    - Скільки кадрів побачено в цьому друці (видно warmup-countdown)

**Недавні сигнали** — останні події в пам'яті процесу: дата/час, принтер, класифікація й оцінка. Рестарт BamDude очищує цей список. Кадр доступний лише після успішного збереження; новіша картинка з камери його не підміняє.

### Збережені кадри детекцій

Увімкніть **Зберігати кадри детекцій**, щоб лишати докази локально. Це окремий перемикач, **типово вимкнений**. Вкладка **Збережені кадри** переживає рестарт, а **Переглянути детекцію** відкриває саме оригінальний JPEG, переданий ML, з рамками та confidence окремих детекцій. Вимкнення запису зберігає наявні докази й не зупиняє детекцію чи її дії. Відновити відсутні кадри старих недавніх сигналів неможливо.

- Записуються `warning`/`failure` навіть без рамок і `safe`, якщо ML повернув детекції. Помилка камери чи ML не є вердиктом про безпечний друк або брак.
- Оцінка — сума/згладжене значення, **не ймовірність**; вона може перевищувати 1. Відсотки біля рамок — confidence конкретних детекцій, не підтвердження фізичного дефекту.
- Рамки показуються **як їх повернув ML-сервер**. Деякі бекенди upstream Obico рахують висоту рамки через ширину кадру; відповідь не визначає бекенд, тож BamDude не вгадує поправку. Оригінальний JPEG і сирі кортежі рамок незмінні. Viewer ігнорує EXIF-поворот, як і ML при декодуванні збережених пікселів.
- Джерело кадру та час надходження в буфер трансляції показуються окремо. **Час зйомки камерою невідомий**: буферний кадр може бути старішим за ML-запит, а надходження не є зйомкою. Назва роботи/контекст спостереження не доводять належність кадру фізичному прогону.
- Межі на ферму: **15 діб, 1 ГБ і 10 000 подій**. При заповненні першими видаляються безпечні події, далі попередження, потім найстаріші збої. Нові safe не витісняють warning/failure. Панель показує фактично найстаріший збережений кадр, а не обіцяє повні 15 діб.
- Резервна копія містить рівно готові оригінали, на які посилається її знімок БД, з перевіркою хешів. Запис під час backup триває. Фізичне видалення захищених файлів відкладається до завершення копіювання; якщо через це сховище заповнене, нові кадри, включно зі збоями, можуть пропускатися. Попередження стосується повноти запису, а не роботи детектора.
- **Очистити збережену історію** потребує підтвердження і `settings:update`; архіви та завдання не видаляються. Наявні backup зберігають свої копії. Видалення принтера прибирає й його історію. API-ключі не можуть змінювати цей перемикач чи очищувати історію. Метадані потребують `printers:read`, кадри/деталі — ще й `camera:view`; права власника ключа та список дозволених принтерів діють далі.

Кадри містять зображення камери й входять до звичайних backup: відповідно обмежуйте доступ і зберігання копій. Відсутній, прострочений або пошкоджений оригінал показується як недоступний. Перегляд історії не запускає новий захват і не надсилає команд принтеру.

### Бейдж AI на картках принтерів

Щоб бачити, як детекція веде друк, не треба сидіти на цій сторінці. Кожна картка на сторінці **Printers** несе бейдж **AI** поряд з іншими бейджами здоров'я — сірий, поки нічого не спостерігається, далі зелений / бурштиновий / червоний у міру класифікації друку. Він показує обраний детектор, хоч який. Тултип несе поточну оцінку; клік повертає сюди, до повного статусу й історії.

Принтер, якого детекція **не** спостерігає, не показує бейджа взагалі, а не такий, що натякає на покриття.

Бейдж ніколи не каже, що друк спостерігається, коли це не так. Поки друк під наглядом чекає на перший результат, він пише **AI запускається** (сірий). Коли остання перевірка не дала результату — ML-сервер відхилив токен, був недоступний, камера не дала кадру або не задано адресу, з якої ML API забирає кадри, — він пише **AI не перевіряє** (бурштиновий), а тултип називає причину для цього принтера (причину бачать користувачі з доступом до налаштувань; решта бачить, що друк не перевіряється). Без результату оцінка не показується. Поки Obico взагалі не може перевіряти — процес камери не працює або принтер відключено, — бейдж пише **AI не стежить**. Вердикт показано лише тоді, коли друк іде або на паузі: щойно друк закінчився чи принтер відключився, бейдж одразу його прибирає. Список активних друків на цій сторінці показує те саме. **Перевірити** перевіряє значення з форми, не зберігаючи їх.

!!! info "Бейджу не потрібне право на налаштування"
    Його бачить кожен, хто бачить принтери. Він свідомо не несе жодної
    конфігурації — адреса ML-сервера лишається за `settings:read`.
    Для збереженої історії діють окремі права принтера/камери, описані вище.

## :material-alert-circle: Вимоги і підводні камені

- **Двостороння reachability.** BamDude має дістати ML API на `http://<obico-host>:3333/p/`, **і** ML-контейнер має дістати BamDude на `<адреса>/api/v1/obico/cached-frame/{nonce}`. Цю адресу впиши в поле **Адреса BamDude для ML API**: якщо вони в одній Docker-мережі — ім’я сервісу BamDude-контейнера; на різних хостах — LAN IP. `localhost` працює лише коли обидва запущені прямо на одному хості — усередині контейнера це сам контейнер.
- **Адреса для ML API обов'язкова.** Якщо поле **Адреса BamDude для ML API** порожнє і не задано **Налаштування → Мережа → Зовнішній URL**, BamDude нема чого віддати ML API: друки під наглядом не перевіряються, а бейдж пише **AI не перевіряє**. Досить будь-якої з двох адрес.
- **Public URL caveat при reverse-proxy auth.** Cached-frame route обходить always-on auth gate BamDude (ML-контейнер не може віддати bearer для одноразового GET), тож переконайся що твій nginx / Caddy / Traefik не накладає **свій** auth-шар на `/api/v1/obico/cached-frame/`. Власна security-поверхня route — 32-байтний випадковий nonce + 30-секундний TTL — без nonce 404.
- **Calibration-друки скіпаються.** Detection loop крутиться лише поки друк у `RUNNING` стані, тож calibration / first-layer фаза не класифікується — Bambu-калібрації створюють надто багато форм, що ще не є реальними фейлами.
- **Перші 30 кадрів ігноруються.** Навіть всередині `RUNNING`, 30-frame warmup означає, що перші ~5 хвилин кожного друку навмисно тихі — даємо EWM stabilise до того, як щось тригерити.
- **Один раз за друк на кожному рівні.** Сповіщення надсилається один раз за друк, і пауза стається один раз за друк — для обох детекторів разом; подальші оцінки в тому ж друці нічого не запускають повторно. Це навмисно — не хочемо п'ять "pause"-команд одна на одну, коли spaghetti monster уже очевидний, а друк, який ти відновив після паузи від детекції, вдруге на паузу не стане. Аналіз тримається через паузи, після перепідключення починається заново і зникає, коли друк закінчується; наступний друк — зокрема повторний друк того самого файлу — починається з чистого аркуша. Повторюється лише нагадування: про збій, підозра на який тримається через три години після останнього сповіщення, повідомляється знову. Нагадування ніколи не ставить принтер на паузу.
- **Тло живе в пам'яті.** Тло кожного принтера і стан кожного друку на диск не пишуться. Після рестарту BamDude тло набирається заново, а друк, що вже йде, вважається новим.
- **Камера одного принтера не зупиняє решту.** Принтер, з камери якого не вдалося взяти кадр, показує **AI не перевіряє** зі своєю причиною; інші принтери під наглядом перевіряються як завжди.
- **Камера має бути доступною.** Detection loop фетчить кадри з локальної камери принтера так само, як головний UI BamDude. Якщо camera-сторінка в UI не показує стрім — Obico теж нічого не отримає.
- **Disk / RAM.** ~4 GB RAM на Obico-хості. CPU масштабується кількістю моніторених принтерів × частотою polling-у. 5-секундний інтервал на 8 принтерів — приблизно 1.6 кадрів/сек, на більшості заліза без проблем.

## :material-help-circle: Усунення несправностей

**`No address for the ML API to fetch snapshots from`**
: Заповни поле **Адреса BamDude для ML API** в **Налаштування → Виявлення збоїв** (і натисни **Зберегти підключення**) або задай зовнішній URL у **Налаштування → Мережа**. У будь-якому разі це має бути hostname або IP, що відкривається зсередини Obico-контейнера. Перевір `curl`-ом цієї адреси з shell-а в Obico-контейнері.

**ML API здоровий, але жодна перевірка не може забрати кадр**
: ML-контейнер не дістається до BamDude за адресою, яку йому дали, — зазвичай зовнішній URL є публічним ім’ям за логіном reverse proxy або ім’ям, якого контейнер не знає. Вкажи в полі **Адреса BamDude для ML API** адресу BamDude в локальній мережі або ім’я його сервісу Docker, якщо обидва контейнери в одній мережі.

**Test button повертає помилку**
: ML API недосяжне з BamDude. Перевір `docker compose ps ml_api` і спробуй `curl http://<obico-host>:3333/hc/` з BamDude-хоста. Якщо `/hc/` працює а Test ні — двічі перевір, що поле URL вживає ту ж схему (`http://` vs `https://`) і порт.

**Сервіс крутиться але детекцій нема**
: Відсутність записів не доводить безпечний друк. Події з'являються за небезпечного вердикту або повернутих детекцій; для збережених кадрів також потрібні ввімкнений запис і місце. Спершу перевір Status card, що друк справді перевіряється, а тоді налаштовуй чутливість.

**False positives на нормальних друках**
: Опусти sensitivity High → Medium → Low. Також перевір кут камери — якщо в кадрі забагато non-print background (котушки філаменту, AMS, кіт оператора), модель має більше шансів побачити "spaghetti" в випадкових формах. Те, що камера бачить постійно, запам’ятовується як тло принтера й перестає рахуватися, але після рестарту BamDude тло починається спочатку — на перших друках після рестарту його ще мало.

**Сповіщення прийшло, а друк на паузу не став**
: Так працюють два рівні. Сповіщення надсилається на рівні сповіщення, а **Поставити друк на паузу** і **Пауза + вимкнути живлення** чекають сильнішого сигналу — **Рівня паузи**, який видно на картці статусу. Якщо сигнал далі не росте, друк триває, а рішення лишається за тобою.

**Детекція поставила друк на паузу — чи стане він на паузу знову після «Відновити»?**
: Ні. Пауза стається один раз за друк, і стан детекції друку через паузу зберігається. Якщо збій справжній — зупини друк сам.

**Пропущені очевидні фейли**
: Підніми sensitivity. Пам'ятай 30-frame warmup на старті — перші ~5 хв навмисно тихі. Перевір, що камера справді показує build plate (а не лише toolhead).

**`/api/v1/obico/cached-frame/` повертає 401 / 403**
: Твій reverse proxy енфорсить власний auth-шар поверх BamDude. Виріж виняток для цього шляху; BamDude сам whitelist-ить його з always-on gate.

## :material-power-off: Fail-safe поведінка

Якщо API Obico недосяжне або повертає non-2xx:

- Помилка логується на `WARNING`, не `ERROR` (без спам-stack-trace-ів).
- Detection loop продовжує — transient outage не вимикає детекцію назавжди.
- Жодна несправжня "failure"-action не фірить з пропущеної класифікації.

Якщо посеред друку обрати інший детектор або **Вимкнено**, Obico зупиняється до свого наступного кадру камери чи виклику ML; друк триває без перерви, а вже ухвалена дія виконується до кінця. Усе, що детекція знала про поточні друки, забувається, тож після повторного вибору Obico кожен із них починається з чистого аркуша — без другої паузи для друку, який уже ставився на паузу.
