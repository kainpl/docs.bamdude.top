# Калібровка філаменту

BamDude має **вбудований майстер калібровки філаменту**, який тюнить параметри друку на філамент — pressure-advance K, flow ratio, ліміти швидкості й температури — прямо всередині BamDude. Більше не треба тримати відкритим десктопний Bambu Studio лише заради калібровки: майстер відтворює флоу калібровки Bambu Studio проти твого власного підключеного принтера.

Результат pressure-advance із майстра напряму годує [K-профіль](kprofiles.uk.md) — на тій сторінці описано, як отримане K зберігається, синкається та застосовується per-spool.

---

## :material-gesture-tap-button: Як відкрити майстер

Картка кожного принтера має kebab-меню (⋮) з двома сусідніми пунктами калібровки:

| Пункт меню | Що відкриває |
|---|---|
| **Filament Calibration** | Сам майстер калібровки — обери режим, наріж, надрукуй, збережи результат. |
| **Calibration History** | Модалка зі збереженими в BamDude рядками калібровки поруч із live K-profile таблицею принтера. |

---

## :material-cog-sync: Як він нарізає

Це ключова відмінність від фіксованого тестового друку. Майстер **не** постачає канонічний, заздалегідь нарізаний 3MF і не друкує його наосліп. Для кожного режиму він нарізає геометрію калібрувального scaffold проти **твоїх активних пресетів принтера / процесу / філаменту** через підключений **OrcaSlicer або Bambu Studio sidecar** — точно так, як це робить десктопний майстер калібровки Bambu Studio.

Per-mode preset overrides (wall loops, line width, initial-layer speed, spiral mode тощо) застосовуються перед нарізкою, тож калібрувальний об'єкт поводиться ідентично калібровці Bambu Studio.

Нарізаний `.gcode.3mf` далі FTP-иться на принтер і запускається як **реальний друк через звичайний dispatch-pipeline**. Оскільки він іде тим самим шляхом, що й будь-який job із бібліотеки, plate-change макроси та chamber-light MQTT-екшени спрацьовують так само, як для звичайного друку.

!!! note "Потрібен slicer sidecar"
    Майстру потрібен доступний OrcaSlicer або Bambu Studio sidecar для нарізки. Сконфігуруй його в **Settings** перед запуском калібровки. Без slicer-а майстер не зможе видати придатний до друку 3MF.

## :material-format-list-bulleted-type: Режими калібровки

### Pressure Advance

Три pressure-advance режими, всі **повністю production**:

| Режим | Що друкує |
|---|---|
| **PA Line** | Серія single-perimeter ліній, кожна зі зростаючим K. |
| **PA Pattern** | Сітковий патерн, що показує якість K по 2D-полю. |
| **PA Tower** | Вертикальна вежа з K, що інкрементиться по висоті. |

Усі три проходять повний флоу: нарізка → FTP → друк → save-діалог → K-профіль збережений і прив'язаний до AMS-слота.

### Speed & quality вежі

| Режим | Що друкує |
|---|---|
| **Volumetric Speed Tower** | Spiral-mode вежа, у якої швидкість зовнішньої стінки наростає з висотою. |
| **VFA Tower** | Вежа Vibration Fine Artifacts — теж spiral-mode, швидкість зовнішньої стінки наростає з висотою. |

Обидві **production**. Це print-and-eyeball калібровки: оператор зчитує висоту фейлу оком, далі користується калькулятором фінального кроку (див. нижче).

### У розробці

**Temperature Tower**, **Retraction Tower**, **Flow Rate** та **Auto** (lidar-driven) калібровка викочуються режим-за-режимом. Поки кожен не приземлиться, він показаний сірим у майстрі.

## :material-state-machine: Життєвий цикл режиму

Кожен режим перебуває в одному з трьох станів. Саме так BamDude безпечно викочує режим калібровки — режими градуюють від `disabled` через `verification` до `production`.

| Стан | У майстрі | Значення |
|---|---|---|
| `disabled` | Сірий, не обирається | Ще не в цьому білді. |
| `verification` | Обирається, з кнопкою **Download sliced 3MF** | Перехідний sign-off стан. Оператор може завантажити нарізаний майстром вивід і порівняти його з десктопним Bambu Studio, перш ніж режиму довірять керувати реальним друком. |
| `production` | Повний флоу майстра | Нарізка → FTP → друк → save. Режиму довіряють. |

## :material-content-save-check: Крок збереження / завершення

Як завершується калібровка, залежить від родини режиму.

### Pressure Advance режими

Pressure-advance режими завершуються **save-діалогом**:

- **PA Line / PA Pattern** — оператор зчитує K-мітку, надруковану біля найчистішої лінії чи колонки, і вводить її напряму.
- **PA Tower** — оператор вимірює висоту (мм), де кути найгостріші, і BamDude обчислює K:

    ```
    K = start + step × height_mm
    ```

Результат записується в рядок `filament_calibration`, пушиться в 16-слотову K-profile історію принтера через MQTT і прив'язується до AMS-слота — тож наступні друки автоматично його використовують.

### Tower режими (VFA, Volumetric Speed)

Tower режими — print-and-eyeball. Результат — це **slicer-side налаштування**, без runtime-ручки на принтері. Крок завершення дає **калькулятор**: введи виміряну висоту фейлу (мм), і BamDude застосує per-mode формулу, показавши результат inline.

| Режим | Формула | Одиниця |
|---|---|---|
| **Volumetric Speed Tower** | `result = start + height × step` | mm³/s |
| **VFA Tower** | `result = start + ⌊height / 5⌋ × step` | mm/s |

VFA бандить швидкість кожні 5 мм — звідси цілочисельне ділення.

Натискання **Save result** записує значення в історію калібровки як фермовий запис — "цей філамент, на цьому принтері + соплі, скалібровано до X".

!!! note "Tower-результат — інертний запис"
    На відміну від pressure-advance результату, tower-результат **не** застосовується автоматично нікуди — це slicer-side налаштування без printer-side ручки, яку можна було б запушити. Збережений рядок — це запис для довідки. Скопіюй значення у filament-профіль свого slicer-а власноруч.

## :material-fingerprint: Ідентичність результату

Кожен результат калібровки ключується по **5-tuple**:

`(принтер, філамент, діаметр сопла, nozzle volume type, екструдер)`

Ідентичність — **per-printer-instance**: два ідентичні принтери на фермі можуть нести незалежні значення калібровки для того ж філаменту. Майстер ніколи не припускає, що калібровка філаменту на одному принтері покриває решту.

---

## :material-link-variant: Auto-bind на старті друку

Активна pressure-advance калібровка **auto-binds на кожному старті друку**. BamDude пере-матчить live cali-індекс принтера по стабільній 5-tuple ідентичності щоразу, коли друк починається.

Це означає, що реордери AMS-слотів і RFID re-tap не можуть тихо відкотити на невірне K — навіть якщо індекс слота зсунувся, правильна калібровка пере-прив'язується зі збереженої в BamDude ідентичності перед запуском друку.

---

## :material-history: Модалка Calibration History

Kebab-пункт **Calibration History** відкриває модалку, що показує збережені в BamDude рядки калібровки пліч-о-пліч із live 16-слотовою K-profile таблицею принтера.

На кожен рядок можна:

- **Set active** — зробити цю калібровку прив'язаною для свого слота.
- **Delete** — видалити збережений рядок.
- **Refresh from printer** — пере-прочитати live cali-індекс принтера для цього рядка.

Tower-результати теж тут, показані з одиницею, похідною від режиму (VFA в mm/s, Volumetric Speed в mm³/s), тож історія читається коректно незалежно від родини режиму.

---

## :material-printer-3d: H2D двоекструдерний

На H2D / H2D Pro майстер показує **вкладки на екструдер**. Кожен екструдер калібрується незалежно — свої режими, свої результати, своя 5-tuple ідентичність (екструдер — частина ключа). Калібровка лівого екструдера ніколи не чіпає правий.

## :material-alert: Траблшутинг

**Режим сірий**

- Режим у стані `disabled` у цьому білді — він ще не вийшов. Temperature Tower, Retraction Tower, Flow Rate та Auto калібровка викочуються режим-за-режимом; перевір changelog на білд, що вмикає потрібний.

**Калібрувальний друк не задиспатчився**

- Майстер нарізає через slicer sidecar. Підтверди, що OrcaSlicer або Bambu Studio sidecar сконфігурований і доступний у **Settings**.
- Перевір, що принтер онлайн із зеленим статус-діодом і не в середині друку — калібрувальний job диспатчиться через звичайний pipeline і стає в чергу за активним друком.

**Збережене K ніби не застосовується на наступному друку**

- Pressure-advance результати auto-bind-яться на старті друку через 5-tuple ідентичність. Глянь **Calibration History**, чи рядок **set active** для слота.
- Перевір, що діаметр сопла і nozzle volume type збігаються — результат ключується по обох, тож зміна сопла дає окрему, незматчену ідентичність, поки не перекалібруєш.

**Tower-результат не дав ефекту**

- Очікувано — tower-результат (VFA, Volumetric Speed) це інертний запис, не printer-side налаштування. Скопіюй значення у filament-профіль свого slicer-а власноруч.
