# Зібрати проєкт

Виберіть моделі у [Файловому менеджері](file-manager.md) — BamDude розкладе їх на столах і збереже **проєктні файли 3MF** поруч із вихідними: по одному на кожен названий принтер, уже з профілями принтера, процесу й філаменту всередині. Такий файл відкривається в Bambu Studio чи OrcaSlicer готовим до нарізки.

Розкладка щільніша за авторозкладку слайсера: дрібні деталі кладуться **в отвори й порожнини більших**. Рамка з кришкою всередині займає на столі одне місце, а не два.

## :material-cursor-default-click: Як почати

1. Виберіть у бібліотеці один чи кілька файлів **STL**, **OBJ** або **STEP / STP**.
2. Натисніть **Зібрати проєкт** у панелі вибору.

Якщо серед вибраного є файл іншого типу (нарізаний 3MF, G-code), кнопка неактивна, а її підказка називає файли, які не підходять — діалог ніколи не відкривається з мовчки урізаним списком.

Потрібне право завантажувати в бібліотеку (`library:upload`).

## :material-format-list-numbered: Деталі

Кожен вибраний файл — рядок:

| Поле | Що робить |
|---|---|
| **Копій** | Скільки штук цієї деталі розмістити. До 2000 копій в одному збиранні — разом по всіх деталях. |
| **Заповнити стіл** | Замість числа: стільки, скільки вміщає один стіл. Така деталь отримує окремий стіл. |
| **Орієнтація** | *Як у файлі*, чверть оберту навколо X чи Y або *Догори дном*. Після повороту деталь ставиться на стіл найнижчою точкою. |

## :material-printer-3d: Принтери

Кожен рядок принтера — три профілі: **Принтер**, **Процес**, **Філамент**. Списки ті самі, що й у діалозі нарізки: ваші локальні профілі, Orca Cloud, Bambu Cloud і стандартні. **Додати принтер** додає ще рядок, до 8.

Кожен рядок дає **власний проєкт**, розкладений під зону друку цього принтера і збережений із цими профілями. Збирання одразу для X1 Carbon і A1 mini — це два файли з двома різними розкладками.

- **Принтери з двома соплами** (H2D, H2C та подібні) показують вибір **Друкувати** — *Лівим соплом* чи *Правим соплом*. Деталі тримаються в межах досяжності вибраного сопла, і в проєкті це сопло закріплено.
- Зони, де принтер не друкує, лишаються вільними.
- Профіль принтера, який не описує зону друку — картка моделі замість профілю машини, або принтер, що відлічує координати від центру столу, — показує попередження у своєму рядку, і кнопка **Зібрати** неактивна, доки не вибрано інший.

Сайдкар слайсера для збирання не потрібен. Профілі читає сам BamDude; стандартні завантажуються з репозиторію профілів OrcaSlicer при першому використанні й зберігаються, тож ферма без інтернету працює з тим, що вже має.

## :material-tune: Розкладка

| Параметр | Типово | Значення |
|---|---|---|
| **Проміжок між деталями, мм** | 2 | Від 0 до 50. |
| **Поворот деталей на столі** | Кроком 90° | *Не повертати*, *Лише на 180°*, кроком 90° чи 45°. Дрібніший крок пакує щільніше і триває довше. |
| **Центрувати групу на столі** | увімкнено | Якщо вимкнути, деталі лишаються там, де їх поклало пакування, — від кута. |
| **Окремий файл на кожен стіл** | вимкнено | Вимкнено: один багатостоловий проєкт. Увімкнено: файл на кожен стіл. |
| **Назва результату** | за першим файлом | До назви додається модель принтера. Якщо таке ім'я в теці вже є, додається номер — наявний файл ніколи не перезаписується. |

## :material-progress-clock: Поки триває

Збирання — фонова задача у власному робочому процесі; діалог можна закрити й працювати далі — трекер задач у кутку стежить за нею і скаже, коли вона завершиться.

Діалог показує, де зараз задача: чекає на інше збирання, перетворює файли STEP, розміщує деталі для кожного принтера, зберігає. **Зупинити** завершує її й нічого не зберігає. Коли задача вже почала зберігати файли, зупинити її не можна — зупинка в цю мить лишила б файли за повідомленням «нічого не збережено».

Одночасно виконується одне збирання; наступні чекають у черзі.

## :material-check-circle-outline: Результат

Підсумок перелічує кожен принтер із **картинкою кожного стола**, показує, скільки штук якої деталі куди потрапило, і дає посилання на кожен збережений файл. Файли з'являються в теці першої вибраної моделі.

- Деталь, яка не вміщається на жоден стіл принтера — завелика для його зони чи вища, ніж він друкує, — провалює **лише цей принтер** і названа разом із причиною. Решта принтерів отримують свої проєкти.
- Рядок принтера, профіль якого не вдалося прочитати, теж падає сам.
- Якщо ви закрили діалог, а для одного з принтерів щось не вдалося, трекер попросить підтвердити це, а не покаже зелене «готово».

## :material-cube-scan: Моделі STEP

Файл STEP чи STP перед пакуванням перетворюється на сервері — з точністю, з якою STEP імпортує Bambu Studio, тож круглі поверхні лишаються круглими. Для цього потрібен той самий необов'язковий компонент, що й для [мініатюр STEP](file-manager.md#step-thumbnails): Docker-образ і інсталятор Windows мають його, у нативній установці його вибирають під час встановлення. Без нього вибір зі STEP-файлом відхиляється з поясненням, а збирання STL / OBJ працює як звичайно.

Перетворення навмисно суворе. Модель береться тільки цілою: файл, що посилається на геометрію в іншому файлі, поверхня, яка не є замкненим тілом, дзеркальна збірка, яку ядро не може відтворити, чи модель, надто деталізована для меж, зупиняє збирання і **називає деталь** — розкладки без однієї з потрібних вам деталей не буває. Файл STEP може мати до 64 МБ.

## :material-refresh: Перерозкладка

Зібраний тут проєкт пам'ятає, з чого його зроблено: деталі, кількості, профілі й параметри розкладки. У його меню є **Перерозкласти** — відкривається той самий діалог із цими значеннями: змініть кількість, проміжок чи поворот і розкладіть знову. Моделі беруться з самого проєкту, тож вихідні STL / STEP можуть бути вже видалені.

- **Перемістити попередній файл у кошик** (типово увімкнено) замінює старий проєкт. Для цього потрібне право видаляти цей файл; файл, який використовує задача друку, лишається. У файла з підключеної зовнішньої теки кошика немає — він прибирається з бібліотеки й лишається на своєму ресурсі, і підсумок каже це.
- Для проєкту, збереженого файлом на кожен стіл, перерозкладка працює з усім набором і потребує всіх його файлів у бібліотеці.
- Нарізана копія проєкту цих значень не містить, тому **Перерозкласти** в неї немає.

## :material-ruler: Межі

| | |
|---|---|
| Файлів в одному збиранні | 100 |
| Копій загалом | 2000 |
| Принтерів | 8 |
| Вихідні файли разом | 200 МБ |
| Один файл STEP | 64 МБ |
| Час на одне збирання | 15 хвилин |
| Збирань у черзі | 16 |

Лише проєкти з одним філаментом: кожна деталь зберігається з одним профілем філаменту свого рядка принтера.

## :material-help-circle-outline: Якщо щось не вдалося

| Повідомлення | Що робити |
|---|---|
| *Деякі деталі не підходять цьому принтеру* | Названа деталь більша чи вища за зону принтера. Поверніть її через **Орієнтацію** або приберіть цей принтер. |
| *Файл STEP не вдалося перетворити на модель для друку* | Відкрийте його у своїй CAD-програмі чи слайсері та експортуйте як STL або як STEP з усією геометрією всередині. |
| *Модель STEP завелика або надто деталізована для перетворення* | Експортуйте її як STL із потрібною вам точністю. |
| *На цьому сервері не встановлено підтримку STEP* | Встановіть компонент мініатюр STEP — див. [Встановлення → STEP previews](../getting-started/installation.md#step-previews). |
| *Вихідний файл змінився під час збирання — нічого не збережено* | Файл замінили під час задачі. Почніть знову. |
| *Збирання тривало надто довго і його зупинено* | Менше копій, грубіший крок повороту або менше принтерів за раз. |

Стан робочого процесу збирання разом з іншими повідомляє `GET /api/v1/system/info` (`assembly_worker`); він входить і до пакета підтримки.
