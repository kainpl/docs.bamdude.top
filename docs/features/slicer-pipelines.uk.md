# Налаштування слайсингу

**Налаштування слайсингу** — це збережений набір: чотири вибори, які ти зазвичай робиш руками в діалозі Slice — printer preset, process preset, filament preset на кожен слот AMS і тип столу. Зберігаєш один раз, а наступного разу обираєш зі списку замість того, щоб вибирати всі чотири заново.

Це вся функція. Це шорткат для повторюваної роботи, а не диспетчер: слайсиш і ставиш у чергу ти так само, як завжди.

!!! info "Треба надрукувати багато копій? Це робота авто-черги"
    Збережені набори не задають кількість і не обирають принтери. Щоб надрукувати партію, користуйся [Auto-Queue Routing](auto-queue.md) — вказуєш кількість і модель принтера, а BamDude розкидає копії по всіх відповідних принтерах, підбираючи тип і колір філаменту.

    У ранніх бетах (`0.4.7b2`–`0.4.7b5`) це називалось «Slicer Pipelines» і вміло ще й розсилати копії — тобто на одну задачу було два способи. Ту половину прибрано; авто-черга робить це і робила завжди.

---

## :material-cog-outline: Що саме зберігається

| Поле | Що це |
|---|---|
| **Назва / опис** | Твоя мітка для налаштування. |
| **Printer preset** | Профіль принтера, проти якого слайсити (джерело + id — локальний, Orca Cloud, Bambu Cloud або стандартний). |
| **Process preset** | Профіль процесу / якості. |
| **Filament presets** | По одному пресету **на кожен слот AMS**, щоб мультиматеріальне завдання зіставило кожен слот із потрібним філаментом. |
| **Тип столу** | Тип пластини, під яку слайсити. |

---

## :material-play-circle-outline: Як зберегти й використати

**Зберегти** — прямо з діалогу Slice кнопкою **Зберегти ці налаштування**: вона захоплює пресети, які ти вже там обрав.

**Використати** — у тому ж діалозі: обираєш набір у списку **Застосувати збережені**, і всі чотири вибори підставляються одразу. Далі слайсиш як завжди і ставиш результат у чергу звичним шляхом — [напряму на принтер](print-queue.md) або [в авто-чергу](auto-queue.md).

### Якщо збережений пресет видалили

Пресети змінюються. Якщо збережений набір посилається на той, якого вже немає, BamDude **не підставляє** цей слот — залишає те, що діалог підібрав автоматично, і називає проблемні слоти в попередженні над списком.

Це важливо: мовчки підставити мертве посилання означало б порожній випадний список при діалозі, який виглядає готовим до слайсу, — і ти б відправив завдання з пресетом, якого не обирав. Перевибери позначений слот вручну, і попередження зникне.

## :material-shield-key: Права

| Право | Дає |
|---|---|
| `pipelines:read` | Бачити збережені набори і підставляти їх у діалозі Slice. |
| `pipelines:write` | Створювати, редагувати й видаляти збережені набори. |

**Administrators** та **Operators** мають обидва; **Viewers** — лише читання.

| Ендпоінт | Метод | Право |
|---|---|---|
| `/slicer-pipelines/` | GET / POST | read / write |
| `/slicer-pipelines/{id}` | GET / PUT / DELETE | read / write / write |

[API-ключ](api-keys.md) із read-скоупом може отримати список збережених наборів; створення й редагування — дія оператора.

!!! note "В API це досі `pipelines`"
    Ендпоінти й права лишились із назвою `pipelines` — фіча прийшла з апстрім-Bambuddy під нею, і перейменування API зламало б тих, хто вже його викликає. Змінилися лише написи в інтерфейсі.

Керувати, перейменовувати й видаляти збережені набори — у **Settings → Друк**.
