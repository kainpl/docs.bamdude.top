# Налаштування слайсингу

**Налаштування слайсингу** — це збережений набір: чотири вибори, які ти зазвичай робиш руками в діалозі Slice — printer preset, process preset, filament preset на кожен слот AMS і тип столу. Зберігаєш один раз, а наступного разу обираєш зі списку замість того, щоб вибирати всі чотири заново.

Це вся функція. Це шорткат для повторюваної роботи, а не диспетчер: слайсиш і ставиш у чергу ти так само, як завжди.

!!! info "Треба надрукувати багато копій? Це робота авто-черги"
    Збережені набори не задають кількість і не обирають принтери. Щоб надрукувати партію, користуйся [Auto-Queue Routing](auto-queue.md) — вказуєш кількість і модель принтера, а BamDude розкидає копії по всіх відповідних принтерах, підбираючи тип і колір філаменту.
---

## :material-cog-outline: Що саме зберігається

| Поле | Що це |
|---|---|
| **Назва / опис** | Твоя мітка для налаштування. |
| **Printer preset** | Профіль принтера, проти якого слайсити (джерело + id — локальний, Orca Cloud, Bambu Cloud або стандартний). |
| **Process preset** | Профіль процесу / якості. |
| **Filament presets** | По одному пресету **на кожен слот AMS**, щоб мультиматеріальне завдання зіставило кожен слот із потрібним філаментом. |
| **Тип столу** | Тип пластини, під яку слайсити, — одна з плит, які пропонує [діалог нарізки](slicer-api.md#bed-plate). Назва поза цим списком відхиляється під час збереження налаштувань. |

## :material-play-circle-outline: Як зберегти й використати

Кнопка **Зберегти ці налаштування** в діалозі нарізки або в рядку принтера в **Зібрати проєкт** зберігає вибрані пресети й тип столу.

**Використати** — у тому ж діалозі: обираєш набір у списку **Застосувати збережені**, і всі чотири вибори підставляються одразу. Далі слайсиш як завжди і ставиш результат у чергу звичним шляхом — [напряму на принтер](print-queue.md) або [в авто-чергу](auto-queue.md).

Рядок під списком каже, що саме набір змінив, — *«Застосовано «назва». Змінено: Профіль принтера, Тип столу»* — або що нічого не змінилося, бо саме це вже було вибрано. Профілі процесу й філаменту, які підставив набір, рахуються як [твій власний вибір](slicer-api.md#explicit-choice): пізніші автоматичні вибори діалогу їх не замінюють. Пресети філаменту йдуть **за слотами**: набір, у якому філаментів менше, ніж слотів у файлі, заповнює перші, а решта лишаються як були.

### Де можна застосувати збережені налаштування

Спільний список **Збережені налаштування** є в нарізці, калібруванні філаменту й збиранні проєкту. У кожному місці набір заповнює його поля.

| Місце | Заповнює |
|---|---|
| Діалог Slice | Принтер, процес, кожен слот філаменту, який називає набір, тип столу. |
| [Калібрування філаменту](filament-calibration.md) — сторінка, що друкує | Принтер, процес і тип столу. У списку лише набори, чий профіль принтера пасує цьому принтеру та вибраному соплу; філамент лишається філаментом вибраного слота. |
| [Калібрування філаменту](filament-calibration.md) — сторінка завантаження | Принтер, процес, тип столу й перший філамент. |
| [Збирання проєкту](assemble-project.md) | Принтер, процес, перший філамент і тип столу в рядку, чиїм списком ти скористався. |

### Якщо збережений пресет видалили

Пресети змінюються. Якщо збережений набір посилається на пресет, якого вже немає або який належить до хмари іншого слайсера, BamDude **не підставляє** цей слот — поле не заповнюється з набору — воно лишає те, що має, а автоматичний вибір іде за принтером, якого обрав набір, — і проблемні поля названо в попередженні під списком.

Це важливо: мовчки підставити мертве посилання означало б порожній випадний список при діалозі, який виглядає готовим до слайсу, — і ти б відправив завдання з пресетом, якого не обирав. Перевибери позначений слот вручну, і попередження зникне.

### Якщо збережений тип столу не застосовано

Збережений тип столу застосовується лише тоді, коли слайсер цього завдання його має. Інакше діалог лишає тип столу як є і каже про це під полем **Тип столу**:

- **Textured Cool Plate з Bambu Studio** — ця плита є лише в OrcaSlicer: *«У збережених налаштуваннях указано Textured Cool Plate — цей стіл є лише в OrcaSlicer. Тип столу лишився без змін.»* Перемкни завдання на OrcaSlicer і застосуй налаштування ще раз.
- **Назва плити, якої немає у списку** — можливо лише в наборі, збереженому до того, як назви почали перевірятися: *«У збережених налаштуваннях указано стіл, якого тут немає («…»). Тип столу лишився без змін.»* Обери плиту і збережи набір заново.

## :material-shield-key: Права

| Право | Дає |
|---|---|
| `pipelines:read` | Бачити збережені набори й застосовувати їх у діалозі Slice, калібруванні філаменту та збиранні проєкту. Без цього права списку немає. |
| `pipelines:write` | Створювати, редагувати й видаляти збережені набори. |

**Administrators** та **Operators** мають обидва; **Viewers** — лише читання.

| Ендпоінт | Метод | Право |
|---|---|---|
| `/slicer-pipelines/` | GET / POST | read / write |
| `/slicer-pipelines/{id}` | GET / PUT / DELETE | read / write / write |

[API-ключ](api-keys.md) із read-скоупом може отримати список збережених наборів; створення й редагування — дія оператора.

!!! note "В API це досі `pipelines`"
    Ендпоінти й права лишились із назвою `pipelines` — фіча прийшла з апстрім-Bambuddy під нею, і перейменування API зламало б тих, хто вже його викликає. Змінилися лише написи в інтерфейсі.

Керувати, перейменовувати й видаляти збережені набори — у **Settings → Слайсинг**.
