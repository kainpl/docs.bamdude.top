# Інвентар котушок

BamDude має власний інвентар фізичних котушок — окремий (і комплементарний) до [інтеграції зі Spoolman](spoolman.uk.md). Внутрішній інвентар трекає кожну котушку з виробником, кольором, вагою, ціною, датою покупки і lot-номером; BamDude автоматично віднімає витрату з ваги на кожен друк, алертить, коли котушка падає нижче порогу, і пам'ятає, в якому слоті AMS на якому принтері яка котушка.

Користуйся цією сторінкою, якщо хочеш трекати пластик без піднімання окремого Spoolman-сервісу. Якщо вже використовуєш Spoolman — див. [Spoolman](spoolman.uk.md) для шару двосторонньої синхронізації.

## :material-view-dashboard: Огляд інвентаря

Сторінка «Філамент» відкривається з п'ятьма підсумковими картками над списком котушок; клік по картці веде до відфільтрованого списку:

| Картка | Що показує |
|---|---|
| **Загальний інвентар** | Кількість котушок + сумарна вага в кг по всьому інвентарю. |
| **Загально використано** | Грами, витрачені з усіх котушок від початку відстеження — або, для котушки зі скинутим лічильником, від того [скидання](#reset-counter). Доповнює [Статистику](stats.uk.md), де є розбивка за періодами. |
| **За матеріалом** | Кільцева діаграма за типом філаменту (PLA, PETG, ABS, …). Клік на сегмент фільтрує список котушок до цього матеріалу. |
| **У принтері** | Скільки котушок зараз завантажено в усіх блоках AMS усіх принтерів (сума призначень слотів). |
| **Мало запасу** | Кількість котушок нижче або глобального `low_stock_threshold`, або власного порога котушки (діє суворіший із двох). Клік фільтрує список до котушок із малим запасом — пов'язано зі сповіщенням `filament_low`. |

### Фільтри, пошук, режими перегляду

Тулбар над списком комбінує free-form search-box з chip-стрічками і view-mode toggle-ами:

- **Поле пошуку** — матчить **ім'я котушки, зібране твоїм шаблоном відображення**, а не лише сирі колонки за ним, тож знайти можна все, що показано у списку: із шаблоном `{brand}/{material}` запит `LU/PET` спрацює. Бренд, матеріал, колір, підтип, нотатка і slicer-preset матчаться завжди, як і **id** та **номер лота** котушки — ці два незалежно від шаблону, бо це числа, написані на самій котушці. [Номер матеріалу](#material-number) матчиться теж. Кожен токен має щось зматчити, тож `SUN Bl` знаходить SUNLU Black. Токен у вигляді `#123` знаходить рівно котушку з цим номером і жодну іншу; голе `123` лишається звичайним пошуком за підрядком. Натисни `/` будь-де на сторінці, щоб сфокусуватися.
- **Список «Матеріал»** — вибір одного значення.
- **Список «Номер матеріалу»** — вибір одного значення, з пунктом **Без номера матеріалу** для котушок, які його не мають. З'являється, щойно хоча б одна котушка має [номер матеріалу](#material-number).
- **Список «Колір»** — вибір одного значення. Опції — кольори, які реально є в наявності (з твоїх існуючих, не архівованих котушок), згруповані за resolved color-catalog name, тож два близьких hex, що обидва читаються як "Cobalt Blue", фільтруються разом незалежно від бренду. Дропдаун зʼявляється, лише коли хоча б одна котушка в наявності має резолвабельний колір.
- **Чіп місця зберігання** — звужує список котушок до однієї локації зберігання з [керованого каталогу локацій](#storage-locations-catalog), тож можна бачити лише котушки з однієї коробки / полиці / dry-box.
- **Вкладки статусу** — Активні / Архівовані / Усі, плюс швидкі фільтри Використані / Нові, плюс фільтр запасу Усі / Запас (без профілю слайсера) / Налаштовано (з профілем слайсера).
- **Список «Бренд»** — вибір одного значення.
- **Режими перегляду** — **Таблиця** (дані, сортовні колонки), **Картки** (кольорові зразки) або **[Історія](#history)** (усі списання ферми). Поруч стоїть *Прогноз*, якщо є права на нього.
- **Групувати** — перемикач, що візуально згортає однакові котушки в один розгортуваний рядок із лічильником (напр. *5 однакових котушок*). Grouping-key — `manufacturer + material + color name + label weight + subtype`; lot у ключ свідомо **не** входить, тож batch, створений з **авто-нумерацією лотів** (див. нижче), усе одно колапсує в один рядок, і група може охоплювати кілька лотів. Котушка, встановлена в принтер, завжди видна окремо, тож знаєш, яка фізична котушка в якому слоті; надпочата котушка, повернута на полицю, групується зі своїми близнючками, а залишок рядка — точна сума по всіх учасниках. Group-state persist-ить через сесії.

    **Перевірка ваги** зіставляє суму показів ваг із розрахунковою вагою брутто, коли зважено всі котушки групи. Якщо сума вимірів менша за сумарну тару, для групи все одно використовується повне порівняння з вагою брутто. Для групи з неповними вимірами показується риска. Розгорніть групу, щоб побачити показ кожної котушки.

!!! info "Сортування груп"
    Заголовки **ID**, **Лот**, **Придбано**, **Розташування**, **Етикетка**, **Нетто** та **Залишок** сортують і групи, і котушки всередині розгорнутих груп. Групи впорядковуються до пагінації. Вага етикетки й нетто беруться як суми групи, відсоток залишку — як сумарний залишок, поділений на сумарну вагу етикетки. ID, лот, дата придбання й розташування беруться з представника групи — котушки з найменшим ID.

## :material-package-variant: Додавання котушок

**Філамент** у бічному меню відкриває список котушок. **+ Додати котушку** питає:

| Поле | Примітки |
|---|---|
| Бренд / виробник | Вільний рядок, але BamDude автодоповнює з виробників, яких уже бачив. |
| Матеріал | PLA, PETG, ABS, ASA, TPU, PA, PC, … (відповідає списку Bambu, але приймає власні значення). |
| Колір | Вибір hex-кольору — каталог кольорів (нижче) пропонує назви. |
| Вага | Чиста вага в грамах. Котушки Bambu типово 1000 г; картонна серцевина AMS-HT — ~250 г. |
| Діаметр | `1.75` (типово) або `2.85`. Зберігається як є, тож працюють і бренди, відмінні від Bambu. |
| Вартість | Ціна котушки; з неї рахується вартість проєкту / архіву. |
| Дата придбання | Необов'язково; корисно для нагадувань про ротацію запасу. |
| Лот | Необов'язково; щоб зіставляти котушки з однієї партії (у деяких брендів відтінок відрізняється між лотами). |
| Примітка | Що завгодно для пам'яті. |

Котушки належать користувачу, що їх створив. `inventory:create` потрібен, щоб додавати нові; `inventory:read` дає Viewer-у бачити список.

### Копіювати котушку — дублювати наявний рядок

Кожен рядок котушки (картки, таблиця, згруповані рядки) має кнопку **Копіювати котушку** поряд із **Редагувати**. Клік відкриває форму котушки, попередньо заповнену всім із вихідного рядка, крім `weight_used` — він скидається в **0**. Корисно, коли ти щойно купив другу / третю / n-ну котушку наявного філаменту. Заголовок каже **Копіювати котушку** замість «Редагувати котушку», кнопка внизу — **Копіювати котушку** замість «Зберегти». **Швидке додавання (перемикач із полем `Кількість`) доступне і при копіюванні** — тож можна склонувати котушку одразу в цілу партію; кожна копія стартує чистою (витрата = 0, без RFID-тега). Вихідний рядок не чіпається; збереження створює нові котушки, кожна з власним `id`. Форма котушки не залежить від принтера, тож та сама кнопка працює і в режимі Spoolman.

### Масове редагування — змінити багато котушок одразу

Кнопка **Масове редагування** в тулбарі (лише вбудований інвентар) відкриває діалог, де можна змінити поле одразу для кількох котушок. Обери, які котушки редагувати (стартує з усіх відфільтрованих; зніми у лівому списку ті, що чіпати не треба) і **познач поля для застосування**: пресет слайсера, матеріал, бренд, підтип, вага на етикетці, колір, вага порожньої котушки, дата придбання, діаметр, ціна/кг, примітка, категорія, поріг low-stock, додаткові кольори, візуальний ефект, місце зберігання, номер матеріалу, **Востаннє сушено** і **Розблокувати вагу**.

Два з них — дії, а не значення. **Востаннє сушено** записує обраним котушкам сушіння «зараз» або стирає дату (**Очистити дату**) — для партії, висушеної в зовнішній сушарці; див. [Востаннє сушено](#last-dried). **Розблокувати вагу** знімає блокування, яке ставить на котушку введена вручну вага, тож синхронізація ваги з AMS знову може оновлювати обрані котушки; самі ваги лишаються без змін — див. [Вага, введена вручну, блокується](#hand-entered-weight-lock).

Кожне позначене поле префілиться лише коли вибрані котушки вже мають спільне значення (інакше показує *«— різні —»*); **записуються тільки позначені поля**, решта лишається як було, а **використана вага й RFID-tag не чіпаються**. Інпути дзеркалять одиничну форму — preset / ефект / діаметр / порожня котушка / місце зберігання це дропдауни; матеріал / бренд / підтип автокомпліт з усього, що знає система (slicer-пресети + колор-каталог + built-ins, не лише з вибраних); список кольорів — з колор-каталогу, відфільтрований за брендом + матеріалом, що застосовуються, і оновлюється при їх зміні.

### Імпорт / експорт CSV

Дві кнопки в хедері інвентарю переносять цілі списки котушок туди-сюди як CSV — зручно для backup-у інвентарю, редагування в таблиці або bulk-завантаження свіжо-прибулого замовлення.

- **Експорт CSV** завантажує файл із датою в назві, `bamdude_inventory_YYYYMMDD.csv`: один рядок на кожну котушку, що відповідає поточним фільтрам, — а не лише сторінку на екрані.
- **Імпорт CSV** масово додає котушки з CSV. Замість того щоб писати одразу, він спершу показує **таблицю попереднього перегляду**, що позначає кожен рядок як *валідний*, *з помилкою* або *пропущений* — і відмічає рядки, де колір заповнено з каталогу кольорів або де вже існує така сама котушка, — **до того, як щось запишеться**. Клік підтвердження зберігає лише валідні рядки.

CSV-заголовки толерантні до регістру й пробілів, тож колонка з назвою `Label Weight`, `label_weight` чи `LABELWEIGHT` резолвиться однаково. Обов'язковий лише `material`; решта колонок опційні, і до кожного рядка застосовується та сама валідація, що й у ручній формі додавання котушки.

Файл несе також колонки `material_number` і `last_dried_at`; `last_dried_at` — дата/час у форматі ISO. Порожня клітинка `material_number` означає «без номера» — імпортована котушка не успадковує його від свого філаменту.

В останній колонці `__bamdude_text_escapes_v1` експорт котушок указує, які клітинки було захищено як текст. Зберігайте цю колонку під час повторного імпорту з BamDude. Вона дозволяє відрізнити службовий префікс від апострофа, який ви ввели у примітці чи іншому текстовому полі. Попередні CSV-файли імпортуються за своїми правилами екранування.

Імпорт/експорт CSV — **тільки для локального інвентарю**. У **режимі Spoolman** обидві кнопки вимкнені, з підказкою, що вказує на власні CSV-інструменти Spoolman.

### Каталог локацій зберігання {#storage-locations-catalog}

Де котушка фізично лежить — полиця, шухляда чи dry-box — це **керований каталог**, а не вільний текст. Кнопка **Місця** у шапці інвентарю відкриває менеджер каталогу, де ти створюєш, перейменовуєш і видаляєш локації; поле **Місце зберігання** у формі котушки — це список із цього каталогу, з можливістю створити нове місце просто в ньому, тож не треба виходити з форми, щоб додати полицю.

- **Перейменування поширюється** — перейменування локації одним записом оновлює кожну прив'язану до неї котушку, тож назви не розходяться.
- **Видалення захищене** — перш ніж видаляти локацію, перенеси призначені їй котушки й відв'яжи датчики Zigbee чи Home Assistant.
- **Синк зі Spoolman** — у режимі Spoolman каталог імпортує унікальні локації Spoolman, а перейменування каскадиться на per-spool поле `location` у Spoolman (з локальним відкатом, якщо Spoolman відхилить, тож двоє ніколи не розходяться).

Перегляд каталогу потребує `inventory:read`; створення / перейменування / видалення локації потребує `inventory:update`.

Місце зберігання може показувати покази [датчиків Zigbee та Home Assistant](sensors.uk.md). У каталозі кожне джерело показано окремо, з графіком історії. Якщо одну величину вимірюють кілька датчиків, обери основне джерело для компактного показу температури, вологості або заряду — мовчки жодне джерело не обирається. Необов'язкові колонки таблиці та підпис на картці котушки показують покази її місця зберігання. Колонки таблиці сортують увесь інвентар за поточними показами; котушки без доступного показу йдуть останніми. Для налаштування датчиків і перегляду показів потрібні права на датчики.

### Редагування котушки, створеної через швидке додавання, імпорт CSV чи RFID

Ці три шляхи створюють котушку з матеріалом і майже нічим більше — без сім'ї філаменту, без бренду, без підтипу. **Редагування й копіювання такої котушки питають рівно те, що питає сервер: матеріал.** Тож змінити її місце зберігання, ціну чи примітку можна, не заповнюючи нічого іншого.

Сім'я, бренд і підтип лишаються видимими й редагованими, а маленькі позначки `*` з'являються лише там, де поле справді обов'язкове.

!!! info "Списки брендів і матеріалів пропонують усі продукти"
    Каталог кольорів знає лише частину пар бренд/матеріал — Elegoo занесений у
    каталог лише для PLA, хоча **Elegoo ASA** — реальний філамент, який можна купити.

    Тому обидва списки завжди пропонують усе: відомі пари першими під
    **Пропоновані**, решта — під **Усі**. Власні бренд і матеріал котушки завжди
    присутні в її ж списку, навіть якщо про них більше ніхто не чув.

### Котушка посилається на сім'ю філаменту

Форма котушки має один вибір **Сімʼя філаменту** — та сама ідентичність, що в Bambu Studio (`filament_id`), спільна з діалогом слота AMS і редактором K-профілів. Котушка не залежить від принтера за самою конструкцією: варіанти пресетів під окремі принтери — справа *сім'ї*, і вони визначаються під конкретний принтер у момент призначення слота чи нарізання. Вибір сім'ї заповнює матеріал і бренд; власні сім'ї мають бейдж своєї хмари; рядок **Створити нову сімʼю…** відкриває [діалог створення філаменту](filament-families.uk.md#створення-власного-філаменту), не виходячи з форми. Повна модель: [Сім'ї філаментів](filament-families.uk.md).

### Категорія та власний поріг малого запасу котушки

Два додаткові необов'язкові поля у формі котушки точніше керують і фільтрацією, і сповіщеннями:

| Поле | Ефект |
|---|---|
| **Категорія** | Вільний короткий тег — наприклад, `PETG`, `ABS`, `TPU`, `paint`, `experimental`. Сторінка інвентаря над списком малює стрічку чіпів-фільтрів, тож можна показувати «тільки TPU» чи «тільки experimental». Стрічка чіпів з'являється лише коли хоча б одна котушка має категорію — щоб не захаращувати сторінку в перший день. Чіп **Без категорії** фільтрує котушки без категорії. |
| **Поріг низьк. запасу (%)** | Власний поріг котушки замість глобального `low_stock_threshold`. Корисний, коли конкретна котушка потребує ранішого попередження (наприклад, дорогий PA — 50% залишку = час замовляти; дешевий PLA може почекати до 10%). Порожньо = успадковує глобальне значення. |

Обидві колонки видно в таблиці інвентаря, і їх можна редагувати просто в ній.

### Повна форма: вкладка «Філамент»

Форма **+ Додати котушку** має дві вкладки. Перша — «Філамент» — охоплює все, потрібне, щоб ідентифікувати котушку й визначити її сім'ю філаменту.

| Поле | Опис |
|---|---|
| **Сімʼя філаменту** | Пошук і вибір сім'ї (вбудований каталог + твої хмарні/локальні/власні — див. [Сім'ї філаментів](filament-families.uk.md)). Вибір автоматично заповнює *Матеріал* і *Бренд*. |
| **Матеріал** | PLA, PETG, ABS, ASA, TPU, PA, PC, … — приймає власні значення, див. [Власні матеріали](#custom-materials). |
| **Бренд** | Виробник філаменту; автодоповнення з брендів, які вже траплялися. |
| **Підтип** | Basic, Matte, Silk, HF, Metal, CF, … |
| **Вага на етикетці** | Чиста вага, як надруковано на котушці (типово 1000 г; картонна серцевина AMS-HT ~250 г). |
| **Кількість** | 1–100 котушок створюються однією операцією. Корисно для «купив упаковку з п'яти PLA» — усі копії з однаковими матеріалом / кольором / вагою / ціною (лоти можуть відрізнятися, див. **Лот** + авто-нумерацію нижче). |
| **Колір** | Візуальний вибір із відтінком, прозорістю й оздобленням. Стрічка останніх кольорів + палітри брендів. |
| **Додаткові кольори** | Необов'язково. Список із 2–8 hex-кольорів через кому (напр. `EC984C,#6CD4BC,A66EB9,D87694`) для багатоколірних котушок. Зразок кольору малюється по-різному залежно від значення **Візуальний ефект** нижче — плавний перехід, смуги з чіткими межами або кольорове коло. Формат як на 3dfilamentprofiles.com, тож можна вставляти як є. |
| **Візуальний ефект** | Накладається поверх зразка кольору — профіль слайсера **не** змінює. Поверхневі ефекти (*Іскристий*, *Дерево*, *Мармур*, *Світиться*, *Матовий*) малюють накладку; варіанти з блиском (*Шовк*, *Галактика*, *Веселка*, *Метал*, *Напівпрозорий*) дають м'який блиск; структурні варіанти задають форму кольорового шару — *Градієнт* = плавний перехід під 135°, *Двоколірний* / *Триколірний* = горизонтальні смуги з чіткими межами (кожен колір у власному сегменті, без діагонального переходу), *Мультиколор* = кольорове коло. Під списком форма має живий попередній перегляд, тож ефект видно до збереження. |

#### Режим «Швидке додавання (запас)»

Перемикач **Швидке додавання (запас)** зверху форми вмикає мінімальний режим: сім'я філаменту стає необов'язковою, а вкладка «PA профіль» ховається. Обов'язковий лише **Матеріал**; **Бренд** і **Підтип** необов'язкові, поруч — **Вага на етикетці**, **Кількість** і **Колір**. Ідеально для інвентаризації щойно отриманого замовлення до того, як ти вирішив, з якою сім'єю філаменту його пов'язати.

Котушки зі швидкого додавання називаються **котушками запасу** — вони обліковують вагу й витрату як будь-яка інша котушка, але не прив'язані до профілю філаменту принтера. Таку котушку можна пізніше відредагувати й призначити їй сім'ю філаменту (тоді вона стає *налаштованою*) або відфільтрувати лише запас фільтром запасу в інвентарі.

Поле **Кількість** показується лише у швидкому додаванні й створює вказану кількість котушок однією транзакцією. Швидке додавання також показує поле **Лот** разом із чекбоксом **Авто-нумерація лотів (+1 на копію)**:

- **Авто-нумерація увімкнена** — копії нумеруються послідовно **від введеного значення лота**: Лот `5` × Кількість `3` → три котушки з лотами **5, 6, 7**. Лишиш «Лот» порожнім — нумерація стартує з 1.
- **Авто-нумерація вимкнена** — усі копії отримують одне введене значення лота (або взагалі без лота).

!!! tip "Купівля партією"
    Упаковка з п'яти PLA з однієї партії → Кількість = 5, Лот = 1, **Авто-нумерація лотів** увімкнена → пʼять котушок із лотами 1–5, кожну можна відстежити за її лотом, і при цьому один рядок *5 однакових котушок* під перемикачем **Групувати** — лот у ключ групування не входить, тож нумерація лотів нічого не коштує у списку.

#### Звідки беруться сім'ї {#where-families-come-from}

Вибір **Сімʼя філаменту** живиться з двох ярусів, обидва резолвляться локально (див. [Сім'ї філаментів](filament-families.uk.md)):

| Ярус | Опис |
|---|---|
| **Вбудований каталог** | Кожна офіційна сім'я філаментів Bambu, дистильована з самих Bambu Studio та OrcaSlicer. Завжди доступний, без login-у. |
| **Ваші власні** | Сім'ї за вашими пресетами Bambu Cloud / Orca Cloud (дзеркалюються на сервер у фоні), локальні імпорти і сім'ї, створені в BamDude. З бейджем походження. |

Перегляд показує спершу *ваші* сім'ї (ті, що за вашими пресетами, котушками й калібруваннями); пошук іде по повному каталогу обох екосистем із дедуплікацією. Список не буває порожнім — з хмарою чи без.

Кастомні пресети, що inherit-ять з Bambu-пресетів (напр. *# Overture Matte PLA @BBL H2D*), повністю підтримуються — сім'я резолвиться з inheritance-ланцюжка.

#### Власні матеріали {#custom-materials}

Список матеріалів має базовий набір — PLA, PETG, ABS, TPU, ASA, PC, PA, PVA, HIPS — плюс варіанти з вуглецевим і скляним волокном та спеціальні (PLA-CF/GF, PLA Aero, PETG-CF, ABS/ASA-GF, ASA-CF, PCTG, PAHT-CF, PA6-CF/GF, PPS/PPS-CF/GF), згруповані за родиною матеріалу. Якщо твого матеріалу все одно немає (напр. PHA, PP, PVDF) — введи його просто в поле «Матеріал»: унизу списку з'явиться опція *Використати власний матеріал: …*. Клікни її, щоб підтвердити.

Власні матеріали працюють як вбудовані — для обліку інвентаря, історії витрат, фільтрування і сповіщень.

!!! example "Додавання PCTG (3D-Fuel Pro)"
    1. **+ Додати котушку**.
    2. **Сімʼя філаменту**: обери найближчу PETG-сім'ю (PCTG — це різновид PETG). Власний PCTG-профіль OrcaSlicer спершу імпортуй через [Local Profiles](local-profiles.uk.md).
    3. **Матеріал**: введи `PCTG` → клікни *Використати власний матеріал: PCTG*.
    4. **Бренд**: `3D-Fuel`. **Підтип**: `Pro`.
    5. Задай колір (315 °C max bed, 80 °C bed для PCTG — типові температури друку й столу успадковуються з базового PETG-пресета; за потреби зміни їх у слайсері). Збережи.

#### Розділ «Додатково»

| Поле | Опис |
|---|---|
| **Вага порожньої котушки** | Обери з [Каталогу котушок](#spool-catalog) (90+ записів) або введи вручну — потрібно для точного розрахунку залишку. Вага порожньої котушки 0 г — окреме значення, і воно зберігається як 0. |
| **Залишкова вага** | Поточне `label_weight - weight_used` зі смугою відносно максимуму. |
| **Вартість за кг** | Ціна саме цієї котушки; з неї рахується [облік вартості](#cost-tracking) і вартість архівів. |
| **Востаннє сушено** | Коли котушку востаннє сушили — див. [Востаннє сушено](#last-dried). Показується під час редагування котушки. |
| **Номер матеріалу** | Твій власний артикул філаменту — див. [Номер матеріалу](#material-number). |
| **Примітка** | Довільний текст. |

#### Номер матеріалу {#material-number}

**Номер матеріалу** — довільний внутрішній артикул поруч із полем **Лот**: номер, яким філамент називають у твоїй майстерні чи бухгалтерії, хоч би як його називав бренд. Поле підказує номери, які вже використовуються.

- Нова котушка філаменту, що вже має номер, отримує його автоматично — «той самий філамент» тут означає те, за чим групує **Групувати** (бренд, матеріал, назва кольору, вага за етикеткою, підтип). Введений тобою номер ніколи не замінюється, а редагування котушки саме його не змінює. Імпорт CSV не успадковує: порожня клітинка там означає «без номера».
- Номер доступний як необов'язкова колонка таблиці (типово вимкнена — увімкни в налаштуваннях колонок), як фільтр, у полі пошуку, у **Масовому редагуванні**, як рівень у [Порядку котушок](#spool-order), як змінна `{material_number}` шаблону назви котушки та шаблонів наліпок і як колонка `material_number` в експорті та імпорті CSV.
- [Stats](stats.uk.md#by-material-number) підсумовує витрату й вартість за номером матеріалу.
- У режимі Spoolman поле показує артикул філаменту зі Spoolman і доступне лише для читання — міняй його у Spoolman.

#### Востаннє сушено {#last-dried}

Котушка пам'ятає, коли її востаннє сушили. Коли цикл сушіння в AMS пропрацював щонайменше половину свого часу, кожна котушка, призначена в слот цього блока, отримує дату, а з нею температуру й години, якщо вони відомі. Запис належить котушці, тож лишається з нею після переїзду в інший AMS чи на полицю. Цикл, зупинений завчасно, нічого не позначає і не перезаписує попереднє сушіння. Працює і з вбудованим інвентарем, і зі Spoolman.

Для котушки, висушеної деінде, постав дату вручну: поле **Востаннє сушено** у формі котушки має кнопку **Зараз**, а очищення поля стирає запис; **Масове редагування** робить те саме для цілого виділення. Дата, поставлена вручну, не несе температури й годин.

Дата показується на картці котушки, вмикається як колонка таблиці **Востаннє сушено** (типово вимкнена), передається в експорті та імпорті CSV як `last_dried_at` і може бути рівнем у [Порядку котушок](#spool-order).

#### Вага, введена вручну, блокується {#hand-entered-weight-lock}

Коли ти сам вводиш використану вагу котушки, BamDude блокує цю вагу від синхронізацій ваги з AMS: ні автоматична синхронізація, ні кнопка **Синхронізувати вагу з AMS** її не перезаписують. Друки й далі списують використане. Вага, що прийшла через імпорт CSV, блокується так само.

Зняття блокування — явна дія. Відкрий котушку: примітка каже, що вагу введено вручну, а під нею є чекбокс **Дозволити синхронізації ваги з AMS знову оновлювати цю котушку**. Для багатьох котушок одразу познач **Розблокувати вагу** в **Масовому редагуванні**. В обох випадках збережена вага лишається як є; змінити її можуть лише наступні синхронізації.

#### Призначення в слот із форми {#assign-to-slot-from-form}

Котушка, що не стоїть у жодному слоті й не заархівована, має внизу своєї форми кнопку **Призначити в слот**. Обери принтер, **Блок AMS** і **Слот** — і далі працює звичайний діалог призначення з усіма його перевірками, так само, як коли починаєш із картки принтера. Слот, у якому стоїть RFID-котушка Bambu Lab, обрати не можна — ним керує принтер.

### Вкладка «PA профіль»

Друга вкладка прив'язує до котушки калібрувальні профілі pressure advance (K-фактор). Автовибір добирає профілі за брендом + матеріалом + підтипом на всіх твоїх принтерах і соплах; збіги згруповано за принтером і соплом (ліве / праве на двосоплових):

- **Автовибір** — автоматично заповнює матрицю з твоїх наявних K-профілів.
- **Згрупований вигляд** — згортувані заголовки принтерів, під кожним — рядки для сопел (L / R).
- **Значення K-фактора** показані просто в рядках, тож їх можна перевірити перед збереженням.
- **Бейдж діаметра сопла** на кожному рядку. Профілі тягнуться для **кожного** розміру сопла, який звітує принтер, тож на багатосопловій машині один філамент може дати два рядки з однаковою назвою — саме діаметр їх і розрізняє. Принтер, який ще не відзвітував своє залізо, опитується на 0.4 мм.
- **Власний профіль для принтера** — обери інший профіль для одного принтера, якщо калібрувальні значення того самого бренду відрізняються між машинами.

Див. [K-профілі](kprofiles.uk.md) про калібрування, яке створює ці профілі.

## :material-checkbox-multiple-marked: Масові дії

Кожен рядок на сторінці «Філамент» має чекбокс. Познач один — і над списком з'явиться панель із діями **Редагувати · Надрукувати наліпки для вибраних котушок** (**Надрукувати наліпку для вибраної котушки**, коли позначено одну) **· Скинути лічильник · Архівувати** (або **Відновити** на вкладці «Архівовані») **· Видалити**.

Чотири способи виділення:

| Контрол | Що позначає |
|---|---|
| Чекбокс рядка | Цю котушку |
| Чекбокс групи | Усі котушки групи (показує риску, коли позначено лише частину) |
| Чекбокс у шапці | Усі котушки **на поточній сторінці** |
| **Вибрати всі N за фільтром** | Усі котушки, що їх повертає поточний фільтр, включно з рядками на інших сторінках |

Останній пункт — свідомо окрема явна дія, а не поведінка за замовчуванням. Редагувати «все, що показує фільтр» зручно; *видаляти* це не має ставатися через галочку, якої ти не бачив. З тієї ж причини виділення скидається саме, щойно ти міняєш фільтр, пошук, вкладку чи групування — панель із написом «вибрано 12» над списком, де тих котушок уже нема, це рівно той сценарій, у якому масове видалення прилітає не туди.

Архівування, відновлення та видалення спершу перепитують.

**Архівування котушки забирає її з AMS-слота.** Слот звільняється на картці принтера, і наступний друк із нього вже не списується на архівну котушку. Котушку в слоті, з якого подає друк, що зараз іде, не можна архівувати, доки цей друк не завершиться: одиночне архівування відхиляється, а масове такі котушки пропускає й каже, скільки їх залишено, — архівуйте їх після завершення друку. Архівна котушка, яка ще показується в слоті, залишає його, щойно її принтер стане вільним.

!!! warning "Використану котушку архівують, а не видаляють"
    **Видалити** прибирає лише котушку, на яку ніщо не посилається. Котушку, що має історію витрат, стоїть у слоті або належить до друку, який зараз іде, видалити не вдасться — з підказкою заархівувати її натомість: інакше її записи й друки, оцінені за ними, лишилися б без котушки. У масовому видаленні котушки, які можна прибрати, видаляються, а відхилені — перелічуються. Для котушки, яку ти закінчив, використовуй **Архівувати**. У режимі Spoolman історія — це записи BamDude для поточної адреси Spoolman — див. [Spoolman](spoolman.md).

Усе це працює і в **режимі Spoolman**, не лише з вбудованим інвентарем. Оскільки Spoolman — окремий сервіс, який може бути тимчасово недоступним, окремі рядки можуть не пройти: тоді ти побачиш чесне **«7 виконано, 2 не вдалося»** замість повідомлення про успіх, а виділення збережеться, щоб можна було повторити для решти.

!!! tip "Діалог редагування показує, що саме зміниться"
    Діалог масового редагування перелічує конкретні котушки з виділення. Він лише для читання — вибір робиться на сторінці — але варто його прочитати, перш ніж застосовувати поле до сорока котушок.

## :material-format-list-checkbox: Призначення слотів AMS

Як котушка існує — її можна припаркувати в конкретний слот AMS на конкретному принтері. Права AMS-панель на картці кожного принтера показує чотири слоти кожного AMS (один — на AMS HT) і дає кинути котушку в кожен.

За кулісами це таблиця `spool_assignment` — один рядок на трійку `(printer, ams_id, tray_id)`. Два призначення на той самий слот одночасно існувати не можуть; присвоєння нової котушки звільняє попередню (вона повертається в "available, не в принтері").

Зворотне теж правда: **котушка стоїть лише в одному слоті**. Призначення котушки, яка досі записана в іншому слоті — на тому самому принтері чи на іншому, — забирає її з того слота. Призначення відхиляється, коли той інший слот живить друк, що зараз іде: дочекайся кінця друку чи зупини його, або обери іншу котушку.

Дві речі призначення **не** знімають:

- **Одиничне повідомлення «порожньо» від AMS на простої.** Слот, який звітує, що котушки немає, поки нічого не друкується, втрачає призначення лише тоді, коли приблизно через 25 секунд він усе ще звітує порожнім. Тож одне випадкове статус-повідомлення призначень не чіпає, а котушка, яку справді вийняли, відв'язується трохи згодом.
- **Від'єднання AMS.** Блок зникає з картки принтера, а його котушки лишаються призначеними до моменту, коли його під'єднають знову.

Ще кілька зручностей:

- **RFID auto-assign** — Bambu-котушки з цілими RFID-тегами матчаться на каталог моментально, як AMS читає тег. Якщо тег вказує на відому каталог-сутність, але інвентар-рядка ще немає — BamDude пропонує створити inline. Якщо тег невідомий (third-party, custom) — можна прив'язати його до наявної котушки, щоб наступного разу не лазити вручну.
- **Auto-tracking нових Bambu-котушок** — коли AMS RFID не матчить жодного існуючого tray UUID, BamDude спочатку шукає **untagged**-котушку зі збіжним матеріалом + кольором + брендом (`Bambu` / `Bambu Lab` / unspecified) і прив'язує RFID до неї. Тож Quick-Add stock-запис, що ти залогував наперед, реюзається (твоя вага, нотатки, cost-data зберігаються) замість того, щоб видавати дублікат. Якщо збігу немає — створюється свіжий inventory-рядок з AMS-data, намальований так само, як котушка того ж кольору, додана вручну: назва кольору, додаткові кольори й ефект беруться з каталогу кольорів, а де каталог ефекту не має — його дає підтип, якщо той називає оздоблення (*Wood*, *Silk*, *Sparkle*, *Gradient*…; *Basic* чи *CF* не називають жодного).
- **Drying schedules + AMS humidity tracking** — див. [AMS та вологість](ams.uk.md) — inventory- і AMS-сторінки шерять стан, тож "drying" котушка візуально позначена як in-progress в обох місцях.

!!! note "Вимкни тихе створення для невідомих тегів"
    Авто-створення свіжого рядка для нерозпізнаного RFID керується через **Налаштування → Філамент → Автододавання котушок з невідомим RFID** (`auto_add_unknown_rfid`, за замовчуванням **увімкнено**). Вимкни його — і невідомий тег натомість покаже **картку підтвердження** з матеріалом і кольором, префіленими з AMS-читання, тож нічого не запишеться в інвентар, доки ти не підтвердиш. Зручно, якщо ти створюєш котушки вручну наперед і не хочеш дублікатів.

!!! tip "Знайти котушку за її тегом"
    NFC-інтеграції можуть знайти одну котушку, не листаючи весь інвентар: `GET /api/v1/inventory/spools/by-tag?tray_uuid=<uuid>` (або `&tag_uid=<uid>`). Матчинг hex-нормалізований і case-insensitive; архівні котушки виключені, доки не передаси `include_archived=true`. Читається з `inventory:read` АБО `inventory:update`, тож Manage-Inventory API-ключ може дедупити скан без глобального read-scope.

### Стабільні assignments на startup-і

Spool-assignments зберігаються через рестарти BamDude за **spool ID**, не за slot ID. Якщо AMS реконнектиться в іншому порядку при boot-і — RFID slot 3 приземлиться там, де був slot 1 минулої сесії, тощо — BamDude відновлює за RFID-identifier-ом, тож правильна котушка лишається прив'язана до правильного фізичного tray, без ручного фіксу. Якщо та сама котушка все ще в тому самому фізичному слоті (verified by RFID) — reconfigure-команда принтеру не відсилається.

### «Налаштувати слот» чи «Призначити котушку» {#configure-ams-slot-vs-assign-spool}

Ці дві дії стоять поруч у меню слота, але роблять різне. Дивись таблицю нижче, коли вагаєшся:

| Дія | Що змінює | Скільки діє | Коли використовувати |
|---|---|---|---|
| **Налаштувати слот** | Каже **принтеру**, який профіль філаменту (температури, потік, pressure advance) використовувати для цього фізичного слота | Поки слот не налаштують заново або поки RFID не перезапише налаштування | «Я щойно завантажив сторонній PETG у слот 1 — задай профіль, щоб принтер брав правильні температури.» |
| **Призначити котушку** | Каже **BamDude**, на який запис інвентаря списувати витрату з цього слота, — і **також** виконує «Налаштувати слот» із профілем філаменту, кольором і K-профілем котушки | Поки не призначать іншу або поки AMS не побачить інший RFID | «Відстежувати, яка фізична котушка в якому слоті, щоб витрата й вартість списувалися правильно.» Працює і на порожніх, і на налаштованих слотах. |

Призначення котушки — найпростіший шлях: воно за один крок робить і облік, і налаштування принтера. «Налаштувати слот» напряму потрібне лише тоді, коли хочеш перевизначити налаштування або налаштувати слот без котушки з інвентаря.

### Прогноз запасів + логістична панель

Режим **Прогноз**, поряд із **Таблиця** / **Картки** / **Історія**, перетворює сирий `spool_usage_history` у систему прийняття рішень про повторне замовлення:

- **Темп витрати на день** — експоненційно зважена середня з періодом напіввитрати 30 днів, рахується на **групу кольору** (матеріал / підтип / бренд / назва кольору). П'ять кольорів одного PLA Basic стають п'ятьма незалежними forecast-рядками, кожен зі своїм запасом і датою замовлення — тож нестача чорного не ховається за повною котушкою білого. Одна котушка зі свіжих друків важить більше, ніж річний сплеск. Колір, для якого записаної історії замало, щоб побачити тренд, оцінюється за підсумками його котушок: витрата кожної котушки розкладається на час, коли нею справді друкували — від першого використання до останнього, — і рахується лише те, що припадає на останні 90 днів. Час, який котушка пролежала на полиці до відкриття, витратою не є, тож філамент, куплений місяці тому й відкритий минулого тижня, прогнозується в темпі цього тижня; філамент, яким не друкували 90 днів, показує нульову витрату.
- **Прогноз днів, що лишились** — поточний запас ділимо на темп з урахуванням 95%-довірчого запасу безпеки (`σ × √термін × 1.65`).
- **Дата повторного замовлення** — коли ставити замовлення, щоб нова котушка прибула *до* того, як ти закінчиш поточну, з урахуванням налаштованого терміну постачання.
- **Зайнято під замовлення** — скільки **відомих** грамів активні замовлення ще мають забрати з полиці: ще не надрукований план плюс те, що вже чекає в чергах, пораховано так само, як на сторінках замовлень, і розкладено по SKU, які можуть це покрити (за залишком ваги, коли підходять кілька брендів). Якщо в активному замовленні канал слайсера не має достовірної ваги, панель попереджає: **Зайнято** й **Замовити до** враховують лише відому частину; BamDude не вигадує грами й не приписує таку невідомість конкретному SKU. Під цим числом стоїть те, що ще можна обіцяти, і **Замовити до** відлічується саме від *цього*, а не від усього, що лежить на полиці, — **Закінчиться** навмисно ні, бо темп витрати вже містить друк цих замовлень. Якщо обіцяно більше, ніж лежить на полиці, рядок показує **Обіцяно більше, ніж є**, і це рахується як попередження ще до того, як SKU отримає темп витрати. Потреба в кольорі, якого немає на складі, перелічується під таблицею, а не розподіляється між кольорами, які є.
- **Фільтри + лічильник** — списки **Матеріал** і **Бренд** звужують таблицю; окрема колонка **Котушки** показує, скільки фізичних котушок стоїть за кожним рядком кольору. Кожна колонка сортовна.
- **Розгортувані редактори кольору** — lead-time-days, запас безпеки (подвійна одиниця — дні чи грами), перемикач сповіщень-снуз. Кожне налаштування зберігається у таблиці `filament_sku_settings`; кольори без налаштувань беруть глобальний мінімум терміну постачання (поле **Глобальний термін постачання** в режимі «Прогноз»).
- **Топ-5 діаграма** — stacked-area, multi-series прогноз п'яти найшвидших кольорів з пунктирними ROP-лініями. Перемикач періоду: 1Т / 1М / 6М.
- **Список покупок (Логістика)** — окрема панель під таблицею прогнозу. Додавай SKU в чергу `pending → purchased → received`. Позначення *received* автоматично створює котушки з `category='Stock'` через bulk-create (використовує середню історичну вагу котушки). CSV-експорт + clear-all. Назви й примітки, схожі на формули, записуються в CSV як текст. Кількість і вага зберігають числові значення.
- **Перемикачі сповіщень** — дві події провайдерів сповіщень стоять у **Налаштування → Сповіщення → Сповіщення про запаси**: *Час замовляти* (SKU досяг точки повторного замовлення) і *Ризик закінчення* (закінчиться до прибуття поповнення). Обидві надсилаються через провайдера, як будь-яка інша подія. Про колір, у якого всі котушки заархівовано, натомість повідомляють один раз, що він закінчився, — і зовсім не повідомляють, поки той самий колір іншого бренду є на полиці; див. [Сповіщення](notifications.md).

Forecast-вкладка працює і в **режимі Spoolman**: BamDude веде власний запис кожного друку, списаного на котушку Spoolman, і будує прогноз за ним. Див. [Spoolman → Історія витрат і прогноз](spoolman.md#spoolman-usage-history).

Дозволи: `inventory:forecast_read` (бачити панель) і `inventory:forecast_write` (змінювати налаштування SKU + список покупок). У типових групах Viewers мають read, Operators — обидва.

### Pre-load assignment (зважив-призначив до завантаження)

Можна призначити котушку у слот **до того, як** завантажиш філамент — зручно, коли щойно зважив свіжу котушку і хочеш трекати її з першого ж друку. Коли цільовий слот порожній (`tray_type` blank в AMS-data), BamDude:

- Одразу зберігає рядок `SpoolAssignment`, тож inventory-сторінка показує pairing.
- **Відкладає** публікацію `ams_filament_setting` + `extrusion_cali_sel` через MQTT — firmware Bambu тихо відкидає обидві команди для незавантажених слотів (немає filament-context, до якого міг би прив'язатися K-profile / pressure-advance index), і слати їх все одно означало б закрити модалку фальшивим «Призначено!» поки слайсер далі показує дефолтний PLA назавжди.
- Показує це в підтверджувальному тості: *«Котушку призначено. Слот налаштується, коли ви вставите філамент.»*
- Автоматично повторно надсилає повну конфігурацію в момент, коли слот стає завантаженим. «Завантажено»-сигнал — це AMS state-код (`state == 11`, «філамент подано в екструдер»), а не material-string з tray-data — тож сторонні котушки без читабельного RFID (які репортять state=11 але тримають `tray_type=""`) теж тригерять replay. Після replay-у assignment-fingerprint штампується, тож наступні AMS-пуші не re-firать.

### Автоматичне призначення повної котушки зі складу {#automatic-stock-assignment}

!!! info "Доступність"
    Працює з **вбудованим інвентарем**, не зі Spoolman, і типово вимкнена для кожного принтера.

Це зручно, коли в принтер регулярно ставлять нові повні котушки одного філаменту без RFID. BamDude може призначати наступну відповідну котушку з інвентарю, коли бачить вставлення філаменту в порожній слот AMS, зокрема після закінчення попередньої котушки.

1. Додайте повні котушки на сторінці **Філамент** із правильними матеріалом, кольором, брендом, підтипом, сім’єю філаменту й вагою етикетки.
2. Відкрийте **Принтери → Редагувати принтер**, увімкніть **Призначати повну котушку зі складу при завантаженні**, виберіть **Групу філаменту на складі** й збережіть принтер.
3. Поки BamDude підключений до принтера, вставте нову повну котушку цієї групи в порожній слот AMS. Перевірте призначення на слоті або в інвентарі.

Для зміни налаштування потрібні права редагування принтера й інвентарю; для читання списку груп — право читання інвентарю.

**Яку котушку обирає.** Група має збігатися точно, включно з кольором і сім’єю філаменту. Підходять неархівовані, непризначені котушки без RFID: одноколірний філамент 1,75 мм, додатна вага етикетки, нульова фактична витрата й відсутність попереднього використання в друках. Котушка, внесена як часткова, не підходить. Спочатку обирається найраніше доданий запис, за однакової дати — найменший ID. Скидання показуваного лічильника витрати не робить використану котушку новою. Коли група закінчиться, вона лишиться вибраною: BamDude не підставляє іншу групу й не створює котушку. Додайте відповідний запас або призначте котушку вручну.

**Що означає завантаження.** У котушки без RFID немає доступного принтеру номера запису інвентарю чи точної ваги. Вмикаючи це правило, ви підтверджуєте, що нові котушки, завантажені таким способом, повні й належать вибраній групі. Старт і перепідключення лише запам’ятовують стан слотів; уже вставленим котушкам нові записи не призначаються. RFID і ручне призначення мають пріоритет. Виймання й повернення відомої часткової котушки без runout зберігає її призначення.

!!! warning "Повернення старої котушки після runout"
    Виймання часткової котушки під час друку саме може спричинити runout. Якщо повертаєте ту саму котушку, **призначте її вручну до вставлення або відновлення друку**. Інакше ввімкнене правило вважатиме заміну новою повною котушкою. Ручне призначення після runout має пріоритет, навіть якщо це та сама часткова котушка. Для заміни часткової котушки повною без runout теж використовуйте ручне призначення.

**Зовнішні тримачі:** звичайне завантаження потребує ручного призначення, бо датчика вставлення немає. За ввімкненого правила однозначно визначений runout зовнішньої котушки й ваш перехід **Пауза → Друк** у тому самому сеансі підключення можуть призначити повну заміну з вибраної групи. BamDude має бачити завантаженим саме цей зовнішній канал; звичайна пауза, перепідключення чи неоднозначний runout не підходять. Повернення старої котушки потребує ручного призначення до відновлення. Самостійно друк ця можливість не відновлює.

Це правило призначення фізичних котушок в інвентарі. Воно не змінює [маршрутизацію філаменту](filament-routing.md), ігнорування кольору чи профілю в черзі та сумісність AMS Backup.

### Заміна котушки на призначеному слоті

Знімати призначення заздалегідь не треба. Наведи на призначений слот і обери **Замінити котушку** (поруч із **Зняти призначення**): діалог показує, що зараз призначено, і пропонує лише вільні котушки — поточна і будь-яка призначена в інший слот приховані, тож випадково «витягти» котушку з іншого принтера неможливо — і одне підтвердження міняє призначення. Працює однаково на слотах AMS, AMS HT і зовнішніх, із вбудованим інвентарем і зі Spoolman.

В обліку нічого не змінюється: заміна проходить рівно тим самим шляхом, що й зняття з наступним призначенням. Посеред друку з'являється та сама підказка — на паузі або після паузи — з питанням, чи це фізична заміна котушки (витрата філаменту ділиться по шару паузи), чи виправлення хибного зв'язку (весь друк іде на нову котушку).

## :material-water-percent: Автоматичний облік витрати

Кожен друк, який BamDude диспатчить, читає per-filament `weight` з source-3MF. На `print_complete` витрачені грами віднімаються з котушки, що була призначена відповідному AMS-слоту на момент старту друку:

- Таблиця `spool_usage_history` записує кожне віднімання (один рядок на філамент друку × котушку — два філаменти одного файла, надруковані з тієї самої котушки, дають два записи історії).
- `spool.used_grams` — running-total.
- `spool.weight - spool.used_grams` — те, що залишилося.

Сторінка інвентаря кольорує кожну котушку за відсотком залишку, з налаштовним **порогом малого запасу** (олівець на підсумковій картці **Мало запасу**). Коли котушка падає нижче порога, спрацьовує сповіщення `filament_low` (підпишись на нього в тих провайдерах, де це потрібно). Про котушку, яка вже нижче свого порога, повідомляється й одразу, щойно її ставлять у слот — призначають вручну, розпізнають за RFID-тегом чи автоматично завантажують зі складу, — і коли її вагу, вагу за етикеткою або власний поріг змінюють вручну, поки вона стоїть у слоті. Це так само одне сповіщення на пробіг, і лише для котушки в слоті. Слот із прив'язкою до Spoolman оцінюється за цифрою Spoolman проти того самого порога. Слот без прив'язки до інвентаря не оцінюється взагалі: власний лічильник принтера показує 0 % для будь-якої котушки без RFID-тега, а це не відповідь — признач котушку, і BamDude знатиме, що на ній є.

Якщо друк впав посеред — віднята кількість це slicer-estimate × completion-ratio (best effort), а не повний estimate. External-print fallback archives — ті, що з друків, запущених прямо з тачскріна принтера — реконсилюються тим самим шляхом, як їхній 3MF відновлюється.

Видалення запису витрат повертає його вагу котушці. Закриття по runout і корекції AMS стосуються загального споживання котушки, а не грамів друку: їх видалення не змінює архів. Видалення звичайного запису друку, як і раніше, зменшує грами архіву. Перерахунок вартості також не додає службові корекції до ціни друку. В історії, експорті та бекапі вони зберігаються окремими записами.

### Деталізоване usage-tracking

Pipeline відняття складніше, ніж плоске "відняти slicer-estimate в кінці друку". BamDude обирає найточніше доступне джерело per-сценарій:

| Сценарій | Primary-джерело | Fallback |
|---|---|---|
| **3MF доступний + completed-друк** | Per-filament `used_g` з `slice_info.config` 3MF, мапнуте на physical AMS tray-ї через `ams_mapping`, захоплене з MQTT print-команди | — |
| **3MF доступний + failed/aborted partial-друк** | Per-layer G-code analysis: скільки грамів пройшло через кожен філамент до layer-у, де друк зупинився | Linear scaling = `total × completion_ratio`, якщо per-layer data не парситься |
| **Slicer-initiated друк** (BambuStudio / OrcaSlicer / Handy) | `ams_mapping` захоплене з live MQTT print-команди — гарантує, що правильний tray білиться, незалежно від того, який app стартував | — |
| **Single-filament друк** | Принтер's currently-active tray | — |
| **G-code-only друк, без 3MF** | AMS `remain%` дельта між print-start і print-end (integer-precision, ~10 г на 1 % step для 1 кг котушки) | — |
| **External print, fallback archive recovered later** | Реюзає 3MF source у момент завершення recovery, ретроактивно реконсилює відняття | — |

#### Що входить у грами слайсера {#slicer-grams}

Грами по кожному філаменту, які BamDude списує (і показує як оцінку друку), — це **вся витрата** цього філаменту за слайсером, а не лише модель. Bambu Studio складає для кожного філаменту:

- **модель**;
- **підтримки**;
- **prime tower**;
- **промивку** на кожній зміні філаменту (те, що принтер зливає у відходи).

Промивку слайсер рахує сам, за своєю таблицею об'ємів промивки; принтер зливає приблизно стільки ж, але відходи ніхто не зважує. Плита, G-code якої більший за 1 ГБ, не аналізується — її списують за зміною відсотка залишку AMS, — а аналіз дуже великої плити може тривати до 12 хвилин.

### Runout закриває котушку рівно в нуль

Runout — єдиний момент, коли реальність повідомляє точну цифру: на котушці **0 г**, хоч би що казали книги. BamDude слухає **власні runout-коди принтера** — AMS-слот чекає філамент, AMS автоматично перемкнувся на резервний слот, або закінчилась зовнішня котушка — і перетворює кожен на точний облік. Застрягання й заплутування *ніколи* не сприймаються як runout (рахуються лише точні коди прошивки), а котушка, чий слот не визначено однозначно, ніколи не чіпається.

Що відбувається, по порядку:

1. Runout журналиться на точному шарі, з котушкою, що фідила, **замороженою на той момент**.
2. Приходить нотифікація **Закінчився філамент** (увімкни її на своєму провайдері): або *«чекає філамент — признач заміну в BamDude, щоб решта друку лягла на правильну котушку»*, або інформаційна *«перемкнувся на резервний слот»*.
3. Заправляєш нову котушку. RFID-котушку BamDude побачить сам по тегу; для безтегових (зовнішні холдери включно) **сигналом є призначення заміни на слот** — зроби це будь-коли до кінця друку.
4. На завершенні друк розрізається **по runout-шару** (пошарова G-code-точність): кожна котушка отримує лише свій сегмент. Потім витрачена котушка отримує один фінальний рядок **«Закриття по runout»** на все, чого книги не бачили — її історія сходиться рівно з вагою етикетки, залишок стає точним нулем.

**Приклад.** Книги котушки A кажуть 2 кг залишку; друк на 600 г обривається runout'ом у точці, де реально з'їдено 250 г; заправляєш котушку B і додруковуєш.

| Рядок | Котушка | Грами |
|---|---|---|
| Сегмент друку до runout-шару | A | 250 г |
| Сегмент після | B | 350 г |
| Закриття по runout (помаранчевий рядок історії) | A | **+1750 г** |

A закінчує рівно з 0 г залишку (250 + 1750 = її 2 кг етикетки); B несе лише чесні 350 г. Архів друку так само показує 600 г і вартість за 600 — закриття є визнанням життєвого дрейфу котушки, а не витратою цього друку. Якщо B *не* призначиш — усі 600 г лишаться на A, закриття зменшиться до 1400 г, A все одно закінчить у нулі, а B лишиться необлікованою — саме тому нотифікація і підштовхує призначити.

Два runout'и одного слота за один довгий друк (два коротких хвости підряд) обробляються як окремі епізоди — кожен зі своєю межею і закриттям. У Spoolman-режимі все працює ідентично. Налаштовується в **Налаштування → Філамент → Точність списання**: тумблер закриття, опційна доплата за продувку на автоперемиканні (аварійного пуржа нема в оцінці слайсера), двобічний AMS-синк нижче, і скільки тримати по-принтовий журнал подій для розбору (72 год за замовчуванням).

**Друк, що переходить між треями** — резерв AMS, який потім повертається до поповненого слота, або завантажувач, що на кожному завантаженні на мить звітує інший трей (так P1S з BMCU звітує зовнішній тримач), — списується відрізок за відрізком: кожен відрізок один раз, на котушку, яку для нього записав журнал. Тож котушка, вставлена в той самий слот після runout, отримує свою частку. Трей, звітований у межах одного шару, не годував нічого, що видно за лічильником шарів, і не списується. Грами, для яких не вдається назвати котушку, надходять у сповіщенні **Філамент не списано** — і у вбудованому інвентарі, і в Spoolman. На принтері з двома зовнішніми тримачами зовнішній філамент, тримач якого друк не назвав, так само позначається як не записаний, а не списується на перший тримач.

**Друк, що зупинився після заміни котушки**, ділить лише те, що встиг надрукувати. Скасований друк зупинився на шарі 50 із 200, котушка B змінила котушку A на шарі 40, і витрачено, скажімо, 10 г: A надрукувала 40 із цих 50 шарів, B — 10, тож A списується 8 г, B — 2 г. Котушка, що з'явилася на останньому надрукованому шарі або пізніше, не отримує з цієї ваги нічого. Шар зупинки, кількість шарів плити та прогрес беруться такими, якими принтер звітував у момент завершення друку, тож друк, запущений на тому ж принтері до запису обліку, їх не змінить. Без пошарового G-code відрізки міряються кількістю шарів — точно лише тоді, коли шари витрачають приблизно однаково філаменту. Якщо принтер не повідомив шару зупинки, ніщо не каже, де заміна відносно зупинки: тоді вага надходить як не записана, а не ділиться порівну, — хіба що всі відрізки годувала та сама котушка, і тоді вона отримує все. Завершеному друку такий шар не потрібен, коли є його G-code.

**Поповнення неактивного слота після переходу на резерв.** Повторний autoswitch-статус не означає, що
закінчилась і нова котушка. Якщо журнал підтверджує резерв в іншому слоті того самого чотирислотового AMS,
інша котушка достовірно присутня, а подача на початковий слот не поверталася, BamDude не зараховує їй
повторний статус. Такі самі події, уже збережені в журналі, не потрапляють в облік так само. Після справжнього
повернення на поповнений слот його наступний runout обробляється звичайно. Перевірка спирається на
датчик та історію подачі, а не на затримку; інший AMS чи зовнішній тримач такої підстави не дає.

Якщо поточне призначення слота вже зникло, live-перевірка спершу визначає котушку за власним журналом. Рішення й новий запис використовують один зафіксований показник датчика. Повторні або згорнуті повідомлення про відкритий епізод не сповіщають знову; нове підтвердження переходу від паузи до резерву — сповіщає. Початкові шар та ідентичність котушки зберігаються, слабший повтор не стирає підтверджений autoswitch.

#### Заміна котушки, поки трубка ще подає стару

Коли AMS-слот спорожнів, принтер продовжує друкувати ниткою, що лишилась у трубці подачі, і на цей час показує id зовнішньої котушки. У цей час можна вставити нову котушку в слот — і призначити її — без зсуву обліку. Нитка з трубки лишається на **старій** котушці, доки принтер знову не подасть із цього слота; нова котушка списується з **того шару**, а не з моменту, коли ви її призначили. Призначення лише називає котушку в слоті; межу подачі визначає принтер. Пізній runout трубки списується на стару котушку, а пізніший runout нової котушки й далі рахується як її власний. Вбудований інвентар і Spoolman ділять друк однаково.

Під час друку журнал витрат записує це окремими подіями — початок хвоста й повернення подачі — поруч зі змінами треїв і runout. Вони визначають, як друк поділиться на завершенні; історія витрат котушки, як і раніше, показує лише те, що списано на кожну котушку.

Якщо BamDude перезапуститься посеред цього, він підхопить хвіст із журналу. Повідомлення, які він отримує, поки знову приєднується до друку, зберігають шар, на якому кожне надійшло, і порядок, у якому вони прийшли, тож кожен відрізок дістається котушці, що стояла в слоті, коли його подавали: котушка, призначена в цю мить, однаково залишає філамент із трубки старій котушці, а якщо призначити двічі, котушка між двома призначеннями зберігає свій відрізок. Призначення одразу після приєднання чекає, доки ці повідомлення буде записано, тож не може перейменувати відрізок, поданий раніше. Якщо їх не вдається записати, те, що вони охоплювали, позначається як **не записане**, а не списується на котушку, що стоїть у слоті наприкінці друку; попереднє зберігає свої котушки. Так само й тоді, коли зв'язок із принтером у ту мить був відсутній або ще відсутній під час списання; коли ніщо не підказує, як грами друку розподіляються по шарах, його філамент позначається як **не записаний**, а не ділиться навздогад. Запізніле повідомлення попереднього друку ніколи не потрапляє в наступний і не збиває того, що пам'ятає цей друк. Якщо історію друку не вдається прочитати, BamDude пробує ще кілька разів; те, чого він так і не побачив, позначається як **не записане**, а не списується на останню відому котушку — навіть коли цей невідомий відрізок і є всім, що відомо про друк, і оцінка за залишком у відсотках з AMS потім його теж не списує. Скасований одноколірний друк у Spoolman ділиться так само, як у внутрішньому складі. Якщо подача повернулась, поки BamDude не спостерігав, межею стає шар, який він побачив першим, а непобачений відрізок позначається як **не записаний** — його не отримує жодна котушка. Питання «трубка ще подає?» в застосунку навмисно немає: призначення й подача — різні факти, і діалог не зміг би назвати правильний шар.

### Архівування котушки після runout

Перемикач **Налаштування → Філамент → Точність списання → Архівувати закриту котушку** може архівувати порожню котушку після закриття однозначного епізоду runout, коли принтер підтверджено перейшов на резервну або замінну котушку. Типово **вимкнений**; працює з вбудованим інвентарем і Spoolman. Якщо котушку вставили знову й продовжили той самий друк, вона лишається активною. Нульовий або від’ємний обліковий залишок сам по собі не доводить фізичного runout.

### Двобічний AMS-синк ваги для тегованих котушок

Для котушок із валідним Bambu RFID-тегом показання AMS на простої коригують книги і **вниз**, не лише вгору — оцінка залишку прошивки це те саме число, яке Bambu Studio дзеркалить у свій filament manager. Корекція вниз навмисно обережна: те саме значення має повторитися у двох звітах з інтервалом щонайменше хвилину, тож збитий звіт після реконекту ніколи не перепише котушку. Безтегових котушок цей шлях не торкається.

Синхронізація чекає, доки друк буде проведено. Поки друк іде і доки його філамент не списано на завершенні, жодне показання AMS не записується на котушки цього принтера — показник залишку у відсотках уже містить частину того, що витратив друк, і його запис порахував би цей філамент двічі. [Вагу, введену вручну](#hand-entered-weight-lock), синхронізація не чіпає взагалі.

### Живе «Філаменту вже»

Поки друк іде, розгорнута картка принтера показує, скільки філаменту він уже з'їв — по кожному слоту на мультиколірних, оновлення двічі на хвилину — і каже **«розділено між котушками»**, щойно runout реально поділив друк між рулонами. Тільки відображення: у книги, як і раніше, пишеться один раз, на завершенні.

Цифра — це загальна витрата кожного філаменту за слайсером ([що в неї входить](#slicer-grams)), помножена на частку вже надрукованого, а частка вимірюється за видавлюванням у самому G-code — модель, підтримки й prime tower, шар за шаром. Промивки на зміні філаменту в G-code немає (її робить процедура зміни філаменту в принтері), тож живий віджет розподіляє її рівномірно по друку, а не стрибає на кожній зміні: посередині це оцінка, а наприкінці сума дорівнює загальній витраті слайсера.

#### Mid-print spool-change семантика

- **Після runout'а** — атрибуція ріжеться по runout-шару, як описано вище: межею володіє журнал.
- **Без runout'а** (ре-assign слота посеред друку для виправлення хибного лінка) — виграє live-assignment, і весь друк білиться новопризначеній котушці. Це семантика виправлення: BamDude вважає, що лінк був хибним із самого початку, а не що ти міняв рулони.

### Скинути лічильник {#reset-counter}

Кожна котушка має дію-ластик — **Скинути лічильник** — що обнуляє відображуваний лічильник **Загально використано** (**Скинути всі лічильники** скидає лічильник усіх активних котушок одразу). Важливо: це обнуляє лише *відображувану* цифру витрати — залишок ваги котушки при цьому **не** змінюється. Механічно це записує `weight_used_baseline`, тож показана витрата стає «використано від останнього скидання», а не за весь час — корисно, коли ти перемотуєш чи міняєш рулон, але лишаєш той самий запис інвентаря замість створення нового.

API за цими діями — `POST /inventory/spools/{id}/reset-consumed-counter` для однієї котушки і `POST /inventory/spools/reset-consumed-counter-bulk` для всіх.

### Режим «Історія» — усі списання одразу {#history}

Третій режим перегляду інвентаря, **Історія**, між «Картки» і «Прогноз», показує записи списань усієї ферми, а не однієї котушки: що друкувалось, з якої котушки, на якому принтері, скільки грамів, скільки коштувало і чим закінчилось — найновіше зверху.

Вкладка самої котушки відповідає на «куди пішла ця котушка». Цей режим — на «куди пішов філамент», а саме з цього питання зазвичай і починають. Записи ті самі, різниця лише в точці входу.

Усе в цьому списку рахує **сервер** — сторінка, порядок, фільтри, пошук і підсумки. У ферми з роком друку тут шестизначна кількість записів, і браузер їх не завантажує.

- **Пошук** — те саме поле пошуку сторінки. Той самий бокс, те саме місце; просто шукає воно тепер події — за назвою друку, котушкою і принтером одночасно.
- **Фільтри** — принтер (разом із *Без принтера*, для записів, що не числяться за жодною машиною), матеріал, бренд, статус і діапазон дат. Плюс стан самої котушки: **Усі / Активні / Архівовані** і **Усі / У принтері / На полиці**. Останні дві групи мають варіант *Усі*, якого немає на таблиці котушок, і він дефолтний: вихід котушки в архів чи зняття з принтера не скасовує того, що вона надрукувала, тож нічого тут не ховається, доки не попросиш.
- **Сортування** — за будь-якою колонкою: дата, котушка, друк, принтер, грами, відсотки, вартість, статус.
- **Підсумки** — грами (і гроші) поруч із фільтрами рахуються по **всьому фільтру**, а не по сторінці на екрані. «Скільки коштував серпень» — це один діапазон дат.

Котушки, які ти відтоді заархівував чи видалив, зберігають свої рядки — позначені, а не сховані: грами, які вони несуть, усе одно були надруковані, а викидання їх розсинхронізувало б ці підсумки з [архівами](archiving.uk.md). Імена котушок ідуть за твоїм [шаблоном відображуваної назви](#display-name-follows-your-template), а архівний принтер читається як *Printer 5 (Archived)* — так само, як усюди. Клік на котушці відкриває її.

У **режимі Spoolman** тут показано власний запис BamDude про друки, списані на котушки Spoolman, — див. [Spoolman → Історія витрат і прогноз](spoolman.md#spoolman-usage-history).

### Видалення записів витрати

Кожен рядок має **×** при наведенні, щоб видалити саме цей запис — і у вкладці **Історія** самої котушки, і в загальнофермовому режимі History; кнопка **Очистити** у вкладці котушки робить те саме для всього її списку. Видалення запису трактує ту витрату так, ніби її не було: його вага **повертається до котушки** (`weight_used` зменшується, тож залишок росте), і та сама величина віднімається від облікованого пластику привʼязаного друку, тож сторінка [Stats](stats.uk.md) лишається синхронною з інвенторі. Для мультиколірного друку віднімання — поелементне: видалення запису одного кольору повертає лише його частку й лишає решту друку без змін. Зручно, щоб «не рахувати» помилковий чи тестовий друк проти рулону.

## :material-currency-usd: Облік вартості {#cost-tracking}

Кожна котушка може мати вартість за кілограм; BamDude зводить її у вартість кожного друку, архіву і проєкту.

### Де задається вартість за кг

| Де | Поле | Примітки |
|---|---|---|
| Форма котушки → розділ «Додатково» | **Вартість за кг** | Ціна саме цієї котушки; має пріоритет над глобальним значенням |
| **Налаштування → Друк → Відстеження витрат** | **Вартість філаменту за замовчуванням (за кг)** | Запасна ціна за кг, коли в котушки ціни немає (типово 25.00 у `default_filament_cost`) |
| **Налаштування → Друк → Відстеження витрат** | **Валюта** | Символ, що використовується скрізь — USD, EUR, GBP, MYR і ще ~25 |

### Як обчислюється вартість

Для кожного друку BamDude рахує вартість по кожній котушці в міру списання грамів:

```
cost = (weight_used_grams / 1000) × cost_per_kg
```

- Per-spool `cost_per_kg` виграє; якщо unset — використовується глобальний default.
- Обчислений cost зберігається на кожному `spool_usage_history` рядку і агрегується в `print_archive.cost`.
- Print-modal preview показує **real-time cost estimate**, базований на завантажених котушках + їхніх cost/kg, перед стартом друку.
- Картки архівів показують total filament-cost; inventory-таблиця має sortable Cost/kg колонку (hidden by default — увімкни через column-settings); [Stats](stats.uk.md) сумує cost через усі друки.

### Перерахунок вартості

Друк зберігає вартість, з якою його проведено: кожен запис витрат несе те, скільки його грами коштували за ціною котушки на той момент. Кнопка **Перерахувати вартість** на сторінці [Stats](stats.uk.md#recalculate-costs) заново складає cost кожного архіву з цих записів — записані ціни зберігаються — у цьому priority-порядку:

1. `spool_usage_history` records, joined to `archive_id` (найточніші, per-spool actuals), плюс типова ставка для грамів, не покритих жодною котушкою або записаних без ціни.
2. Legacy usage records, joined by print-name (для старіших архівів без FK link-у).
3. Типова вартість філаменту (коли usage records взагалі немає).

Щоб виправити друки, проведені за хибною ціною котушки, зміни її **Вартість за кг** і скористайся [Переоцінити витрати](stats.uk.md#re-price-usage) на сторінці Stats — вона переоцінює записані витрати однієї котушки або одного періоду за поточними цінами котушок.

!!! tip "Задавай ціни одразу"
    Для точного обліку вартості задавай `cost_per_kg` на кожній котушці, коли додаєш її в інвентар. Типове значення — груба оцінка; ціни окремих котушок дають точні дані по кожному друку і роблять кнопку **Перерахувати вартість** корисною.

## :material-palette: Каталог кольорів

Імена кольорів приходять з таблиці `color_catalog` — manufacturer-aware. Коли два бренди постачають paint-chip з тим самим hex — для UI виграє Bambu Lab; non-Bambu резолвиться через свої записи. Якщо hex котушки взагалі не в каталозі — BamDude падає на HSL-derived ім'я ("dark cyan", "light yellow"), тож в UI ніколи не побачиш голий hex. Один hex може бути й двома кольорами в лінійці одного бренду — `#FFFFFF` це Jade White у PLA Basic і Ivory White у PLA Matte, — тож слот AMS спершу питає з власним матеріалом, а слот із призначеною котушкою показує назву кольору цієї котушки. Колір, обраний на екрані принтера, приходить на відтінок убік від каталожного значення, тож слот, чий hex не має точного збігу, дістає назву найближчого кольору Bambu Lab із власної продуктової лінійки слота — лінійку беруть із RFID-даних котушки або, без RFID, із пресета філаменту слота. HSL-ім'я дістається лише кольору, для якого близького кольору Bambu немає.

Каталог можна розширювати руками під **Налаштування → Філамент → Каталог кольорів**. Frontend підтягує runtime-мапу `{hex: name}` один раз на сесію — додавання нового запису діє на наступний логін (або hard-refresh).

### Багатоколірні градієнти

Painted, dual-color і silk-пластики — це не одне hex-значення, а градієнт між двома чи більше. BamDude малює їх як **справжні градієнтні swatch'і** на картках інвентаря, AMS-індикаторах слотів і colour-picker'і, замість колапсу до одного плоского hex (який завжди обирає не той "домінуючий" колір). Метадані 3MF несуть color stops; каталог резолвить ім'я; widget-swatch малює градієнт у CSS. Жодних ручних paint-chip-таблиць — суто data-driven.

!!! tip "Жодних жорстко зашитих таблиць кольорів"
    BamDude свідомо не має зашитих у код таблиць `tray_id_name` / hex — вони неминуче хибно підписували б сторонні філаменти. Каталог — єдине джерело істини, навіть коли спокусливо «зрізати шлях» у визначенні кольору десь у коді.

### Прозорий / clear пластик

Прозорий пластик — це first-class колір. Редактор кольору котушки має окремий quick-swatch **Clear**, а hex-поле приймає 8-значне значення `RRGGBBAA`, тож ти можеш позначити котушку як повністю чи частково прозору. Clear-котушки малюються як **шахова дошка** (checkerboard) swatch скрізь, де зʼявляється колір — картки інвентаря, AMS-індикатори слотів, colour-picker — замість того, щоб показуватись як невидимий або суцільно-чорний чіп.

## :material-printer: Друкові PDF-наліпки

Знайти конкретну котушку у шафі з 50 залишками — наклей на кожну наліпку. У шапці сторінки «Філамент» є кнопка **Друк наліпок…**, що відкриває multi-select picker, попередньо заповнений котушками за поточним фільтром. Кожна картка інвентарю та рядок таблиці теж має per-spool printer-іконку для one-shot друку наліпки, а кнопка **Надрукувати наліпки для вибраних котушок** на панелі вибраного відкриває той самий діалог для позначених котушок.

Щойно вибрано дизайн, діалог показує **Перегляд** — наліпку першої вибраної котушки, намальовану з її справжніх даних, — ще до будь-якого друку. **Друк** відкриває PDF у новій вкладці; **Зберегти як PNG** поруч завантажує ті самі наліпки зображеннями на 203, 300 або 600 dpi — один PNG для однієї котушки або ZIP для кількох. Самі дизайни й аркуші малюються в **Налаштування → Філамент → Маркування**. Подробиці, обмеження й шлях настільного принтера етикеток: [Наліпки на котушки](labels.md), [Збереження наліпок як зображень](labels.md#saving-labels-as-pictures).

### Назва на наліпці слідує шаблону {#display-name-follows-your-template}

Жирний центральний рядок на наліпці використовує той самий шаблон **Відображувана назва котушки**, що й сама сторінка «Філамент» (Налаштування → Філамент → **Відображувана назва котушки**). Тож якщо ти задав шаблон `{brand} {material} {color_name} (#{id})` для списку — саме це й буде друкуватися на кожній наліпці. 18 змінних (`{id}`, `{brand}`, `{material}`, `{subtype}`, `{color_name}`, `{slicer_filament_name}`, `{note}`, `{label_weight_g}`, `{label_weight_kg}`, `{remaining_g}`, `{remaining_kg}`, `{remaining_pct}`, `{color_hex}`, `{cost_per_kg}`, `{purchase_date}`, `{filament_diameter}`, `{lot}`, `{material_number}`) описані в тій самій панелі налаштувань, де редагується шаблон.

### Як резолвиться QR-deeplink

Нові етикетки вбудованого інвентарю містять ключ, прив’язаний до конкретного запису котушки. Перейменування або зміна партії не впливають на етикетку. Під час збереження з актуальної етикетки редактор повторно перевіряє запис. Після видалення запису вона втрачає чинність. Номер видаленої котушки повторно не видається; а номер, виданий повторно раніше, ніж з’явилося це правило, чи після відновлення старішої копії, однаково не дасть етикетці знайти іншу котушку. Старі етикетки й далі відкривають інвентар за номером. Передрукуйте їх, щоб скористатися дією **Сканувати етикетку котушки**. Етикетки Spoolman зберігають попередні посилання.

Адресу для посилання BamDude бере з першого доступного джерела нижче.

1. Налаштування `external_url` (Налаштування → Мережа → Зовнішній URL) — preferred, щоб скан з телефону потрапив на твій публічний URL BamDude, а не на внутрішню адресу.
2. Змінна оточення `APP_URL`.
3. Scheme + host поточного запиту (те, що у браузері в момент експорту).

Для phone-scan workflow задай `external_url` один раз — і кожна наліпка з кожного шаблону друкуватиме правильний deeplink.

### Призначення за етикеткою {#assign-by-scanning-a-label}

У вбудованому інвентарі відкрийте діалог призначення потрібного слота AMS і натисніть **Сканувати етикетку котушки**. Для місця зберігання відкрийте **Інвентар → Місця зберігання** й натисніть кнопку сканування в потрібному рядку.

Виберіть **Увімкнути камеру** або **Вибрати фото**. Для доступу до камери відкрийте BamDude через HTTPS. Вибір фото працює й тоді, коли камера недоступна. Якщо BamDude не прочитає QR-код з першого разу, він повторить спробу для великого фото з вищою роздільністю. Звірте назву й номер знайденої котушки, тоді підтвердьте призначення або переміщення.

### UX picker-а для великих бібліотек

Modal масштабується для великого інвентарю:

- **Пошук** — substring по composed display name + бренд + `#ID`.
- **Material filter chips** — виводяться з видимих котушок.
- **Обрати всі видимі / Зняти видимі / Скинути все** — selections survive при зміні фільтра (additive), тож можна звузити до "PLA only", обрати всі, потім звузити до "PETG", і додати ще.
- **Перемикач сортування (За ID / За кольором)** — *За ID* (типово) перелічує котушки за зростанням ID; *За кольором* групує їх за відтінком (хроматичні кольори за тоном, ахроматичні — за світлістю, у хвості веселки), тож надрукований аркуш виходить упорядкованим за веселкою. Лише на сесію — скидається до «За ID» при кожному відкритті вікна вибору.

### Server-side rendering

PDF-и рендеряться на сервері через ReportLab + qrcode. Чистий Python, без headless-браузера, output байт-ідентичний у всіх браузерах, аркуші Avery вирівнюються до <0.1 мм. Endpoints (обидва gated на `inventory:read`):

- `POST /inventory/labels` — local-DB котушки.
- `POST /spoolman/labels` — Spoolman-backed котушки (тільки якщо Spoolman-інтеграція ввімкнена).

Обидва приймають `{spools: [{id, display_name?}], template}` і повертають `application/pdf` через streaming response. Cap — 500 котушок на запит.

### Порядок котушок {#spool-order}

**Налаштування → Філамент → Порядок котушок** задає порядок, у якому пропонуються котушки. Це список рівнів сортування — у кожного поле й напрям (**За зростанням** / **За спаданням**), — що діють згори донизу: другий рівень впорядковує котушки, які перший лишив рівними. Типовий приклад — матеріал, потім бренд, потім найменший залишок першим. Обери поле під **Додати рівень…**, розстав рівні стрілками вгору й вниз і натисни **Зберегти порядок**; **Скинути до вбудованого** прибирає всі рівні.

За цим порядком ідуть два місця:

- **Діалог, у якому котушку ставлять у слот**, перелічує котушки в цьому порядку.
- **Сторінка філаменту**, поки не вибрано жодну колонку: рядок над таблицею каже *Порядок із налаштувань: …* і називає рівні. Клік по заголовку колонки все одно сортує за цією колонкою.

Поля: **Назва (за шаблоном)** — назва котушки, як її складає твій шаблон відображення, — **Матеріал**, **Підтип**, **Бренд**, **Назва кольору**, **Профіль слайсера**, **Залишок, г**, **Залишок, %**, **Використано, г**, **Вага за етикеткою**, **Додано**, **Куплено**, **Останнє використання**, **Востаннє сушено**, **Місце зберігання**, **Ціна за кг**, **Лот**, **Номер матеріалу** і **Номер котушки**.

Якщо рівнів немає, діалог слота сортує за матеріалом, брендом і кольором, а сторінка філаменту — за номером котушки. Порядок діє і для інвентарів Spoolman.

### Синхронізувати вагу з AMS (інструмент відновлення)

Коли використовується вбудований інвентар, **Налаштування → Філамент** показує кнопку **Синхронізувати вагу з AMS** під вибором режиму. Вона примусово синхронізує ваги всіх котушок інвентаря з поточними показами датчика AMS `remain%` на підключених зараз принтерах.

Використовуй це **тільки** для відновлення зіпсованих даних про вагу — наприклад, якщо вимкнення живлення принтера скинуло облікові грами всіх котушок до нуля. Синхронізація перезаписує збережені `weight_used` тим, що AMS звітує просто зараз. Принтери мають бути на зв'язку, щоб синхронізація могла прочитати покази.

Два види котушок пропускаються й рахуються в результаті як пропущені:

- **Котушки на принтері, друк якого ще не проведено** — друк іде або завершився, але ще не списаний. Показання AMS уже містить частину філаменту цього друку, тож синхронізація порахувала б його двічі. Друге повідомлення каже, скільки принтерів пропущено; повтори синхронізацію, коли їхні друки завершаться. Кнопка **Синхронізувати ваги AMS у Spoolman** у режимі Spoolman чекає так само.
- **Котушки з [вагою, введеною вручну](#hand-entered-weight-lock)** — спершу розблокуй їх, якщо показання AMS має замінити твою цифру.

!!! warning "Низька роздільна здатність — лише для відновлення"
    AMS `remain%` — ціле число (крок 1 % = ~10 г для котушки 1 кг). У повсякденному обліку покладайся на автоматичне списання за 3MF, описане вище, — воно точне до грама. **Синхронізувати вагу з AMS** — інструмент відновлення, а не звичайний шлях обліку.

### Каталог котушок {#spool-catalog}

Заздалегідь задані ваги порожніх котушок для швидкого вибору при додаванні. Постачається з 90+ записами для поширених виробників (картонна серцевина Bambu Lab, eSun, Polymaker, Overture тощо). Розташований у **Налаштування → Філамент → Каталог котушок**.

| Кнопка | Опис |
|---|---|
| **Експорт** | Завантажити весь каталог як JSON-файл — для резервної копії чи щоб поділитися зі спільнотою |
| **Імпорт** | Завантажити JSON-файл, щоб додати записи. Дублікати (та сама назва) пропускаються автоматично |
| **Скинути** | Відновити вбудований типовий каталог (перезаписує всі записи — потрібне підтвердження) |
| **+ Додати** | Вручну додати новий запис ваги котушки |

#### Формат імпорту

```json
[
  { "name": "Brand - Spool Type", "weight": 210 }
]
```

### Каталог кольорів

Єдине джерело істини для перетворення hex-кольорів на відображувані назви — спливне вікно AMS, список інвентаря, картки філаменту у вікні друку, вікно зіставлення AMS при повторному друку й автоматично створені записи інвентаря беруть назви з цієї таблиці. Постачається з 600+ кольорами 20 брендів.

| Кнопка | Опис |
|---|---|
| **Експорт** | Завантажити весь каталог як JSON |
| **Імпорт** | Завантажити JSON-файл, щоб додати кольори. Дублікати (той самий виробник + назва кольору + матеріал) пропускаються |
| **Синхронізувати** | Тягне нові кольори з [FilamentColors.xyz](https://filamentcolors.xyz/) — бази виміряних кольорів філаменту, яку веде спільнота. **Лише додає нові записи**, наявних ніколи не змінює |
| **Скинути** | Відновити вбудований типовий каталог (перезаписує всі записи) |
| **+ Додати** | Вручну додати новий колір (виробник, назва кольору, hex, матеріал) |

#### Формат імпорту

```json
[
  { "manufacturer": "eSUN", "color_name": "Silk Gold", "hex_color": "#C48E2F", "material": "PLA Silk" }
]
```

!!! info "Авторитет display-імен"
    BamDude резолвить кожне spool-color-ім'я, дивлячись hex у цьому каталозі (Bambu Lab entries вигрують, коли той самий hex зареєстрований під кількома брендами). Жодного hardcoded `tray_id_name` → name mapping нігде в кодбазі — додавання або редагування кольору тут — це supported шлях для виправлення або розширення display-імен. Restart-free: frontend перетягує каталог при наступному page-load.

## :material-frequently-asked-questions: FAQ

### Мого матеріалу немає у списку (напр. PCTG, PHA, PP)

Введи назву матеріалу просто в поле «Матеріал». Унизу списку з'явиться зелена опція *Використати власний матеріал* — клікни її. Власні матеріали працюють як вбудовані — для обліку, історії витрат, фільтрування і сповіщень.

### Чи треба обирати профіль слайсера для кожної котушки?

Ні. У режимі **Швидке додавання (запас)** котушки додаються лише з матеріалом і вагою. Котушки запасу обліковують вагу, витрату й вартість; пізніше їх можна відредагувати й призначити профіль. У повному режимі **Сімʼя філаменту** обов'язкова — обери найближчу доступну сім'ю (наприклад, загальну PETG для стороннього PETG) або створи власну рядком **Створити нову сімʼю…** у списку вибору.

### Маю різні принтери (P1S + H2D) і сопла — чи важливі пресети?

Сам інвентар котушок **не залежить від принтера**. Додай котушку один раз і призначай у будь-який слот AMS будь-якого принтера. Фільтрування за моделлю принтера вмикається лише в дії **Налаштувати слот** (коли кажеш принтеру, який профіль використовувати) — там список пресетів відфільтровано за моделлю принтера, тож видно лише сумісні профілі.

### Інвентар лише для завантажених котушок?

Ні. Інвентар обліковує **усі твої котушки** — завантажені й ні. Можна внести кожну котушку, яку маєш, навіть ті, що лежать на полиці. Підсумкова картка *У принтері* показує, скільки завантажено зараз; решта обліковуються так само (залишок ваги, історія витрат, вартість, сушіння).

### У чому різниця між «Призначити котушку» і «Налаштувати слот»?

Див. [таблицю порівняння](#configure-ams-slot-vs-assign-spool) вище. Коротко: **Призначити котушку** робить обидві речі — прив'язує запис інвентаря для обліку і налаштовує слот за профілем котушки. **Налаштувати слот** робить лише налаштування на боці принтера. Для звичайної роботи використовуй призначення; налаштування слота — коли хочеш перевизначити налаштування або налаштувати слот без котушки з інвентаря.

### Звідки беруться сім'ї філаментів?

Із вбудованого каталогу (кожен офіційний філамент Bambu, без мережі) плюс твої власні — віддзеркалені з хмари, імпортовані локально чи створені в BamDude. Навіть без входу в хмару список не буває порожнім. Див. [Звідки беруться сім'ї](#where-families-come-from) і [Сім'ї філаментів](filament-families.uk.md).
