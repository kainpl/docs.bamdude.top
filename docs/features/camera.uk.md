# Трансляція камери

Візуально спостерігайте за друком через живу трансляцію камери безпосередньо з вашого принтера Bambu Lab.

---

## :material-video: Жива трансляція

BamDude забезпечує MJPEG-відеотрансляцію з вбудованої камери принтера або зовнішньої мережевої камери.

### Відкриття камери

1. Натисніть іконку :material-camera: камери на картці принтера
2. Оберіть між оверлей-режимом або окремим вікном (налаштовується в Параметрах)
3. Трансляція починається автоматично

### Елементи керування

| Кнопка | Дія |
|:------:|-----|
| **Live** | Відеотрансляція MJPEG у реальному часі |
| **Snapshot** | Одне статичне зображення (менше навантаження) |
| :material-refresh: | Перезапустити трансляцію |
| :material-fullscreen: | Повноекранний режим |

## :material-webcam: Зовнішні камери

Підключай зовнішні мережеві камери замість вбудованої камери принтера. Корисно для кращих кутів, вищої роздільної здатності або принтерів у бокс-корпусах, де вбудована частково перекрита.

### Підтримувані типи

| Тип | Приклад URL/шлях |
|-----|------------------|
| **MJPEG** | `http://192.168.1.50/mjpeg` |
| **RTSP** | `rtsp://192.168.1.50:554/stream` |
| **Snapshot** | `http://192.168.1.50/snapshot.jpg` |
| **USB (V4L2)** | `/dev/video0` |

### Конфігурація

1. **Settings** → **General** → **Camera**.
2. Знайди свій принтер у секції **External Cameras**.
3. Перемкни switch для увімкнення.
4. Введи **URL** камери.
5. Обери **Type**.
6. Натисни **Test** — BamDude відкриває стрім один раз, підтверджує кадр і відключається.

!!! tip "RTSP-авторизація"
    Креденшали в URL: `rtsp://user:password@192.168.1.50:554/stream`.

!!! tip "go2rtc та IP-камери: warm-up-frame skip + Snapshot URL override"
    Багато MJPEG-джерел — особливо go2rtc, плюс ряд IP-камер — видають "warm-up" / часто чорний кадр на байті відразу після прийняття з'єднання (останній keyframe з енкодера до того, як він наздожене реальний live-контент). Починаючи з 0.4.4 BamDude читає повз перший кадр і повертає другий на всіх шляхах захоплення single-frame (notification thumbnails, finish photo, layer-timelapse, plate detection, Obico inference). Повільні / single-frame стріми, які не доставляють другий кадр у таймаут, падають на перший — щоб caller завжди отримав *щось*. Без додаткового налаштування.

    **Опційно: Snapshot URL override.** Для типів **MJPEG**, **RTSP** і **USB** можна додатково заповнити окремий **Snapshot URL** під live-stream URL. Коли заданий, BamDude тягне single-frame захоплення (notification thumbnails, finish photo, layer timelapse, plate detection, Obico inference) з нього через plain HTTP GET — повністю обходячи warm-up-frame dance. Корисно для go2rtc-сетапів (`http://<host>:1984/api/frame.jpeg?src=<name>` — спеціалізований single-frame ендпоінт, який ніколи не повертає stale keyframe з енкодера) чи IP-камер зі snapshot-ендпоінтом типу `/snapshot.jpg`. Натисни **Test** поряд зі Snapshot URL для перевірки. Live-view стрім завжди йде через основний URL; override змінює тільки single-frame захоплення (опитувати snapshot-ендпоінт 1 fps для live-view було б регресом для тих, у кого нема цієї проблеми). Прихований коли тип камери = `Snapshot` — live URL уже single-frame, override був би зайвим. Залиш порожнім — буде використано warm-up-frame skip на live-стрімі.

### USB / V4L2 setup

USB-вебкамери працюють через V4L2 на Linux-хостах:

```bash
# Інсталяція тулзів для лістингу пристроїв
sudo apt install v4l-utils

# Перелік відеопристроїв
v4l2-ctl --list-devices
```

BamDude читає `/dev/video0` за замовчуванням. Якщо камера на іншому ноді (наприклад, `/dev/video2`), введи шлях прямо в поле URL зовнішньої камери.

Для Docker — пробрось пристрій:

```yaml
services:
  bamdude:
    devices:
      - /dev/video0:/dev/video0
```

## :material-movie-roll: Layer-Based Timelapse (тільки зовнішні камери)

Коли увімкнено зовнішню камеру і принтер публікує per-layer-change MQTT-події, BamDude автоматично:

1. **Захоплює кадр** на кожен інкремент шару друку.
2. **Зберігає кадри** у тимчасовій директорії під час друку.
3. **Стічить відео** через **ffmpeg** на завершенні друку.
4. **Прикріплює** результуючий timelapse до архіву друку.

!!! note "Тільки зовнішні камери"
    Layer-based timelapse працює лише з зовнішніми камерами (MJPEG, RTSP, Snapshot або USB). Вбудовані камери принтерів використовують власну timelapse-фічу принтера — він стічить сам, і BamDude просто прикріплює готовий MP4/AVI.

!!! note "ffmpeg обов'язковий"
    Layer-timelapse потребує `ffmpeg` (включений у Docker-образ BamDude; на bare metal — `apt install ffmpeg`).

Це продукує помітно якісніший timelapse за fixed-interval capture, бо кожен кадр відповідає чистому стану друку (голова припаркована поза деталлю, між шарами).

## :material-key-variant: Stream-токен як шлюз

Camera-ендпоінти (live-стрім, snapshot, cover-мініатюра, plate-detection reference) не дружать з Bearer-токеном -- тег `<img src>` не може причепити заголовок `Authorization`. BamDude натомість пропускає їх через короткоживучий query-param токен:

1. Фронт стукає в `POST /api/v1/printers/camera/stream-token`, щоб отримати токен, прив'язаний до поточного користувача (TTL 60 хв).
2. Токен дописується як `?token=...` до кожного camera-URL через `withStreamToken()` в API-клієнті.
3. Уже відрендерені DOM-вузли (наприклад, `<img>`, змонтований до приходу токена) ретрофітяться через `rewriteMediaSrcWithToken()`.
4. Токен у React-Query кешується по `user.id`, тож логін/логаут інвалідує кеш.

Токени зберігаються в `auth_ephemeral_tokens`, тож переживають перезапуски бекенда і працюють під багатоворкерними деплоями. Операторам нічого робити не треба -- це невидима сантехніка -- але наслідок такий: copy-paste camera-URL з браузера працює лише на час життя вшитого токена.

### Довготривалі токени для Home Assistant / Frigate / kiosk

Токен на 60 хв з UI-сторони не годиться для kiosk-дашборду на стіні, camera-entity в Home Assistant чи Frigate-фронту, що ре-фетчить той самий URL місяцями. BamDude вміє mint'ити **довготривалі stream-токени** під ці кейси:

1. **Settings → Camera → Long-lived tokens → + New token**.
2. Обери принтер(и) (один токен може авторизувати кілька камер), expiry (місяці / роки / never), і опційний label (наприклад, `frigate-living-room`).
3. Сторінка покаже токен **один раз** — копіюй у конфіг HA / Frigate / kiosk. Більше не покаже.
4. Токен дає лише camera-ендпоінти (`/stream`, `/snapshot`, `/cover`) на обрані принтери — жодного іншого API.

| Властивість | Деталь |
|---|---|
| Storage | Та сама `auth_ephemeral_tokens` таблиця, з `token_type='camera_longlived'`, тож звичайний 60-хв sweeper їх не чіпає. |
| Revocation | Видалити рядок з таблиці long-lived tokens — діє з наступного запиту. Кеш-шару немає. |
| Audit | Кожен токен записує last-used-at + last-used-IP, тож видно чи kiosk його реально споживає. Stale-токени (no use 30+ днів) отримують жовтий warning-чіп. |
| Liimit | Soft cap 50 active-токенів на інсталяцію — підняти лише через DB-доступ (`auth_ephemeral_tokens` спеціально low-friction by design). |

Форма URL: `/api/v1/printers/{id}/stream?token={long_lived_token}` — той самий query-param контракт що й короткоживучий, тож HA-camera platform / Frigate `mjpeg_streams` / `<img src>` у kiosk-дашборді працюють без додаткової сантехніки.

### Деталі створення

1. **Settings → Long-lived Tokens** (під Security / API Keys).
2. Введи описове ім'я (наприклад, `Home Assistant`, `Kitchen Kiosk`, `Frigate`).
3. Обери TTL (1–365 днів, дефолт 90).
4. Натисни **Create**.
5. Plaintext-токен покажеться **рівно один раз** у copy-to-clipboard модалі.

!!! danger "Токен показується один раз"
    Збережи токен зараз. BamDude зберігає лише хеш (SHA-256) — як тільки модал закриється, plaintext не буде відновити. Якщо втратив — revoke ряд і створи новий.

### `lookup_prefix` і audit-поля

Кожен ряд long-lived токена несе:

- **lookup_prefix** — перші 4 символи хеша токена, для ідентифікації конкретного ряду коли забув, який пристрій який токен має. Безпечно показувати поряд з лейблом.
- **last_used_at** — таймстамп останнього успішного автентифікованого запиту з цим токеном. Stale-токени (нема активності 30+ днів) отримують жовтий warning-чіп для прибирання.
- **last_used_ip** — останній IP клієнта, корисно щоб помітити несподіване використання.

### Admin "All users" view

Адміни бачать додаткову секцію **All users (admin view)** під своїми токенами — лістує кожен активний long-lived токен по всіх юзерах інсталяції. Корисно для тріажу при підозрі на витік або для farm-wide hygiene (revoke стародавні токени).

### Maximum lifetime: 365 днів (m028)

BamDude відмовляє "never expires" by design — leaked permanent token буде irrevocable footgun. Maximum TTL — **365 днів**, enforce server-side через міграцію `m028`, що додає таблицю `long_lived_tokens`. Для довшого доступу — ротуй токени щорічно як частину звичайного credential-hygiene циклу.

### Дозволи

Створення і управління long-lived camera-токенами потребує `camera:view` — той самий permission, що для звичайних 60-хв browser-side stream-токенів. Дефолтні групи Viewers і Operators його мають.

Для делегування управління токенами не-адміну — переконайся, що він у групі з `camera:view` та `settings:read` (щоб дістати Settings).

### Revoke токена

1. **Settings → Long-lived Tokens**.
2. Знайди ряд за іменем або `lookup_prefix`.
3. Натисни **Revoke**, підтверди.

Будь-який пристрій з цим токеном втратить доступ з наступного запиту — без grace period, без cache-шару. Хеш ряду видаляється з БД, тож навіть DB-dump replay не спрацює.

## :material-image-frame: Cover-мініатюри

`GET /api/v1/printers/{id}/cover` повертає мініатюру того, що принтер *зараз* друкує. Видається виключно з локального каталогу архівів -- BamDude ніколи не ініціює FTP-завантаження з цього ендпоінта. Поки друк активний і 3MF архіву ще не догнаний (наприклад, друк, запущений з екрана принтера, де FTP-recovery-цикл ще не наздогнав), ендпоінт повертає 404, а UI показує загальний плейсхолдер. Щойно `archive_download_retry` витягне 3MF, ендпоінт почне віддавати реальний PNG без жодних дій з боку клієнта.

## :material-application: Оверлей-режим vs віконний режим

Переглядач камери має два режими, налаштовуються per-user у **Settings > Camera**:

- **Embedded** (за замовчуванням) -- переглядач накладається прямо поверх картки принтера. Кілька принтерів можуть мати камери відкритими одночасно, і кожен переглядач тримає власний розмір/позицію через локальний стан. Status bar у заголовку сторінки продовжує керувати рештою UI.
- **Window** -- переглядач запускається в окремому вікні браузера (або PWA-вікні). Корисно, щоб припаркувати одну камеру на другому моніторі.

Embedded -- правильний дефолт для живого моніторингу; віконний режим -- для сетапів, де камера живе на окремому екрані від дашборду принтерів.

### Embedded-фічі

В embedded-режимі камера з'являється як floating-вікно з такими можливостями:

- **Draggable** — клікни і тягни header для переміщення.
- **Resizable** — тягни нижній правий куток для зміни розміру.
- **Persistent position** — позиція і розмір запам'ятовуються per-printer між сесіями.
- **Navigation persistence** — відкриті камери залишаються відкритими, коли йдеш зі сторінки Printers і повертаєшся.
- **Minimize** — кнопка згортання до title-бару.
- **Close** — X для закриття.
- **Multi-viewer** — відкривай камери для кількох принтерів одночасно, кожна зі своєю позицією і розміром.

!!! tip "Embedded-режим для всієї ферми"
    Embedded тримає тебе на головному екрані під час моніторингу — не треба перемикати вікна браузера. Відкрий кілька переглядачів — моніторинг усієї ферми відразу.

## :material-tune: Snapshot mode та налаштування FPS

Для меншого трафіку перемкни per-camera режим у **Snapshot** замість **Live**:

- Захоплює один кадр за запитом, refresh — наступний.
- Ідеально для cellular-конекшенів, повільних мереж, дешевих kiosk-екранів без потреби в русі.

Дефолтний фреймрейт live-режиму — 15 FPS. Тюн через URL `?fps=N` або per-camera setting:

| FPS | Use case |
|-----|----------|
| **5** | Малий трафік / A1/P1 камери (hardware-ліміт) |
| **10–15** | Збалансовано (15 default) |
| **20–25** | Гладше відео |
| **30** | Maximum quality (X1 / H2 / P2 only — і USB) |

!!! note "FPS-ліміти за типом камери"
    - **Зовнішні камери** — кеп 15 FPS.
    - **A1 / P1 принтери** — кеп 5 FPS (hardware-обмеження).
    - **X1 / H2 / P2 принтери** — до 30 FPS.

!!! note "Вищий FPS = більше трафіку"
    Вищі fps жеруть більше bandwidth і ресурсів сервера — для multi-printer ферми на 30 FPS на кожному перегляді відразу плануй відповідно.

## :material-connection: Очищення стріма та auto-reconnect

BamDude правильно прибирає за собою camera-стріми, щоб не плодити osиротілі `ffmpeg`-процеси:

- **Window close** — стрім стопиться автоматично.
- **Tab hidden** — стрім паузиться для збереження ресурсів.
- **Page unload** — `ffmpeg`-процес вбивається.
- **Refresh** — старий стрім зупиняється, новий стартує.

### Stall detection

Браузер періодично перевіряє, чи стрім ще отримує кадри:

- **Інтервал перевірки** — кожні 5 секунд.
- **Детекція** — порівняння timestamp останнього кадру.
- **Threshold** — stalled, якщо нема нових кадрів **>5 секунд**.

### Автоматичне відновлення

При детекції stall:

1. Засікає, що кадри не приходять у threshold.
2. Закриває застряглий конекшен.
3. Реконнектиться автоматично.
4. Відновлює стрімінг.

!!! tip "Мережеві blip-и"
    Якщо мережа коротко падає — стрім відновиться автоматично після повернення з'єднання, без ручного втручання.

## :material-stethoscope: Діагностика камери

Коли камера не стрімить, BamDude може запустити вбудовану діагностику, що тестує з'єднання стадія за стадією і каже, *яка саме* ланка ланцюга зламана. Кнопка **Diagnose** стоїть поряд з **Retry** на error-стані переглядача, а маленька іконка стетоскопа живе в always-visible control bar (між :material-refresh: Refresh і :material-fullscreen: Fullscreen) для pre-flight перевірки ще до старту стрімінгу.

Вона стукає в `POST /api/v1/printers/{id}/camera/diagnose` і показує результат inline в модалі: один рядок на стадію з маркером pass / fail / skipped, тривалістю стадії в мілісекундах і перекладеним remediation-хінтом. Кнопка **Run again** перезапускає всю перевірку без закриття модала.

### Стадії

| Стадія | Що перевіряє |
|--------|--------------|
| **`tcp_reachable`** | Відкриває сирий TCP-сокет до camera-порту — `322` для RTSPS, `6000` для chamber-image — з таймаутом 3 секунди. Розрізняє **timeout** ("принтер недосяжний"), **refused**-конекшен ("camera-порт закритий — перевір LAN-Only Mode + Developer Mode") і помилку **host-unreachable**. |
| **`first_frame`** | Захоплює один JPEG end-to-end з таймаутом 15 секунд, через той самий pipeline, що живить `/camera/snapshot`. Доводить, що повний шлях реально віддає зображення, а не лише відкритий порт. |

!!! note "Шорткат на живому стрімі"
    Якщо переглядач уже дивиться камеру **і** буферизований останній кадр свіжіший за 10 секунд, діагностика пропускає реальний тест і репортить стрім як живий / healthy. Відкриття свіжого сокета вибило б живого глядача на firmware, що дозволяє лише один camera-конекшен — тож коли вже є доказ, що камера працює, BamDude її не чіпає.

Результат також несе метадані для support-тріажу: протокол (`rtsp` / `chamber_image`), порт, профіль (`default` чи model-specific назва) і summary-код.

## :material-scan-helper: Build Plate Empty Detection

Автоматично детектить об'єкти, залишені на столі перед стартом друку. При детекції — друк паузиться, фаєриться нотифікація.

### Як це працює

1. **Calibrate** — захоп reference-зображення твого пустого столу.
2. **Enable** — увімкни plate-detection для принтера.
3. **Auto-check** — при старті будь-якого друку BamDude порівнює поточне зображення камери з референсами.
4. **Auto-pause** — якщо детектовано об'єкти, друк негайно паузиться.

### Калібровка

Зберігай до **5 reference-зображень** на принтер для різних типів столу (textured, smooth, high-temp, тощо):

1. Натисни **scan-іконку** на картці принтера для відкриття модала.
2. Переконайся, що стіл **повністю порожній** і **chamber light ON**.
3. Натисни **Calibrate Empty Plate**.
4. Опційно додай label (`Textured PEI`, `Cool Plate`).
5. Повтори для кожного типу столу, який реально використовуєш.

!!! tip "Кілька референсів"
    Система автоматично обирає найкращий-матчинг референс при перевірці. Калібруй кожен тип, який реально юзаєш, для точної детекції.

### Увімкнення детекції

На картці принтера є **split button**:

| Частина | Дія |
|---------|-----|
| **Main (scan-іконка)** | Перемикає детекцію on/off. |
| **Chevron (▼)** | Відкриває модал калібровки / управління. |

Коли увімкнено — кнопка має зелену рамку.

### ROI (Region of Interest) editor

Налаштуй, яку частину camera-вʼю аналізувати:

1. Відкрий plate-detection модал.
2. Скрол до **Detection Area (ROI)**.
3. Натисни **Edit**.
4. Слайдерами X / Y / Width / Height задай зелений ROI-box.
5. Save.

Зелений box у preview показує detection area. Зосередь на столі, щоб уникнути false positives від рами принтера, AMS, фону.

### Механіка детекції

1. Захоплює поточний камера-кадр (або юзає buffered-кадр, якщо стрім активний).
2. Накладає важкий Gaussian blur на обидва — поточний і reference.
3. Нормалізує обидва для consistent-порівняння.
4. Вирізає ROI-регіон.
5. Рахує pixel-difference відсоток.
6. Якщо різниця > 1% — стіл "не порожній".

### Нотифікації при детекції

- Друк негайно паузиться.
- Toast-нотифікація в BamDude.
- Push-нотифікація (Telegram / Discord / Email / Pushover / ntfy / HA — що увімкнено).
- WebSocket-подія для інтеграцій.

### Вимоги

| Вимога | Деталі |
|--------|--------|
| **OpenCV** | `opencv-python-headless` (вже в Docker-образі). |
| **Chamber light** | Має бути ON для надійної детекції. |
| **Calibration** | Хоча б один reference. |

### Траблшутинг

**False positives (детектить об'єкти при порожньому столі)**

- Калібруй з chamber light ON (як під час друку).
- Зменши ROI, щоб виключити рами/AMS.
- Додай кілька калібровок для різних умов освітлення.

**False negatives (не детектить об'єкти)**

- Переконайся, що chamber light ON.
- Перекалібруй — поверхня столу могла змінитися (резин-резидіу, peel-стікер, подряпини).
- Перевір, що об'єкти всередині ROI — все поза зеленим box ігнорується by design.

## :material-help-circle: Траблшутинг

**Стрім не стартує**

1. Чи увімкнено принтер? Камера потребує живлення.
2. Чи увімкнена камера в налаштуваннях принтера?
3. Чи інстальовано `ffmpeg`? (Включено в Docker-образ.)
4. Чи увімкнено Developer Mode? (Потрібно для доступу до камери на Bambu принтерах.)
5. Для зовнішніх камер — перевір URL з `curl` зсередини BamDude-хоста: `curl -I http://192.168.1.50/mjpeg`.
6. У Docker? Якщо default bridge не дотягується до принтера, перемкни на `network_mode: host`.

**Стрім фризить**

- Network congestion або WiFi-дропи — спробуй знизити FPS до 5 або 10.
- Перевір силу WiFi-сигналу принтера (поганий сигнал — нестабільна доставка кадрів).
- Спробуй snapshot mode — він не залежить від continuous-стріма.

**Висока latency (1–3 секунди лагу)**

Це нормально для MJPEG-over-HTTP і випливає з RTSP-буферизації, ffmpeg-pipeline і HTTP-stream-chunk boundaries. Не усунеш повністю. Зменшити можна:

- Знизити FPS для меншої per-frame буферизації.
- Snapshot-режим замість стріма для моніторингу.
- Зовнішня камера з hardware MJPEG-виходом (пропускає RTSP→MJPEG transcoding).

**Чорний екран**

- Камера може ініціалізуватися — почекай 5–10 секунд і refresh.
- Перевір, що камера працює в Bambu Studio спочатку; якщо там не працює — це printer-side, не BamDude.
- Перевір user-permission grants — потрібен `camera:view`.

**Docker: камера не працює**

Якщо в Docker не працює, спробуй host-network:

```yaml
services:
  bamdude:
    network_mode: host
    # прибери секцію ports: при host-mode
```

Default bridge з NAT працює в більшості сетапів. Host-mode потрібен лише коли мережева конфігурація заважає NAT-трафіку дотягтися до RTSP-порту принтера.

## :material-api: API-ендпоінти

Для розробників і інтеграцій:

| Ендпоінт | Метод | Опис |
|----------|-------|------|
| `/api/v1/printers/{id}/camera/stream` | GET | MJPEG live-стрім. |
| `/api/v1/printers/{id}/camera/snapshot` | GET | Single JPEG-кадр. |
| `/api/v1/printers/{id}/camera/stop` | POST | Зупинити активні стріми принтера. |
| `/api/v1/printers/{id}/camera/test` | GET | Тест conneкту до камери (success/failure без стрімінгу). |
| `/api/v1/printers/camera/stream-token` | POST | Mint 60-хв query-param stream-токен (див. Stream Token Gate вище). |

### Рецепт OBS Browser Source

Embed live-стрім в OBS як Browser Source:

1. В OBS клацни **+** під Sources.
2. Обери **Browser**.
3. URL: `http://your-bamdude:8000/api/v1/printers/{id}/stream?token=<long-lived-token>` (юзай **long-lived camera token** — короткоживучі експайряться mid-stream).
4. Width / height під сцену (наприклад, 1920×1080).
5. **OK**.

Для багатшого overlay зі статус-текстом — див. наступну секцію.

## :material-video-box: OBS Streaming Overlay

Спеціальна overlay-сторінка комбінує camera-фід з real-time print-статусом — один Browser Source замість окремих camera + text. Форма URL:

```
http://your-bamdude:8000/overlay/{printer_id}
```

!!! note "Логін не потрібен"
    Overlay сконструйований для embed-у і не потребує авторизації. Не виставляй цю URL публічно бездумно.

### Що включено

| Елемент | Опис |
|---------|------|
| **Camera-фід** | Full-screen live camera. |
| **BamDude-логотип** | Брендинг у правому верхньому. |
| **Filename** | Ім'я поточного print-файлу. |
| **Status** | Printing, Paused, Idle тощо. |
| **Progress bar** | Візуальний прогрес з відсотком. |
| **Layer count** | Поточний шар / загальна кількість. |
| **Time remaining** | Оцінка залишку часу. |
| **ETA** | Оцінка часу завершення. |

### Кастомізація через query-параметри

| Param | Значення | Ефект |
|-------|----------|-------|
| `size` | `small` / `medium` / `large` | Масштаб тексту і логотипа. `medium` default. |
| `fps` | `1`–`30` | Live-FPS. Сlamp-ається server-side per-camera-type. |
| `camera` | `true` (default), `false`/`0` | `false` ховає camera-фід, показує статус на чорному фоні. |
| `show` | comma-separated: `progress`, `layers`, `eta`, `filename`, `status`, `printer` | Які елементи статусу показувати. |

Приклади:

```
# Компактний кутовий overlay з повним статусом
/overlay/1?size=small&show=progress,layers,eta,filename,status

# Status-only, без камери (low-bandwidth сценарій)
/overlay/1?camera=false&show=progress,eta,status

# Maximum quality, full screen
/overlay/1?size=large&fps=30&show=progress,layers,eta,filename,status,printer
```

### Idle-стан

Коли друк не йде, overlay все одно працює — показує camera-фід плюс "idle" / "offline" і логотип BamDude. Корисно для стрімінгу cleanup ферми, swap-у плити, off-hours.

### Траблшутинг overlay

**Overlay не вантажиться в OBS**

- Перевір, що URL працює в звичайному браузері спочатку.
- Перевір, що OBS дотягується до BamDude-сервера (та сама мережа, без VPN-обмежень).
- Right-click source в OBS → **Refresh cache of current page**.

**Камера не показується в overlay**

- Підтверди, що принтер підключений.
- Підтверди, що camera-стрімінг працює в BamDude напряму спочатку — overlay юзає той самий стрім.
- Status-апдейти йдуть по WebSocket; якщо WS-handshake падає, статус фолбекається на polling кожні 2 секунди.
