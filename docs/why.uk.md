# Чому BamDude

## Два підходи до друку

**Класичний:** слайсер → принтер. Натиснув Print у BambuStudio чи Orca — файл полетів у принтер по локалці. У такій схемі BamDude (як і будь-який інший зовнішній сервіс) — пасивний слухач: ловить події з принтера, веде історію «по можливості», намагається відстежити котушки.

Цей флоу працює, поки у вас один-два принтери і ціна неточної історії / неточного обліку матеріалу прийнятна. Як тільки принтерів стає більше — або як тільки точні логи й реальний контроль котушок починають впливати на бізнес-рішення — модель «слайсер диктує» перестає тримати воду.

**Фарм-орієнтований:** слайсер → BamDude → принтери. Слайсите як зазвичай, але кнопка Print тепер летить не у принтер, а в BamDude — через [віртуальний принтер](features/virtual-printer.uk.md) у режимі **File Manager**. У BamDude ви обираєте, на яких принтерах і в скільки копій друкувати. BamDude:

- сам роздає файли по принтерах,
- виконує макроси (включно зі [свап-модом](features/swap-mode.uk.md)),
- стежить за прогресом і ловить завершення,
- пише повну [історію друку](features/archiving.uk.md),
- веде точний облік котушок.

Це канонічна форма фарм-менеджера: **один центральний source of truth, що оркеструє решту.** Bambu Farm Manager і Bambu Handy роблять те саме — BamDude робить це self-hosted, з власною історією, свап-модом, чергою, обліком енергії, гнучкими сповіщеннями та повноцінною системою доступу.

## Приклад: Benchy на 10 принтерах одночасно

10 A1 mini, [свап-режим](features/swap-mode.uk.md), по одній копії на кожному.

**Без BamDude:**

1. Нарізати Benchy у слайсері.
2. Зберегти `.3mf` на диск.
3. Відкрити SwapList.app → завантажити файл → налаштувати своп → зберегти своп-файл.
4. Відкрити Bambu Farm Manager → завантажити туди своп-файл.
5. Натиснути Print → обрати 10 принтерів → старт.

**Через BamDude:**

1. Нарізати Benchy у слайсері.
2. Натиснути Print → обрати віртуальний принтер у режимі File Manager.
3. Перейти в BamDude → «Запланувати» або «Друкувати».
4. Обрати всі mini, поставити 10 столів, натиснути «Друк».

І все. Файли розлітаються по принтерах автоматично, своп-макроси відпрацьовують, історія пишеться, котушки списуються.

## Куди це вписується

BamDude — заміна Bambu Farm Manager і Bambu Handy для тих, кому потрібно:

- self-hosted, без хмарних залежностей (Bambu Cloud — за бажанням, не з примусу);
- історія друку, яка не «по можливості», а гарантована;
- облік котушок, що базується на реальних подіях друку;
- керування з [Telegram](features/telegram-bot.uk.md), мобільного, веб-інтерфейсу — однаково повноцінно;
- гнучкі сповіщення з per-chat / per-channel налаштуваннями;
- повноцінні API + інтеграції ([Spoolman](features/spoolman.uk.md), [Home Assistant](features/mqtt.uk.md), [OrcaSlicer / BambuStudio як sidecar](features/slicer-api.uk.md), [Prometheus](features/prometheus.uk.md), Webhook).

## А якщо запустити друк зі слайсера напряму чи з екрану принтера?

BamDude вміє підхопити такий друк постфактум — додасть у історію, спробує дотягнути 3MF з принтера. Але це **виняток, а не правило.**

Закритість прошивок Bambu обмежує те, що зовнішній сервер може дізнатися заднім числом. Якщо в момент події BamDude недоступний (зник канал, рестарт сервера — будь-що), і оператор у цей час зробив 10 репринтів руками — ці 10 репринтів так і залишаться невидимими для системи. Жодний пасивний слухач не вкаже їх з абсолютною точністю — їх просто немає в потоці подій, який зміг побачити сервер.

## Архітектурний висновок

Допоки прошивки 3D-принтерів лишаються закритими, єдина робоча форма для серйозної ферми одна:

> **Слайсер ↔ Фарм-менеджер ↔ Принтери.**

Не «слайсер шле напряму, а менеджер десь збоку щось слухає». Не «три різних UI керують одними і тими ж принтерами наосліп, не знаючи один про одного». **Один центр, що бачить усе — тому що все проходить через нього.**

[Віртуальні принтери](features/virtual-printer.uk.md) існують саме для того, щоб полегшити цей перехід — щоб ваш звичний цикл «нарізав → Print» не довелося ламати. Ви не міняєте свій робочий процес. Ви просто перенаправляєте ту саму кнопку Print у правильне місце.
